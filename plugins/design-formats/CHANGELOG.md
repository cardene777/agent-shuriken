# Changelog

Releases of the design-formats plugin, newest first.
Versions follow semantic versioning: a major release changes how the plugin is called or what it stores, a minor release adds behavior, and a patch release fixes behavior.

## [Unreleased]

- `page-design.py theme --keys <key>,...` writes only the named groups and keys of the theme file, such as `--keys light,dark,font.sans,font.mono` for a page that keeps its own sizes, and refuses a name that is neither. `theme` also writes the dark colors into dark blocks that carry more guards after their selector, such as `:not([data-paper])`
- Pages take the user's own look from a theme file, `.design-theme.json` at the root of the repository or else `~/.design-theme.json`. `page-design.py theme <page>` writes its colors, fonts, text size, line height, page width, and corners into a page made from a template, keeps the page's values for the keys it leaves out, and leaves the page as it is without a theme file. A theme file with an unknown key or a bad value is refused with each key named. `page-design.py theme --defaults <page>` prints a page's values as JSON, and `formats/theme.md` lists every key, its type, and each template's default. The four templates take the text size, line height, page width, and the three corner sizes from tokens with the same values as before. `theme` is version 1.0.0 in `musubi.json`
- `verify` reads the strings of a page's script of any length, with their escapes such as `\n`, `\"`, and `\u3001` read, when it looks for facts joined in one line. Before, it read only strings of up to 300 characters without a backslash, so a long note that a report keeps in the JSON of its script, such as techdebt's, was never checked
- `page-design` holds four pattern files, `formats/patterns/details.md`, `lists-and-tables.md`, `input-and-confirmation.md`, and `states-and-notices.md`. Each opens with a table that picks the pattern for a situation, and each rule names its sources in `formats/patterns/sources.md`, from design systems, research and articles, public guidance, and accessibility, with the page, the date it was read, and a quote. Where the sources disagree, each file says which side it took and why
- The templates put the facts about the page in a table whose label cells have their own color, break Japanese text after each full stop, and keep the list at a fixed width with the details taking the rest of the row. On a narrow screen a pressed row shows its details in place of the list, with a button back to it. The report opens long details at full width instead of in a dialog, the approval sheet keeps its button pressable and says what is missing, and the choice page keeps its enlarge button outside the option it enlarges
- `verify` names facts that are not a table of row headers (`facts-not-table`), a Japanese sentence that does not end its line (`sentence-per-line`), and a list column that grows with the page beside its details (`list-detail-width`). `look`, the four page types, and `verify` are version 2.0.0 in `musubi.json`
- `formats/look.md` draws a change over time as a dragon line chart (`[shape: line]`), and the report template opens its figures with the daily sales of the week as a line chart across the full width. page-design follows the dragon skill's updated notation and chart guide
- The report and explainer templates give their figure cards and the enlarged view the card color as `--dragon-figure-background`, so a figure's background matches its card on light and dark pages, and the report centers each figure in its card. `formats/look.md` says to pass the card color, and page-design follows the dragon skill's updated embed and chart guides
- Pages draw their figures with dragon. `formats/look.md` says which figure fits which kind of information, the report template shows the sales by time of day as a bar chart and each kind's share as a donut, and the explainer shows the steps as a band of steps. Each figure is a still dragon block per language that `dragon embed` draws as an SVG. `verify` names a page that still holds a block, and `verify --source` checks a template before `dragon embed`. page-design follows the dragon skill's notation, embed guide, and the guides of the chart, cycle, flow, architecture, and sequence kinds through musubi as optional follows
- The report template puts the facts about the page in a table under the title and the result numbers on one band, shows each value once, gives each row its amount instead of an unlabeled bar, and shows no paging when the list fits on one page. `formats/look.md` holds these as rules

- The samples in the four page templates, `formats/look.md`, and the README all use one small bakery: the weekly sales report, the items to take off the winter menu, how to brew pour-over coffee, and the layout of the menu board
- `verify` also names a title kept per language, such as `title: { en: "Bakery: weekly sales", ja: "..." }` in a page's data, when one of its texts has a colon or a Japanese comma or period
- The report template shows facts and numbers that differ by language, and the approval sheet writes amounts with the yen sign in English and with the Japanese word for yen after the number in Japanese
- The README and `docs/how-it-works.md` list the ten skills that follow page-design, with their plugin and the contents each follows, and `tests/test-followers.sh` checks their declarations, their `SKILL.md` lines, their templates, and `musubi check` with and without design-formats

## [0.1.0] - 2026-11-20

First public release.

- The `page-design` skill holds how documents and reports explain (`formats/structure.md`) and how they look (`formats/look.md`), and four self-contained HTML page templates: a report with details beside the list, an approval sheet, an explainer with a contents list and a glossary, and a choice page that keeps today's version as an option. Skills follow it through musubi, which pins each content's version and fingerprint
- `page-design.py verify` names each line of a page or a Markdown document with a colon or a Japanese comma or period in a heading, facts crammed into one line, or a label joined with a colon, and each page with text under 12px, no language or theme switch, no dictionary, no dark colors, motion without the reduced-motion setting, or a file read from another site, with how to fix it and without printing the page's text
