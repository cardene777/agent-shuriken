# PC Tidyの仕組み

[English](how-it-works.md) · 日本語

このページには、プラグインが何を調べ、項目の種類ごとにどう消し、何に決して触れないかを並べています。

## 一覧に載る物

30日を超えて触れていない項目が、一覧に載ります。

| 種類 | 最後に使った日の調べ方 | 消し方 |
|---|---|---|
| 作業フォルダと手元のリポジトリ | 最後のコミットと最後のチェックアウト | 直接消します。消すのは、全部がリモートにある時だけです |
| アプリ | 最後に起動した時 | 直接消します |
| 消したアプリの残り | 中で最も新しいファイルか、中の実行ファイルが最後に動いた時 | ゴミ箱へ移します |
| 道具と実行環境 | そのバージョンの`bin`にある物が最後に動いた時 | 直接消します。全バージョンが古い時は、バージョン管理ツールごと消すことも提案します |
| AIのモデル | 最後に読み込まれた時 | 直接消します |
| Dockerのimage | 作られた日。コンテナが使っているimageは載せません | `docker image rm` |
| 溜まる記録の設定 | なし | 残す期間を変えます |
| それ以外の物 | 中で最も新しいファイルか、中の実行ファイルが最後に動いた時 | ゴミ箱へ移します |

`.DS_Store`のように、Finderがフォルダを開いただけで書き込むファイルは、使ったことに数えません。
ツールが無くて測れない種類は、0件ではなく「測れなかった」と報告します。
前に消したのにまた作られた物は、それを作り直している元と一緒に名前を挙げます。

## 一覧に載せない物

- 写真、鍵、iCloud Drive、メール、そのほか`skills/pc-tidy/protect-default.txt`にある場所
- 設定フォルダの`protect.txt`に、1行に1つずつ足した場所
- 設定フォルダそのもの
- `~/Documents`と`~/Desktop`にある、リポジトリではない物
- 未コミットの変更か、プッシュしていないコミットがあるリポジトリ
- 動いているプロセスが作業中のフォルダ
- エディタのプラグインのように、ホームフォルダのドットで始まるフォルダの中にあるリポジトリ。ツールが動く時に参照するためです
- Dockerのボリュームと仮想マシンの保存領域
- `~/.npm`や`~/.cargo/registry`のように、自動で作り直されるパッケージマネージャのキャッシュ
- 0バイトの項目

## 安全に消すための仕組み

項目はすべてあなたがページで選び、エージェントが代わりに選ぶことはありません。
消す直前に、プラグインは保護の設定、未コミットの変更、プッシュしていないコミット、動いているプロセスをもう一度確かめます。
一覧を作った後に変わった物は飛ばし、名前と理由を示します。
プラグインはネットワークに接続しないので、リポジトリのコミットがリモートにあるかは、あなたのMacが最後にフェッチした内容から判断します。
シンボリックリンクで繋いだリポジトリや`chezmoi`のように別のツールが管理する設定と、`~/.zshrc`のようなシェルのファイルは書き換えません。
代わりに、何を変えればよいかをエージェントが伝えます。

## 報告

消し終えると、エージェントは次のことを伝えます。

- 消した物と、飛ばした物とその理由
- 空き容量がどれだけ変わったか
- ゴミ箱へ移した量。ゴミ箱を空にすると、その分が空き容量になります
- Time Machineのローカルスナップショットが容量を使ったままになっていないか

## 設定

設定は`~/.local/share/pc-tidy/`に置き、`PC_TIDY_HOME`を設定した時はそちらに置きます。

| ファイル | 中身 |
|---|---|
| `config` | `days=<days>`で、何日使っていない項目を載せるかを決めます。既定は30日です。`min_size_mb=<MB>`で、どの種類にも当たらない物を載せる最小の大きさを決めます。既定は100です |
| `protect.txt` | 守る場所を1行に1つずつ書きます。`~`はホームフォルダを表します |
| `removed.jsonl` | 消した項目の記録 |
| `notes.json` | 説明とあなたのコメント。場所ごとに保存し、次に一覧を作る時にも使います |

## 実行する物

このプラグインはmacOSでだけ動き、ネットワークを必要としません。
`python3`を実行し、`git`、`mdls`、`docker`があれば、そこから使用状況を読みます。
ほかの作業を止めないよう、調査はCPUの優先度を下げて実行します。
