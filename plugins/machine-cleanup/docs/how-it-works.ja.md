# Machine Cleanupの仕組み

[English](how-it-works.md) · 日本語

このページは、調べる時に何をどう測るか、何を使用中と見るか、ページがどうエージェントとやりとりするか、選んだ項目がそれぞれどうなるかを説明します。
命令はどれも技のフォルダの中の`scripts/machine_cleanup.py`です。

## 調べ方

`scan`はまず自分のCPUの優先度を最も低い値 (niceの19) に下げ、macOSでは`taskpolicy -b`、Linuxでは`ionice -c3`の下で`du`を動かしてフォルダの大きさを測ります。動いている間もコンピューターを普通に使えます。
時間の上限 (`--time-limit`の指定が無ければ90秒) に達すると止まり、届かなかった場所を全て理由`time limit`と一緒に並べます。

速くて役に立つ結果が先に出るよう、次の順に見ます。

| 段 | 読む物 |
|---|---|
| プロセス | `--sample`秒 (既定は2秒) あけて`ps`を2回。CPUの使い方は、2回の間にプロセスごとのCPU時間がどれだけ増えたかで測ります。`ps`が出す`%cpu`は過去を少しずつ忘れる平均だからです |
| ログイン項目 | macOSは`~/Library/LaunchAgents`。Linuxは`~/.config/autostart`と`systemctl --user list-unit-files` |
| コンテナ | `docker ps`と`docker stats --no-stream` |
| AIモデル | Ollamaのmanifestとblob (`OLLAMA_MODELS`か`~/.ollama/models`)、Hugging Faceのキャッシュの`models--`のフォルダ (`HF_HUB_CACHE`、`HF_HOME`か`~/.cache/huggingface/hub`)、LM Studioのモデルのフォルダ (`~/.lmstudio/models`と`~/.cache/lm-studio/models`) |
| キャッシュ | パッケージ管理ごとの既定のフォルダ (置き場を変える変数`npm_config_cache`、`PNPM_STORE_DIR`、`YARN_CACHE_FOLDER`、`BUN_INSTALL_CACHE_DIR`、`PIP_CACHE_DIR`、`UV_CACHE_DIR`、`HOMEBREW_CACHE`、`CARGO_HOME`、`GOPATH`、`GOMODCACHE`、`GOCACHE`、`GRADLE_USER_HOME`、`XDG_CACHE_HOME`、`XDG_DATA_HOME`に従います)、macOSのXcodeのフォルダ、`~/Library/Caches`か`~/.cache`の50MB以上のアプリのキャッシュ、`docker system df` |
| ゴミ箱とログ | ゴミ箱、macOSは`~/Library/Logs`の30日より古いファイル、Linuxは`~/.local/state`のログのファイル、`~/Downloads`の30日より古いインストーラー |
| アプリ | macOSは`/Applications`と`~/Applications` (か`--apps-dir`) の中で自分が変えられる`.app`のうち、`mdls`が最後に使った日を90日より前と返す物。Linuxは`flatpak list --user --app` |
| 消したアプリの残り | macOSは`~/Library`の`Application Support`、`Caches`、`Preferences`、`Containers`、`Saved Application State`、`HTTPStorages`、`WebKit`、`Logs`の中で、名前がbundle id (`com.example.app`) の物 |
| ファイル | ホーム (か各`--root`) を8段の深さまでたどります。隠しフォルダ、macOSの`~/Library`と`~/Applications`、「入らない場所」の場所は飛ばします |
| 作業フォルダ | たどる途中で見つけたgitのプロジェクトを、`git log`、`git status`、`git remote`、`git rev-list`で読みます |
| 道具の版 | nvm、fnm、pyenv、rbenv、asdf、mise、rustupの版のフォルダ (置き場を変える変数`NVM_DIR`、`FNM_DIR`、`PYENV_ROOT`、`RBENV_ROOT`、`ASDF_DATA_DIR`、`MISE_DATA_DIR`、`RUSTUP_HOME`に従います)、それぞれの既定の版、たどる途中で見つけた版の指定のファイル |

たどる途中で`.git`を持つフォルダをプロジェクトと見ます。
プロジェクトの一番上から4段以内の`node_modules`、`.next`、`.nuxt`、`.svelte-kit`、`.turbo`、`.parcel-cache`、`.vite`、`.angular`、`.expo`、`.docusaurus`、`.output`、`.vercel`、`.wrangler`、`dist`、`build`、`out`、`target`、`.venv`、`venv`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache`、`.tox`、`.gradle`、`DerivedData`、`coverage`、`.cache`、`Pods`という名前のフォルダは、`git check-ignore`がgitの無視を返し、`git ls-files`が中に追跡するファイルを1つも見つけない時だけビルドの出力にします。
1MB未満のビルドの出力は並べません。

10MB以上のファイルは重複の候補です。
大きさ、先頭の64KiBのSHA-256、中身全体のSHA-256が同じ2つのファイルを重複とし、1つのファイルへのハードリンクは1つと数えます。
調べる時にファイルの中身を読むのはここだけで、残すのはハッシュだけです。
重複を持たない500MB以上のファイルは大きいファイルです。

プロジェクトは、最後のcommitと、`.git/HEAD`とその記録が最後に変わった日 (checkoutかcommit) がどちらも30日より前で、`git status`に未commitの変更も未追跡のファイルも無く、remoteを持ち、`git rev-list HEAD --branches --not --remotes`がremoteを追う参照に無いcommitを1つも返さない時に、使っていない作業フォルダです。
remoteを追う参照は最後に取り込んだ時の記録なので、走査はremoteへ繋ぎません。
gitは`GIT_OPTIONAL_LOCKS=0`で動かすので、読むだけでプロジェクトのindexを書き換えません。
別の作業場所を持つプロジェクトと、別の作業場所そのものは並べません。

消したアプリの残りは、ライブラリの中の物のうち、bundle idの会社の部分 (先頭の2つ、`com.example`など) を持つアプリがアプリのフォルダにも動いているアプリにも無く、残りの部分が動いているプロセスに合わず、中の最新のファイルが30日より前の物です。
8つのフォルダにまたがる同じbundle idの物を1行にまとめます。
ここでのbundle idは、2文字から4文字のトップレベルドメインで始まり、UUIDや長い乱数の文字列のような、アプリやテストが実行ごとに作る部分を持たない名前です。
名前がbundle idでない物、`com.apple.`で始まる物、使っていないアプリやアプリのキャッシュとして既に並べたファイルは外します。bundle idでない名前の物は、ほとんどがmacOS自身と命令の道具の物だからです。
8つのフォルダを読み終える前に時間の上限に達した時は、残りを1つも並べません。読んでいないフォルダにある同じbundle idのファイルが新しいかもしれないからです。
Linuxには残りの行がありません。ファイルを作ったパッケージと結び付けられないからです。

道具の版は、道具の既定の版 (nvmの`alias/default`、fnmの`aliases/default`、pyenvとrbenvの`version`のファイル、asdfとmiseの`~/.tool-versions`、miseの全体の`config.toml`、rustupの`settings.toml`) でも、プロジェクトの`.nvmrc`、`.node-version`、`.python-version`、`.ruby-version`、`.tool-versions`、`mise.toml`、`.mise.toml`、`rust-toolchain`、`rust-toolchain.toml`が指定する版でもない時に、使っていない版です。
版の前の部分 (`20.11.1`に対する`20`) や、隣の別名のリンク (miseの`lts`) で指定された版も、指定に数えます。
動いているプログラムが使う版、既定かプロジェクトがどの版にも合わない語 (`latest`など) を指定した道具の版、時間の上限で全てのプロジェクトを読む前にたどるのが止まった時の版は、並べますが選べません。
作業フォルダと道具の版は、キャッシュの後に行うホームをたどる段から得ます。ホームが大きい時は、`--time-limit`でたどり終える時間を与えます。

モデルは全て、大きさと落とした日と一緒に並べます。
Ollamaのモデルの大きさは、ほかのモデルが使わないblobだけを数えます。空くのはその分だけだからです。
`~/.cache`の下のHugging FaceとLM Studioのフォルダは、アプリのキャッシュとして並べません。モデルは落とし直すのに時間がかかるからです。

結果は状態のフォルダの`scan.json`に置きます。
各項目は、識別子 (ディスクの項目は`d-`と16進の8文字、プロセスとログイン項目とコンテナは`p-`)、分類、種類、大きさかメモリの使用量、ひとりでに戻ってくるか、空け方、使用中ならその理由、変える前の確かめに使う指紋を持ちます。
このファイルは、`df`で測ったディスクの空きと全体、使用中と全体のメモリ、負荷も持ち、全体のタブがそれを図にします。
形式は版5として記し、`serve`と`apply`はそれより古い版の走査を断って走査し直すよう求めます。

キャッシュ、ログのフォルダ、ビルドの出力、開発用のサーバーのように走査が名前を作る行は、`label`も持ちます。名前の鍵と、名前に要る値です。例は`{"key": "build", "vars": {"folder": "node_modules", "project": "shop"}}`です。
ページはこの鍵を自分の辞書で引くので、名前はページの言語に従い、npmやViteのような製品の名前はそのまま残ります。
項目の`name`は英語の名前のまま残り、エージェントの報告に使います。写した選択はこれに頼りません。

## 1つのパスに1つの行

同じファイルに2つの段が行き当たることがあります。ダウンロードの30日より古いインストーラーは、500MB以上のファイルでもありえます。
走査は上の表の順で先に行き当たった段の行を残すので、ファイルは1回だけ出て、1回だけ数えます。
落とした行が重複の写しの1つだった時は、残した行がその組を引き継ぎ、組の写しを1つ残す決まりを保ちます。

行がほかの行の中にあることもあります。使っていない作業フォルダの中のビルドの出力と大きいファイル、使っていないアプリの付属のファイルの中のキャッシュとログです。
中の行は、それだけを空けられるよう自分の行を持ち、自分を含む行の識別子を近い順に`within`に並べます。

| 場所 | 中の行の数え方 |
|---|---|
| 図 | 1回だけです。行の分からは、中にある出ている行を除き、選んだ行の中の選んだ行は何も足しません |
| 下の帯 | 空くディスクに1回だけ数えます |
| 送る前のまとめ | 中の行は外の行と一緒に空くと示します |
| `apply` | 外の行から空けます。外の行が空いた中の行は、一緒に空いたとして`skipped`と報告します |

## 行の推奨度

走査は全ての項目に3つの推奨度のどれかと理由を付け、`recommended`、`check`、`careful`として持ちます。
ページは一覧のタブを推奨度ごとの表に分けて使用中の行を最後に置き、各行の推奨度を、絵と言葉を持つ印で示します。
推奨度は行の並びと説明を決めるだけで、`apply`はどの推奨度の項目も同じように確かめ直します。

| 推奨度 | 項目 | 出す理由 |
|---|---|---|
| おすすめ | 道具が作り直すキャッシュ、30日より長くcommitの無いプロジェクトのビルドの出力、ゴミ箱、30日より古いログとインストーラー、始めた会話が終わった後も動いている開発用のサーバー | 次に要る時に作り直されること、プロジェクトに何日commitが無いか、ファイルがどれだけ古いか |
| 戻せる | 30日以内にcommitのあるプロジェクトのビルドの出力、大きいファイル、重複、使っていない作業フォルダ、使っていないアプリ、消したアプリの残り、使っていない道具のバージョン、AIモデル、ログイン項目、`next-server`のプロセス (`next start`も同じ名前で動くため) | 最後のcommitかcheckoutかダウンロードした日、アプリを開いた日、残りが最後に変わった日から何日か、後から戻せることか入れ直せること |
| 影響あり | 重いプロセスと動いているコンテナ | 終わらせるとその作業が止まること |
| 使用中 | 推奨度に関わらず、使用中の項目 | 使用中の理由 |

おすすめと戻せるの見出しには、その推奨度の行を全部選ぶ「全部選ぶ」のボタンがあります。重複のコピーは1つが必ず残るように1件ずつ選ぶため、このボタンでは選びません。
1つの組のコピーは、走査がどこで見つけてもまとまって並び、最初のコピーがコピーの数と1つの大きさを示します。
影響ありと使用中にはこのボタンが無く、ページは何も選ばない状態で開きます。

## 全体のタブ

ページは全体、ディスク、プログラム、測らなかった場所の4つのタブを持ち、2つ目からのタブは行の数を名前に添えます。
タブは1行に並びます。矢印のキーとHomeとEndでタブを移れて、窓が狭い時はタブの列が横に動きます。
ページは全体のタブで開き、走査の結果を7つの図で見せます。
輪の色か凡例の行のうち種類を持つ物を押すと、その種類だけを出したディスクかプログラムのタブが開き、棒を押すとその行の詳しい情報が開きます。
走査が測れなかった値は、0ではなく「測れませんでした」と出します。
輪の穴には名前と値だけを置き、ディスク全体のようなほかの値は輪の下の行に置きます。

| 図 | 見せる物 |
|---|---|
| 空けられる分の内訳 | 行の種類ごとに空けられるディスクです。使用中の行を除き、重複は1つを残した分だけ数えます。下の行は、そのうち次に使う時に作り直される分です |
| 推奨度ごとの大きさ | 同じディスクをおすすめ、戻せる、影響ありに分け、使用中の行を別に足します。下の行は、おすすめを全部空けた後の空きです |
| ディスク | ディスク全体を、選んだ分、空けられるが選んでいない分、そのほかの使用中、空きに分けます。下の行は、選んだ分を空けた後の空きです |
| メモリ | メモリを、終わらせられるプロセス、使用中のプロセス、そのほかの使用中、空きに分けます。コンテナのメモリは動かしているプロセスが既に数えているので外します。下の行は直近1分の負荷です |
| 大きい物の上位 | ディスクの行のうち大きい8件を、推奨度の色で並べます。長い名前は切らずに次の行へ折り返します |
| メモリを多く使うプロセス | メモリを最も多く使うプロセス6件です |
| CPUを多く使うプロセス | 2回の`ps`の間のCPUの使用率が最も高いプロセス6件です |

棒は名前と値を読み上げ、2つのHostのプロセスのように同じ図に名前が同じ棒がある時は、行のある場所を添えます。

## ディスクとプログラムのタブ

ディスクのタブは、キャッシュ、ビルドの出力、ゴミ箱とログ、大きいファイルと重複、プロジェクト、アプリ、道具とモデルを並べます。
プログラムのタブは、プロセス、ログイン項目、コンテナを並べます。
推奨度ごとに見出しの下に表を置き、一覧を動かしても列の見出しは上に残ります。
行は名前を行の見出しにし、大きさか、プロセスとコンテナではメモリとCPU (%) の列のCPUの使用率を出し、行の名前を付けた選ぶボタンを持ちます。
ログイン項目はメモリもCPUの使用率も持たないので、どちらの欄も空のままです。
大きいファイル、重複のコピー、3つのViteの開発サーバーの1つのようにタブの中で名前が同じ行は、2行目に文字でファイルのあるフォルダを、プロセスでは作業フォルダかコマンドを出します。
幅600px未満では、各行を、値をその名前の下に置くカードで出します。

行の名前を押すと、理由と空けた時に起きることと場所を、プロセスではメモリとCPUの使用率と開始と作業フォルダとコマンドを、名前の横に値を置く形で一覧の横に出します。
消したアプリの残りの場所や重複のコピーのような10行を超える一覧は、開くまで畳みます。
完全に消える行はその旨を別の知らせで示し、選べる行はそこからも選べて、選択を外せます。
一覧と詳しい情報は別々に動き、出している行の名前は詳しい情報の上に残ります。
一覧のタブは最初の行を出して開き、アドレスは出している行を`#item-<id>`で覚えるので、そのアドレスでページを開くとタブの中のその行が出ます。
幅860px以下では、一覧と詳しい情報を入れ替えて出します。名前を押すと一覧の代わりに詳しい情報が出て、上に「一覧へ戻る」、下に前と次の行へのリンクが付き、ブラウザの戻るでも一覧へ戻ります。

行の上の道具はタブに出す行を変えるだけで、選んだ物は変えません。

| 道具 | すること |
|---|---|
| 探す | 名前か場所に打った文字を含む行だけを出します。大文字と小文字は区別しません。何も見つからない時は打った文字を示し、絞り込みを外すボタンを出します |
| 種類 | 種類ごとに行の数を添えたボタンです。押すとその種類だけを出し、タブの説明がその種類の説明に変わります |
| 推奨度 | 推奨度ごとに行の数を添えたボタンです。切った推奨度の行を隠します |
| 並べ替え | 名前か大きさの見出し、プログラムのタブではメモリかCPU (%) の見出しを押すと、推奨度の中の行をその順に並べます。もう一度押すと逆の順になります |
| ページ | 50行を超えるタブは50行ずつ出し、一覧の上と下にページの切り替えを置きます。一覧の上の行は、全体の何行のうちどの行を出しているかを示します |

「選択を外す」はタブの全ての行の選択を外し、「元に戻す」を出して選択を戻せるようにします。
ページの右上は、選んでまだ渡していない行の数を示し、その間はページを離れる前にブラウザが聞きます。
下の帯は、選んだ行の数と、それとは別に空くディスクを出します。
何も選ばずに「空ける」を押すと、帯にその旨が出ます。
行を選んでいると、空ける件数を題にした確認の画面が開き、各行を空けた時に起きることごとに並べ、何を戻せるかを示し、「やめる」と「空ける」を出します。

## 使用中と見る物

使用中の項目は一覧に並び、詳しい情報に理由が出て、ページでも`apply`でも選べません。

| 理由 | 当たる時 |
|---|---|
| 動いているエージェントの会話の下で動いている | 親のプロセスを上へたどると、直接か`node`、`bun`、`deno`を通して動く`claude`、`codex`、`copilot`、`gemini`に着く |
| 動いているエージェントの会話そのもの | プロセスがそれらのエージェントである |
| 動いているエージェントの会話がこの下で動いている | エージェントの親のプロセスを上へたどると、会話を抱えるアプリや端末のように、このプロセスに着く |
| 動いているエージェントの会話を抱えるアプリの一部 | アプリの描画やGPUの補助のように、エージェントの親のプロセスと同じ`.app`の中から動いている |
| 動いているエージェントの会話と同じプロジェクトで作業している | プロセスの作業フォルダが、エージェントの作業フォルダと同じgitのプロジェクトの中にある。エージェントが裏で動かしたままにした開発用のサーバーを残すため |
| 開いている端末で動いている | プロセスが制御端末を持つ |
| OSの一部 | プログラムが`/System/`、`/usr/libexec/`、`/usr/sbin/`、`/sbin/`、`/usr/lib/systemd/`の下にある |
| 動いているプログラムがこのプロジェクトで作業している | プロセスの作業フォルダ (macOSは`lsof -d cwd`、Linuxは`/proc/<pid>/cwd`) が、項目を持つプロジェクトの中か、コンテナならComposeのプロジェクトの作業フォルダの中にある |
| アプリが動いている | アプリの中からプロセスが動いているか、アプリのキャッシュが動いているアプリの物である |
| 道具が動いている | キャッシュの持ち主のパッケージ管理が、インストールのような開発用のサーバー以外の物を動かしている |

調べているエージェントと、その親のプロセスは一覧から全て外します。
ほかのユーザーのプロセスは並べません。

## 入らない場所

| 場所 | 理由 |
|---|---|
| `~/Library/Mobile Documents`、`~/Library/CloudStorage`と、`~/Dropbox`、`~/OneDrive`、`~/Google Drive`、`~/iCloud Drive`、`~/Box`、`~/pCloud Drive`、`~/Nextcloud`、`~/ownCloud`、`~/MEGA` | 同期フォルダです。ここで消すとクラウド側とほかの端末からも消えます |
| WSLの`/mnt` | Windowsのドライブです |
| シンボリックリンク | 調べる時はたどらず、`apply`もリンクとその先を変えません |
| Dockerのボリューム | 作り直されないデータを持ちます |
| アプリのフォルダの中のアプリを除く、ホームの外の全て | `apply`が変えるのを断ります |

## ページとサーバー

`serve`は`scan.json`を読み、`127.0.0.1`の空いているポートを選び、一回限りの合言葉を作り、このコンピューターのブラウザにだけページを出します。
ポートと合言葉は`session.json`に残すので、`serve`をもう一度動かしても、開いているページの住所は変わりません。

| 要求 | 受け取る時 |
|---|---|
| `GET /?t=<token>` | 合言葉が合い、`Host`の見出しが`127.0.0.1:<port>`の時。調べた結果を埋めたページを返します |
| `GET /ping?t=<token>` | 同じ条件。ページが4秒ごとに聞き、エージェントが待っているかを表示します |
| `POST /select` | `Host`と`Origin`の見出しがどちらもこのサーバーを指し、本文が合言葉を持つ64KiB以下のJSONで、全ての識別子が調べた結果にあり使用中でない時 |

ほかは403か404を返すので、ブラウザで開いているほかのサイトはページを読めず、選択も送れません。
ページと全ての応答は、外への接続を許さないContent-Security-Policyを持ちます。

サーバーは選択を受け取ると`machine-cleanup:select <id> <id> ...`を出して終わり、ページは帯と右上に渡した時刻を示します。
サーバーが選択を断った時は、帯が絵の付いた警告として誤りを示し、ページはエージェントが待っているかをもう一度聞きます。
`--wait`秒 (既定は540秒) 待っても選択が届かない時は、終わり方4で終わります。
開いているページはタブの上にエージェントが待っていないことを示し、確認の画面は「空ける」の代わりに「コピー」を出します。
「コピー」は1行目に`machine-cleanup:select`、その下に識別子を1行に1つずつ並べた文を、読むだけの文字の欄とクリップボードに置きます。ブラウザがクリップボードを断った時は、Command+CかCtrl+Cでコピーできるよう文字の欄を選んだ状態にします。
`apply --select`はどちらの形も読み、どちらもページの言語に依りません。

## ページのひな形

`serve`は、スキルのひな形からページをメモリの上で組み立てます。表のパスは`skills/machine-cleanup/`から見た位置です。

| ファイル | 中身 |
|---|---|
| `templates/sheet.html` | ページ。スタイル、英語と日本語の言葉、スクリプトを中に持ちます。`serve`が調べた結果を埋め込みます |
| `musubi.json` | musubiでの`page-design/structure`、`page-design/look`、`page-design/sheet`、`page-design/verify`への任意の準拠。それぞれにバージョンの範囲`^1.0.0`と、最後に確かめた時のコンテンツのフィンガープリントと、`"optional": true`を持つ |

ページのヘッダーには、English / 日本語の切り替えと、その隣に明るい色と暗い色の切り替えがあります。
選ぶまでは色がシステムの設定に従い、ブラウザは選んだ言語と色をローカルストレージに`machine-cleanup-lang`と`machine-cleanup-theme`の名前で残します。どこへも送りません。

- `design-formats`のプラグインの`page-design`のスキルが入っていれば、エージェントはその形式`structure`と`look`、ページの型`sheet`を読みます。`musubi.json`はこれらに任意の準拠で従います。`serve`がページをメモリの上で組み立てるので、エージェントは`templates/sheet.html`に`page-design`の`verify`を回し、名指された行をあなたに伝えます。ほかのプラグインからはこれ以外を読みません
- `musubi`のコマンドが入っていれば、エージェントはこれらを読む前に`musubi check`を回し、失敗したら止まります。`design-formats`が入っていない時、`musubi check`は警告を出してこれらの準拠を飛ばします。従うコンテンツが変わると、フィンガープリントを確かめ直すまで`musubi check`は`machine-cleanup`を拒否します
- `page-design`が無ければ、ページは`templates/sheet.html`だけから作ります。プラグインのどこも`design-formats`を求めません

## 項目ごとの空け方

`apply`はその行か、識別子だけを受け取ります。
調べた結果に無い識別子、使用中の識別子、重複の全ての写しを選ぶ選択が1つでもあると、選択の全体を断り、何も変えません。

| 項目 | `apply`がすること |
|---|---|
| 消す命令を持つキャッシュ | `npm cache clean --force`、`pnpm store prune`、`yarn cache clean`、`bun pm cache rm`、`pip cache purge`、`uv cache clean`、`brew cleanup --prune=all`、`go clean -modcache`、`go clean -cache`、`pod cache clean --all`、`docker image prune -a -f`、`docker builder prune -a -f`、`docker container prune -f`を動かします。道具が入っていない時はフォルダを消します |
| ほかのキャッシュとビルドの出力 | フォルダを消します |
| ゴミ箱 | 中身を全て消します |
| 古いログ | 調べた時に並べたファイルのうち、今も30日より古い物を消します |
| インストーラー、大きいファイル、重複 | ゴミ箱へ移します。macOSは`~/.Trash`、Linuxはfreedesktop.orgのゴミ箱で、ファイルの管理の道具が元に戻せるよう`.trashinfo`の記録を書きます |
| macOSのアプリ | アプリと付属のファイル (`Application Support`、`Caches`、`Preferences`、`Containers`、`Saved Application State`、`HTTPStorages`、`WebKit`、`Logs`の中の物) をゴミ箱へ移します |
| Flatpakのアプリ | `flatpak uninstall --user -y <app>`を動かします |
| 作業フォルダと消したアプリの残り | プロジェクトのフォルダか、残りの全ての場所をゴミ箱へ移します |
| 道具の版 | 版のフォルダと、その版を指していた隣のリンク (miseの`21`と`21.7`など) を消します。rustupの版は`rustup toolchain uninstall <toolchain>`で消します |
| AIモデル | Ollamaが動いている時は`ollama rm <model>`を動かします。動いていない時は、`ollama rm`と同じく、モデルのmanifestとほかのモデルが使わないblobを消します。Hugging FaceとLM Studioのモデルはフォルダを消します |
| プロセス | 終了の合図 (SIGTERM) を送り、`--term-wait`秒 (既定は5秒) 待ちます。まだ動いているプロセスは`survived`と知らせ、その識別子を渡した`apply --kill <id>`の時だけSIGKILLを送ります |
| macOSのLaunchAgent | `launchctl bootout`を動かし、ファイルを状態のフォルダへ移します |
| Linuxの自動起動 | ファイルを状態のフォルダへ移します |
| systemdのユーザー単位 | `systemctl --user disable --now`を動かします |
| コンテナ | `docker stop`を動かします |

## 変える直前の確かめ

`apply`は`ps`を動かして作業フォルダを読み直し、項目ごとに変える前に確かめます。
確かめに通らない項目は`skipped`と理由を知らせ、そのまま残します。

| 項目 | 飛ばす時 |
|---|---|
| ファイル | 大きさ、変更した日時、ファイルの番号のどれかが調べた時と違う |
| フォルダ | フォルダが入れ替わったか、大きさが5%か1MBより大きく変わった |
| プロジェクトの中の項目 | 動いているプログラムが今そのプロジェクトで作業している |
| 作業フォルダ | 30日以内のcommitかcheckout、未commitの変更か未追跡のファイル、remoteに無いcommitのどれかがプロジェクトに増えた |
| 道具の版 | 動いているプログラムが今その版を使っている |
| Ollamaのモデル | manifestが変わった |
| プロセス | プロセスが終わったか、開始の時刻か命令が違う (プロセスの番号が別のプログラムの物になった) |
| ログイン項目 | ファイルが変わったか、無くなった |
| コンテナ | コンテナがもう動いていない |
| Dockerのキャッシュ | 空ける物が残っていない |

前と後で、ディスクの空きを`df -k`、使用中のメモリをmacOSは`vm_stat`と`sysctl hw.memsize`、Linuxは`/proc/meminfo`、負荷を平均の負荷で測り、出します。
Dockerを片付け、Docker Desktopのディスクのファイルがある時は、空きが後から増えうることを書き添えます。Docker Desktopは時間をかけてひとりでに空きを戻すからです。

## 元に戻す

`restore`は戻せる物を並べ、`restore <id>`で戻します。

| 項目 | `restore`がすること |
|---|---|
| macOSのLaunchAgent | ファイルを戻し、`launchctl bootstrap`を動かします |
| Linuxの自動起動 | ファイルを戻します |
| systemdのユーザー単位 | `systemctl --user enable --now`を動かします |
| ゴミ箱へ移したファイル、アプリ、作業フォルダ、消したアプリの残り | まだゴミ箱にあり、元の場所に何も無い時に戻します |

## 予約した片付け

`schedule add`は、`scheduled-run`を毎日か毎週動かす仕事を1件登録します。時刻は`--at HH:MM`で変えない限り03:00で、毎週の時は日曜日に動きます。
1回ごとに、利用者が許した種類だけを調べ、調べた結果がおすすめにした行を、`apply`と同じ変える直前の確かめを通して空けます。
使用中の行と、調べた後に変わった行は、`apply`と同じく飛ばします。
許せるのは下の3つの種類だけで、利用者が登録の時に選びます。

| 種類 | 1回で空ける物 | 1回で残す物 |
|---|---|---|
| `cache` | 道具が作り直すキャッシュ (道具に片付けのコマンドがあればそれで消す)、動いていないアプリのキャッシュ、Dockerのビルドキャッシュ | 道具かアプリが動いているキャッシュ、Dockerのイメージ、止まっているコンテナ |
| `build` | 30日コミットの無いプロジェクトの、gitが無視するビルドの出力 | 30日以内にコミットのあるプロジェクトのビルドの出力と、動いているプログラムが作業しているプロジェクトのビルドの出力 |
| `log` | 30日より古いログのファイル | 新しいログのファイル |

Dockerのイメージと止まっているコンテナは残します。止まっているコンテナはデータを持つことがあり、このコンピューターで作ったイメージは取り直せないことがあるからです。

| システム | 登録の仕方 | 眠っている間に過ぎた回 |
|---|---|---|
| macOS | LaunchAgent (`~/Library/LaunchAgents/machine-cleanup.schedule.plist`) を書き、`launchctl bootstrap`で読み込みます | Macが目覚めた時に動きます |
| systemdのユーザーのセッションがあるLinuxとWSL | `~/.config/systemd/user/`に`machine-cleanup.service`と`machine-cleanup.timer`を書き、`systemctl --user`で有効にします | タイマーに`Persistent=true`があるので、次に起動した時に動きます |
| それが無く、`crontab`があるLinuxとWSL | `# machine-cleanup schedule`で終わる行を、利用者の行の隣に1行足します | 飛ばします |

どちらも無いシステムでは、`schedule add`は終わり方2で断り、何も登録しません。
WSLでは、`/etc/wsl.conf`の`[boot]`に`systemd=true`を書くとsystemdが動きます。

仕事は状態のフォルダに写したスクリプトを動かします。プラグインの更新で古い版のフォルダが消えても止まりません。
予約がある間は、`scan`のたびに今のスクリプトを写しに上書きします。

1回ごとに、空けた物、飛ばした物とその理由、前と後のディスクの空きを`schedule-runs.jsonl`に足します。
`schedule show`と次の`scan`が、最後の回を出します。

macOSでは、デスクトップ、書類、ダウンロードのようにmacOSが守るフォルダを、システム設定のプライバシーとセキュリティの「ファイルとフォルダ」でPythonを許すまで読めません。
許すまでは、そのフォルダを測っていない場所として記録します。

`schedule remove`は仕事を止め、LaunchAgent、systemdの単位、crontabの行のどれかを、`schedule.json`と写したスクリプトと一緒に消します。
過去の回の記録は残します。

## 残す物

全て`~/.local/share/machine-cleanup/` (か`MACHINE_CLEANUP_HOME`) に置きます。フォルダもファイルも自分だけが読めます。

| ファイル | 中身 | 消す物 |
|---|---|---|
| `scan.json` | 最後に調べた結果 | 次の`scan`か`finish` |
| `session.json` | ページのポートと合言葉 | `apply`か`finish` |
| `selection.txt` | ページが最後に送った選択 | `apply`か`finish` |
| `survivors.json` | 最後の`apply`で残ったプロセス | 次の`apply`か`finish` |
| `restore.json` | `restore`が戻せる物 | 項目を戻した`restore` |
| `disabled/` | 止めたログイン項目のファイル | `restore` |
| `schedule.json` | 許した種類、予約が動く間隔と時刻、予約を動かすシステム | `schedule remove` |
| `machine_cleanup.py` | 予約の仕事が動かすスクリプトの写し | `schedule remove` |
| `schedule-runs.jsonl` | 予約の回ごとに空けた物と飛ばした物、前と後のディスクの空き | 消しません。自分で消すまで残ります |

プロセスの命令の文は、名前にtoken、secret、password、passwd、api-key、apikey、authを含む引数と変数の値を`***`に置き換えてから残します。

## しないこと

- 選んでいない物と使用中の物を、消す、移す、止める
- シンボリックリンクをたどる、同期フォルダかWindowsのドライブに入る、アプリを除くホームの外の物を変える
- 管理者のパスワードを求める、使う、ほかのユーザーのプロセスに触れる
- ネットワークに何かを送る、`127.0.0.1`以外でページを出す
- OSの設定を変える、裏で動き続ける物を入れる (頼まれた時に`schedule add`が登録する予約の仕事1件を除く)

## 環境変数

| 変数 | 効果 |
|---|---|
| `MACHINE_CLEANUP_HOME` | `~/.local/share/machine-cleanup`の代わりに使う状態のフォルダ |
| 「調べ方」のキャッシュの変数 | パッケージ管理ごとのキャッシュを探す場所 |
| 「調べ方」の道具の版とモデルの変数 | 版の管理の道具が版を置く場所と、モデルを探す場所 |

## 終わり方

| 番号 | 意味 |
|---|---|
| 0 | 終わった |
| 1 | `apply`か`restore`が断り、何も変えていない |
| 2 | 入力が誤っているか、まだ調べていないか、`schedule add`でsystemdもcronも動かないシステムだった |
| 3 | `apply`か予約の回が空けられない項目があったか、`schedule add`が仕事を登録できなかった |
| 4 | `serve`が選択を受け取らずに待ち終えた |
