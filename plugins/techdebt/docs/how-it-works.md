# How Tech Debt works

English · [日本語](how-it-works.ja.md)

This page explains each measure, how files are ranked, what is skipped, and what the plugin keeps.
Everything here is done by `skills/techdebt/scripts/techdebt.py`, which uses only the Python standard library and `git`.

## Which files it reads

It reads the files `git ls-files` lists in the folder you scan, including untracked files that `.gitignore` does not exclude.
Outside a git repository it walks the folder instead, skipping hidden folders.
It reads source files in Python, JavaScript, TypeScript, Vue, Svelte, Go, Rust, Java, Kotlin, Scala, C, C++, Objective-C, C#, Swift, PHP, Solidity, Dart, Ruby, Lua, shell, Elixir, Clojure, and Haskell.

These are skipped.

| Skipped | Why |
|---|---|
| `node_modules`, `vendor`, `dist`, `build`, `.next`, `target`, `.venv`, `coverage`, and other dependency and build folders | Not your code |
| Lockfiles, minified files, source maps, snapshots, and generated protobuf files | Generated |
| Files whose first 5 lines say `@generated`, `DO NOT EDIT`, or `Code generated by` | Generated |
| Files over 1 MB, binary files, and symlinks | Not source code |

## The measures

| Measure | How it is measured | Listed when |
|---|---|---|
| Hotspots | Commits that touched the file in the last 12 months (`--months N` changes it), from `git log`, and the file's non-blank lines | The file changed 2 or more times |
| Markers | `TODO`, `FIXME`, `HACK`, and `XXX` inside a comment, found outside string literals, and deprecation markers that start a line (`@deprecated`, `@Deprecated`, `#[deprecated]`, `[Obsolete]`). The age is the commit date of the line from `git blame`; a line not yet committed has no age | Always |
| Untested | A source file and a test file match when their names share a stem: `foo.py` with `test_foo.py`, `foo.ts` with `foo.test.ts` or `foo.spec.ts`, `Foo.java` with `FooTest.java`, `foo.go` with `foo_test.go`, and `foo-bar.py` with `test-foo-bar.sh`. A test file is one with such a name or inside a `test`, `tests`, `__tests__`, `spec`, or `e2e` folder. A Rust file with `#[cfg(test)]` counts as tested | The file has 20 or more non-blank lines and is not a config, type declaration, `__init__.py`, `setup.py`, or `conftest.py` file |
| Long functions | Python: each function's span and branches from `ast`, exactly. JavaScript, TypeScript, Go, Rust, Java, Kotlin, C, C++, C#, Swift, PHP, and Solidity: the function's header, then braces counted outside strings and comments until it closes. Branches are `if`, `for`, `while`, `case`, `catch`, `&&`, `||`, and `?` | Over 60 lines |
| Large files | Non-blank lines | Over 500 |
| Duplication | Lines are compared after removing whitespace, blank lines, imports, comments, and lines of only brackets. Any 8 lines in a row that appear in two places are joined into the longest matching block | 8 or more lines, outside test files |

Function length is not measured for Ruby, Lua, shell, Elixir, Clojure, and Haskell; the summary names those languages when they appear.

## Tools that are already installed

| Tool | Where it is looked for | What is kept |
|---|---|---|
| `knip` | `node_modules/.bin/knip`, when `package.json` exists | Unused files, exports, types, and dependencies, and dependencies that are used but not listed |
| `ruff` | `.venv/bin/ruff`, then `PATH`, when the folder has Python files | Rules `C901`, `PLR0911`, `PLR0912`, `PLR0913`, and `PLR0915` (complexity, returns, branches, arguments, and statements) |

A tool that is not installed is reported as not run, with the reason.
The plugin never downloads or installs a tool.

## The ranking

Each file outside the tests gets a score from 0 to 1.
Each measure is divided by the largest value of that measure in the scan, so the busiest file scores 1 on it.

| Part | Weight |
|---|---|
| Changes multiplied by non-blank lines | 40% |
| Long functions | 20% |
| Markers, counting `FIXME` and `HACK` twice | 15% |
| Duplicated lines | 15% |
| No test file, multiplied by how often the file changes | 10% |

The 20 highest scores are ranked.
Changes carry the most weight because debt costs time only where people keep working.

## The agent's notes

For the top files, the agent reads each file and its history and writes three things: what the file does, why it costs the team, and the first step to fix it.
`explain --notes` saves them only when every entry names a ranked file and fills all three; otherwise it saves nothing and exits with code 2.
Notes stay with the same file in later scans while the file is still ranked.

## What it keeps

The plugin keeps three files per scanned folder in `~/.local/share/techdebt/<folder name>-<hash>/`, or under `TECHDEBT_HOME` when it is set.
The folder is readable only by you, and the files stay until you delete them.

| File | Contents |
|---|---|
| `scan.json` | Every measure, the ranking, and the scanned folder's path |
| `notes.json` | The agent's notes |
| `report.html` | The report, with the data inside the page. It loads nothing from the network |

## What it never does

- Change, format, or delete a file in your project
- Download, install, or update a package or tool
- Connect to the network
- Send your code or its history anywhere
