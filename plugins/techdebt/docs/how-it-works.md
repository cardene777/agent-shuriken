# How Tech Debt works

English · [日本語](how-it-works.ja.md)

This page explains each measure, how files are ranked, what is skipped, and what the plugin keeps.
Everything here is done by `skills/techdebt/scripts/techdebt.py`, which uses only the Python standard library and `git`.

## Which files it reads

It reads the files `git ls-files` lists in the folder you scan, including untracked files that `.gitignore` does not exclude.
Outside a git repository it walks the folder instead, skipping hidden folders.
It reads source files in Python, JavaScript, TypeScript, Vue, Svelte, Go, Rust, Java, Kotlin, Scala, C, C++, Objective-C, C#, Swift, PHP, Solidity, Dart, Ruby, Lua, shell, Elixir, Clojure, and Haskell.

These are skipped.

| Skipped | Why |
|---|---|
| `node_modules`, `vendor`, `dist`, `build`, `.next`, `target`, `.venv`, `coverage`, and other dependency and build folders | Not your code |
| Lockfiles, minified files, source maps, snapshots, and generated protobuf files | Generated |
| Files whose first 5 lines say `@generated`, `DO NOT EDIT`, or `Code generated by` | Generated |
| Files over 1 MB, binary files, and symlinks | Not source code |

## The measures

| Measure | How it is measured | Listed when |
|---|---|---|
| Hotspots | Commits that touched the file in the last 12 months (`--months N` changes it), from `git log`, and the file's non-blank lines | The file changed 2 or more times |
| Markers | `TODO`, `FIXME`, `HACK`, and `XXX` inside a comment, found outside string literals, and deprecation markers that start a line (`@deprecated`, `@Deprecated`, `#[deprecated]`, `[Obsolete]`). The age is the commit date of the line from `git blame`; a line not yet committed has no age | Always |
| Untested | A source file and a test file match when their names share a stem: `foo.py` with `test_foo.py`, `foo.ts` with `foo.test.ts` or `foo.spec.ts`, `Foo.java` with `FooTest.java`, `foo.go` with `foo_test.go`, and `foo-bar.py` with `test-foo-bar.sh`. A test file is one with such a name or inside a `test`, `tests`, `__tests__`, `spec`, or `e2e` folder. A Rust file with `#[cfg(test)]` counts as tested | The file has 20 or more non-blank lines and is not a config, type declaration, `__init__.py`, `setup.py`, or `conftest.py` file |
| Long functions | Python: each function's span and branches from `ast`, exactly. JavaScript, TypeScript, Go, Rust, Java, Kotlin, C, C++, C#, Swift, PHP, and Solidity: the function's header, then braces counted outside strings and comments until it closes. Branches are `if`, `for`, `while`, `case`, `catch`, `&&`, `||`, and `?` | Over 60 lines |
| Large files | Non-blank lines | Over 500 |
| Duplication | Lines are compared after removing whitespace, blank lines, imports, comments, and lines of only brackets. Any 8 lines in a row that appear in two places are joined into the longest matching block | 8 or more lines, outside test files |
| Unused dependencies | Approximate, by name. For each `package.json`, the names in `dependencies` and `devDependencies` are looked for in the files under its folder: module names in `import`, `export ... from`, `import()`, `require()`, and `require.resolve()` (`lodash/fp` counts for `lodash`), quoted names in config files (`*.config.*`, `.*rc`, `tsconfig*.json`) and in the other fields of `package.json`, and command names in `scripts`, including the `bin` names of packages installed in `node_modules`, such as `tsc` for `typescript`. A package is also used when a used package lists it in `peerDependencies`, when a config names it by its short name (`react` for `eslint-plugin-react`), or, for `@types/<name>`, when `<name>` is used. When `knip` ran, its unused dependencies are listed instead, and the search does not run | No use was found |
| Deprecated calls | Found by the tools that are already installed, described in the next section: `ruff` with its deprecation rules, `semgrep` with the project's own rule files, and `eslint` with the deprecation rules its config turns on. Each tool that did not run is listed with the reason, and the measure counts as not checked when none ran | A tool reported a call to a deprecated API |

Function length is not measured for Ruby, Lua, shell, Elixir, Clojure, and Haskell; the summary names those languages when they appear.

## Tools that are already installed

| Tool | Where it is looked for | What is kept |
|---|---|---|
| `knip` | `node_modules/.bin/knip`, when `package.json` exists | Unused files, exports, and types, and dependencies that are used but not listed. Its unused dependencies are shown under the unused dependencies measure, not here |
| `ruff` | `.venv/bin/ruff`, then `PATH`, when the folder has Python files | Rules `C901`, `PLR0911`, `PLR0912`, `PLR0913`, and `PLR0915` (complexity, returns, branches, arguments, and statements). Its rules for deprecated APIs go to the deprecated calls measure: `UP005`, `UP019`, `UP021`, `UP023`, `UP026`, and `UP035` (aliases and imports of the standard library), `NPY001`, `NPY003`, and `NPY201` (numpy), `PT020` (pytest), `PD007` (pandas), `PYI057` (typing), `G010` (logging), `AIR301`, `AIR302`, `AIR311`, and `AIR312` (Airflow 3), and `TID251` (APIs the project bans in its ruff config). The security rule `S306` is not used |
| `semgrep` | `.venv/bin/semgrep`, then `PATH`, when the folder has `.semgrep.yml`, `.semgrep.yaml`, or `.semgrep/` | It runs as `semgrep scan --json --quiet --metrics off --disable-version-check` with a `--config` for each of those rule files, and never with registry rules such as `auto` or `p/...`. A finding whose rule id or `category` says security is dropped. A finding whose rule id, message, or metadata mentions deprecation goes to the deprecated calls measure. The rest are kept here. semgrep's settings, anonymous id, and log go to a temporary folder that is removed after the run, so `~/.semgrep` is not written and a semgrep login is not used |
| `eslint` | `node_modules/.bin/eslint`, when `package.json` exists | It first runs `eslint --print-config` on a JavaScript or TypeScript file. Only when the config turns on a deprecation rule, such as `@typescript-eslint/no-deprecated`, `react/no-deprecated`, `import/no-deprecated`, or `deprecation/deprecation`, it runs `eslint --format json .` with the project's config and keeps the findings of those rules, under the deprecated calls measure |

A tool that is not installed is reported as not run, with the reason.
A tool that stops with an error is also reported as not run, with its exit code and the first line it wrote, so that its findings are not counted as zero.
The plugin never downloads or installs a tool.

## The ranking

Each file outside the tests gets a score from 0 to 1.
Each measure is divided by the largest value of that measure in the scan, so the busiest file scores 1 on it.

| Part | Weight |
|---|---|
| Changes multiplied by non-blank lines | 40% |
| Long functions | 20% |
| Markers, counting `FIXME` and `HACK` twice | 15% |
| Duplicated lines | 15% |
| No test file, multiplied by how often the file changes | 10% |

The 20 highest scores are ranked.
Changes carry the most weight because debt costs time only where people keep working.

## The agent's notes

For the top files, the agent reads each file and its history and writes three things: what the file does, why it costs the team, and the first step to fix it.
`explain --notes` saves them only when every entry names a ranked file and fills all three; otherwise it saves nothing and exits with code 2.
Notes stay with the same file in later scans while the file is still ranked.

## What it keeps

The plugin keeps three files per scanned folder in `~/.local/share/techdebt/<folder name>-<hash>/`, or under `TECHDEBT_HOME` when it is set.
The folder is readable only by you, and the files stay until you delete them.

| File | Contents |
|---|---|
| `scan.json` | Every measure, the ranking, and the scanned folder's path |
| `notes.json` | The agent's notes |
| `report.html` | The report, with the data inside the page. It loads nothing from the network |

`scan.json` records the version of its format, now 3, which added the deprecated calls. `explain` and `report` refuse a `scan.json` written by another version of the plugin and ask you to run `scan` again, so a report is never built from data it cannot read.

### Text hidden in marker lines

`scan.json` and the report keep up to 200 characters of each marker line, so a comment that quotes a secret would carry it into them and into any issue that quotes the line.
Before a line is kept, the plugin replaces the text below, on the whole line before it is cut to 200 characters.

| Text | Shown as |
|---|---|
| The home folder | `~` |
| Keys of a known shape: private key headers, AWS access key IDs, GitHub, GitLab, Slack, Stripe, Google API, and npm tokens, `sk-` keys, and JSON Web Tokens | `***` |
| A user name and password in a URL | `https://***@host` |
| A token after `Bearer` or `Basic` | `Bearer ***` |
| A value of 8 or more characters after `NAME=` when the name is in capitals or contains a word such as key, token, secret, password, or session, and after `name:` when such a name is followed by a quoted value or one with digits or symbols | `NAME=***` |
| A run of 32 or more letters and digits with upper and lower case and digits whose words average under 4 characters, as random tokens do. camelCase names average 4 or more and stay | `***` |

Text that none of these match stays as it is, so read a marker line before quoting it outside the report.

## What it never does

- Change, format, or delete a file in your project
- Download, install, or update a package or tool
- Connect to the network
- Send your code or its history anywhere
