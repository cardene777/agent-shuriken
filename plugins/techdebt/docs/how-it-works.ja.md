# Tech Debtの仕組み

[English](how-it-works.md) · 日本語

このページには、各項目の測り方、ファイルの順位の付け方、飛ばす物、プラグインが残す物を載せています。
ここに書いたことはすべて`skills/techdebt/scripts/techdebt.py`が行い、使うのはPythonの標準ライブラリと`git`だけです。

## 読むファイル

調べるフォルダで`git ls-files`が並べるファイルを読みます。`.gitignore`で外していない、まだ追跡していないファイルも含みます。
gitのリポジトリの外では、隠しフォルダを飛ばしながらフォルダをたどります。
読むのは、Python、JavaScript、TypeScript、Vue、Svelte、Go、Rust、Java、Kotlin、Scala、C、C++、Objective-C、C#、Swift、PHP、Solidity、Dart、Ruby、Lua、シェル、Elixir、Clojure、Haskellのソースファイルです。

次の物は飛ばします。

| 飛ばす物 | 理由 |
|---|---|
| `node_modules`、`vendor`、`dist`、`build`、`.next`、`target`、`.venv`、`coverage`などの依存とビルドのフォルダ | 自分たちのコードではないため |
| ロックファイル、縮めたファイル、ソースマップ、スナップショット、protobufから作ったファイル | 生成された物のため |
| 最初の5行に`@generated`、`DO NOT EDIT`、`Code generated by`とあるファイル | 生成された物のため |
| 1MBを超えるファイル、バイナリ、シンボリックリンク | ソースコードではないため |

## 項目

| 項目 | 測り方 | 並べる条件 |
|---|---|---|
| 変更の集中 | 直近12か月(`--months N`で変えられます)にそのファイルを変えたコミットの数を`git log`から数え、空行を除いた行数と合わせます | 2回以上変わったファイル |
| 目印 | コメントの中にある`TODO`、`FIXME`、`HACK`、`XXX`を文字列の外で探します。行の頭にある非推奨の目印(`@deprecated`、`@Deprecated`、`#[deprecated]`、`[Obsolete]`)も数えます。古さは`git blame`で調べたその行のコミットの日付で、まだコミットしていない行には古さがありません | 常に |
| テストの無いファイル | ソースファイルとテストファイルは、名前の幹が同じ時に対応するとみなします。`foo.py`と`test_foo.py`、`foo.ts`と`foo.test.ts`か`foo.spec.ts`、`Foo.java`と`FooTest.java`、`foo.go`と`foo_test.go`、`foo-bar.py`と`test-foo-bar.sh`がこれに当たります。テストファイルは、こうした名前のファイルか、`test`、`tests`、`__tests__`、`spec`、`e2e`のフォルダにあるファイルです。`#[cfg(test)]`のあるRustのファイルはテスト済みとみなします | 空行を除いて20行以上で、設定、型の宣言、`__init__.py`、`setup.py`、`conftest.py`のどれでもないファイル |
| 長い関数 | Pythonは`ast`で各関数の範囲と分岐を正確に測ります。JavaScript、TypeScript、Go、Rust、Java、Kotlin、C、C++、C#、Swift、PHP、Solidityは、関数の頭を見つけ、文字列とコメントの外で波括弧を数えて閉じるまでを測ります。分岐として数えるのは`if`、`for`、`while`、`case`、`catch`、`&&`、`||`、`?`です | 60行を超える関数 |
| 大きいファイル | 空行を除いた行数 | 500行を超えるファイル |
| 重複 | 空白、空行、import、コメント、括弧だけの行を除いて行を比べます。続けて8行が2か所に現れたら、一致する範囲をつないで一番長い部分にします | テストファイル以外で8行以上 |
| 使っていない依存 | 名前で探す概算です。`package.json`ごとに、`dependencies`と`devDependencies`の名前を、そのフォルダーの下のファイルで探します。探すのは、`import`、`export ... from`、`import()`、`require()`、`require.resolve()`のモジュール名(`lodash/fp`は`lodash`と数えます)、設定のファイル(`*.config.*`、`.*rc`、`tsconfig*.json`)と`package.json`のほかの欄にある引用符の中の名前、`scripts`の命令の名前です。命令の名前には、`node_modules`に入っている依存の`bin`の名前(`typescript`に対する`tsc`など)も含めます。使っている依存が`peerDependencies`に挙げる依存、設定に短い名前で書かれた依存(`eslint-plugin-react`に対する`react`)、使っている`<名前>`に対する`@types/<名前>`も、使っている物と数えます。`knip`が動いた時は`knip`の結果を並べ、名前では探しません | 使っている所が見つからない依存 |

Ruby、Lua、シェル、Elixir、Clojure、Haskellでは関数の長さを測りません。これらの言語が含まれる時は、要約に名前を出します。

## すでに入っている道具

| 道具 | 探す場所 | 残す結果 |
|---|---|---|
| `knip` | `package.json`がある時に`node_modules/.bin/knip` | 使われていないファイル、export、型と、使っているのに書かれていない依存。使っていない依存は、ここではなく使っていない依存の項目に並べます |
| `ruff` | Pythonのファイルがある時に`.venv/bin/ruff`、無ければ`PATH` | 規則`C901`、`PLR0911`、`PLR0912`、`PLR0913`、`PLR0915`(複雑さ、returnの数、分岐の数、引数の数、文の数) |

入っていない道具は、理由を添えて「動かしていない」と報告します。
プラグインが道具を取り寄せたり入れたりすることはありません。

## 順位の付け方

テスト以外の各ファイルに0から1の点を付けます。
項目ごとに、その調べた範囲での一番大きい値で割るので、各項目で一番多いファイルが1になります。

| 部分 | 重み |
|---|---|
| 変更の回数と空行を除いた行数の積 | 40% |
| 長い関数 | 20% |
| 目印。`FIXME`と`HACK`は2つ分に数えます | 15% |
| 重複した行 | 15% |
| テストファイルが無いこと。ファイルの変更の多さを掛けます | 10% |

点の高い20個に順位を付けます。
変更の回数の重みを一番大きくしているのは、負債が時間を奪うのは人が作業し続ける所だけだからです。

## エージェントの説明

上位のファイルについて、エージェントは各ファイルとその履歴を読み、3つのことを書きます。何のファイルか、なぜチームの負担になるか、直す最初の一手です。
`explain --notes`は、どの項目も順位の付いたファイルを指し、3つすべてを埋めている時だけ保存します。そうでない時は何も保存せず、終了コード2で止まります。
説明は、そのファイルに順位が付いている間、後の調べ直しでも同じファイルに残ります。

## 残す物

調べたフォルダごとに3つのファイルを`~/.local/share/techdebt/<フォルダ名>-<ハッシュ>/`に置きます。`TECHDEBT_HOME`を設定している時はその下です。
このフォルダはあなただけが読め、消すまで残ります。

| ファイル | 中身 |
|---|---|
| `scan.json` | すべての項目、順位、調べたフォルダのパス |
| `notes.json` | エージェントの説明 |
| `report.html` | 報告のページ。データはページの中にあり、ネットワークから何も読み込みません |

`scan.json`は形式の版を持ちます。`explain`と`report`は、別の版のプラグインが書いた`scan.json`を断り、`scan`のやり直しを求めます。読めないデータから報告を作らないためです。

### 目印の行で隠す物

`scan.json`と報告は、目印のある行を200文字まで残します。秘密の値を書いたコメントがあると、その値がこの2つに入り、その行を引いたIssueにも入ります。
そのため行を残す前に、次の文字列を置き換えます。置き換えは200文字に切る前に、行の全体に対して行います。

| 文字列 | 表示 |
|---|---|
| ホームフォルダ | `~` |
| 決まった形の鍵。秘密鍵の見出し、AWSのアクセスキーID、GitHub、GitLab、Slack、Stripe、Google API、npmのトークン、`sk-`で始まる鍵、JSON Web Token | `***` |
| URLの中のユーザー名とパスワード | `https://***@host` |
| `Bearer`か`Basic`の後のトークン | `Bearer ***` |
| `NAME=`の後の8文字以上の値。名前が大文字の時か、key、token、secret、password、sessionのような語を含む時に隠します。`name:`の後は、そのような名前に引用符付きの値か、数字や記号を含む値が続く時に隠します | `NAME=***` |
| 大文字、小文字、数字を含む32文字以上の英数字の並びで、語の平均の長さが4文字未満の物。乱数のトークンはこの形になります。camelCaseの名前は平均が4文字以上なので残ります | `***` |

どれにも当たらない文字列はそのまま残ります。報告の外へ目印の行を引く前に、その行を読んで確かめてください。

## 決してしないこと

- プロジェクトのファイルを書き換える、整形する、消すこと
- パッケージや道具を取り寄せる、入れる、更新すること
- ネットワークにつなぐこと
- コードや履歴をどこかへ送ること
