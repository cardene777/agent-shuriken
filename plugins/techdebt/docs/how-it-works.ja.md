# Tech Debtの仕組み

[English](how-it-works.md) · 日本語

このページには、各項目の測り方、ファイルの順位の付け方、飛ばす物、プラグインが残す物を載せています。
ここに書いたことはすべて`skills/techdebt/scripts/techdebt.py`が行い、使うのはPythonの標準ライブラリと`git`だけです。

## 読むファイル

調べるフォルダで`git ls-files`が並べるファイルを読みます。`.gitignore`で外していない、まだ追跡していないファイルも含みます。
gitのリポジトリの外では、隠しフォルダを飛ばしながらフォルダをたどります。
読むのは、Python、JavaScript、TypeScript、Vue、Svelte、Go、Rust、Java、Kotlin、Scala、C、C++、Objective-C、C#、Swift、PHP、Solidity、Dart、Ruby、Lua、シェル、Elixir、Clojure、Haskellのソースファイルです。

次の物は飛ばします。

| 飛ばす物 | 理由 |
|---|---|
| `node_modules`、`vendor`、`dist`、`build`、`.next`、`target`、`.venv`、`coverage`などの依存とビルドのフォルダ | 自分たちのコードではないため |
| ロックファイル、縮めたファイル、ソースマップ、スナップショット、protobufから作ったファイル | 生成された物のため |
| 最初の5行に`@generated`、`DO NOT EDIT`、`Code generated by`とあるファイル | 生成された物のため |
| 1MBを超えるファイル、バイナリ、シンボリックリンク | ソースコードではないため |

## 項目

| 項目 | 測り方 | 並べる条件 |
|---|---|---|
| 変更の集中 | 直近12か月(`--months N`で変えられます)にそのファイルを変えたコミットの数を`git log`から数え、空行を除いた行数と合わせます | 2回以上変わったファイル |
| TODOなどのコメント | コメントの中にある`TODO`、`FIXME`、`HACK`、`XXX`を文字列の外で探します。行の頭にある非推奨の書き込み(`@deprecated`、`@Deprecated`、`#[deprecated]`、`[Obsolete]`)も数えます。古さは`git blame`で調べたその行のコミットの日付で、まだコミットしていない行には古さがありません | 常に |
| テストの無いファイル | ソースファイルとテストファイルは、名前の幹が同じ時に対応するとみなします。`foo.py`と`test_foo.py`、`foo.ts`と`foo.test.ts`か`foo.spec.ts`、`Foo.java`と`FooTest.java`、`foo.go`と`foo_test.go`、`foo-bar.py`と`test-foo-bar.sh`がこれに当たります。テストファイルは、こうした名前のファイルか、`test`、`tests`、`__tests__`、`spec`、`e2e`のフォルダにあるファイルです。`#[cfg(test)]`のあるRustのファイルはテスト済みとみなします | 空行を除いて20行以上で、設定、型の宣言、`__init__.py`、`setup.py`、`conftest.py`のどれでもないファイル |
| 長い関数 | Pythonは`ast`で各関数の範囲と分岐を正確に測ります。JavaScript、TypeScript、Go、Rust、Java、Kotlin、C、C++、C#、Swift、PHP、Solidityは、関数の頭を見つけ、文字列とコメントの外で波括弧を数えて閉じるまでを測ります。引数と戻り値の型の中の波括弧は本体と読みません。テンプレート文字列や生文字列のように複数行にまたがる文字列は、終わりまで文字列として読みます。分岐として数えるのは`if`、`for`、`while`、`case`、`catch`、`&&`、`||`、`?`です | 60行を超える関数 |
| 大きいファイル | 空行を除いた行数 | 500行を超えるファイル |
| 重複 | 空白、空行、import、コメント、括弧だけの行を除いて行を比べます。続けて8行が2か所に現れたら、一致する範囲をつないで一番長い部分にします | テストファイル以外で8行以上 |
| 使っていない依存 | 名前で探す概算です。`package.json`ごとに、`dependencies`と`devDependencies`の名前を、そのフォルダーの下のファイルで探します。探すのは、`import`、`export ... from`、`import()`、`require()`、`require.resolve()`のモジュール名(`lodash/fp`は`lodash`と数えます)、設定のファイル(`*.config.*`、`.*rc`、`tsconfig*.json`)と`package.json`のほかの欄にある引用符の中の名前、`scripts`の命令の名前です。命令の名前には、`node_modules`に入っている依存の`bin`の名前(`typescript`に対する`tsc`など)も含めます。使っている依存が`peerDependencies`に挙げる依存、設定に短い名前で書かれた依存(`eslint-plugin-react`に対する`react`)、使っている`<名前>`に対する`@types/<名前>`も、使っている物と数えます。`knip`が動いた時は`knip`の結果を並べ、名前では探しません | 使っている所が見つからない依存 |
| 非推奨の呼び出し | 次の節のすでに入っているツールで探します。`ruff`は非推奨の規則で、`semgrep`はプロジェクトの規則のfileで、`eslint`は設定が有効にしている非推奨の規則で探します。動かなかったツールは理由と一緒に挙げ、どのツールも動かなかった時は調べていないと扱います | ツールが非推奨のAPIの呼び出しを挙げた所 |

Ruby、Lua、シェル、Elixir、Clojure、Haskellでは関数の長さを測りません。これらの言語が含まれる時は、要約に名前を出します。

## すでに入っているツール

| ツール | 探す場所 | 残す結果 |
|---|---|---|
| `knip` | `package.json`がある時に`node_modules/.bin/knip` | 使われていないファイル、export、型と、使っているのに書かれていない依存。使っていない依存は、ここではなく使っていない依存の項目に並べます |
| `ruff` | Pythonのファイルがある時に`.venv/bin/ruff`、無ければ`PATH` | 規則`C901`、`PLR0911`、`PLR0912`、`PLR0913`、`PLR0915`(複雑さ、returnの数、分岐の数、引数の数、文の数)。非推奨のAPIの規則は、非推奨の呼び出しの項目に並べます。`UP005`、`UP019`、`UP021`、`UP023`、`UP026`、`UP035`(標準ライブラリの別名とimport)、`NPY001`、`NPY003`、`NPY201`(numpy)、`PT020`(pytest)、`PD007`(pandas)、`PYI057`(typing)、`G010`(logging)、`AIR301`、`AIR302`、`AIR311`、`AIR312`(Airflow 3)、`TID251`(プロジェクトがruffの設定で禁じたAPI)がこれに当たります。セキュリティの規則`S306`は使いません |
| `semgrep` | `.semgrep.yml`、`.semgrep.yaml`、`.semgrep/`のどれかがある時に`.venv/bin/semgrep`、無ければ`PATH` | `semgrep scan --json --quiet --metrics off --disable-version-check`に、その規則のfileごとの`--config`を付けて回します。`auto`や`p/...`のような登録所の規則は使いません。規則のidか`category`がセキュリティを示す結果は捨てます。規則のid、文、metadataが非推奨に触れる結果は、非推奨の呼び出しの項目に並べます。残りをここに並べます。semgrepの設定、匿名のid、記録は一時のフォルダーに書かせて回した後に消すので、`~/.semgrep`には書かず、semgrepのログインも使いません |
| `eslint` | `package.json`がある時に`node_modules/.bin/eslint` | まずJavaScriptかTypeScriptのファイル1つに`eslint --print-config`を回します。設定が`@typescript-eslint/no-deprecated`、`react/no-deprecated`、`import/no-deprecated`、`deprecation/deprecation`のような非推奨の規則を有効にしている時だけ、プロジェクトの設定のまま`eslint --format json .`を回し、その規則の結果を非推奨の呼び出しの項目に並べます |

入っていないツールは、理由を添えて「動かしていない」と報告します。
`scan.json`と要約は理由を英語で書きます。
報告は理由を英語か日本語の報告の文で、何が起きたかと次にすることの2文で出します。
誤りで止まったツールも、`scan.json`と要約では終了コードと最初に書いた行を添えて「動かしていない」と報告し、結果を0件と数えません。
報告はこのツールに「止まった」の札を付け、終了コードとツールが書いた誤りの文は出しません。
報告は、ツールが書いた結果の文を、報告の文と分けてコードの書式で1字も変えずに引きます。
`scan.json`はツールが書いたとおりに残します。
プラグインがツールを取り寄せたり入れたりすることはありません。

## 順位の付け方

テスト以外の各ファイルに0から1の点を付けます。
項目ごとに、その調べた範囲での一番大きい値で割るので、各項目で一番多いファイルが1になります。

| 部分 | 重み |
|---|---|
| 変更の回数と空行を除いた行数の積 | 40% |
| 長い関数 | 20% |
| TODOなどのコメント。`FIXME`と`HACK`は2つ分に数えます | 15% |
| 重複した行 | 15% |
| テストファイルが無いこと。ファイルの変更の多さを掛けます | 10% |

点の高い20個に順位を付けます。
変更の回数の重みを一番大きくしているのは、負債が時間を奪うのは人が作業し続ける所だけだからです。

## エージェントの説明

上位のファイルについて、エージェントは各ファイルとその履歴を読み、3つのことを書きます。何のファイルか、なぜチームの負担になるか、直す最初の一手です。
`explain --notes`は、どの項目も順位の付いたファイルを指し、3つすべてを埋めている時だけ保存します。そうでない時は何も保存せず、終了コード2で止まります。
説明は、そのファイルに順位が付いている間、後の調べ直しでも同じファイルに残ります。

## 報告のページ

`report`は、スキルのひな形から`report.html`を書きます。表のパスは`skills/techdebt/`から見た位置です。

| ファイル | 持つ物 |
|---|---|
| `templates/base.html` | 報告のページ。スタイルとスクリプトを中に持ちます。`report`が調べた結果、エージェントの説明、プロジェクトの名前を入れます |
| `musubi.json` | musubiでの`page-design/structure`、`page-design/look`、`page-design/report`、`page-design/verify`への任意の準拠。それぞれにバージョンの範囲（`structure`は`^1.0.0`、ほかは`^2.0.0`）と、最後に確かめた時のコンテンツのフィンガープリントと、`"optional": true`を持つ |

報告の題は`<project>の技術的負債`です。
題の下には、調べた時の事実を表の行で並べ、各行の太字の名前の横に値を置きます。
並べるのは、コミット、ブランチ、ソースファイルの数、調べた期間のコミットの数、報告を作った日時です。
gitの外では、最初の行がgitの履歴が無いことを示し、本文の最初のお知らせが測っていない値を示します。
見出しの帯には、言語の切り替えと、その隣に明るい色と暗い色の切り替えがあります。
選ぶまでは色がシステムの設定に従い、ブラウザは選んだ言語と色をローカルストレージに`techdebt-lang`と`techdebt-theme`の名前で残します。
どこへも送りません。

見出しの帯の下には、項目ごとに1枚のカードを並べた数の帯があります。
カードを押すと、その項目を持つタブが開き、その項目の節へ移ります。
動かせなかった項目は0ではなく「測っていない」と出します。
gitの外の変更の集中、`package.json`が無い時の使っていない依存、`ruff`と`semgrep`と`eslint`がどれも動かなかった時の非推奨の呼び出しがこれに当たります。
knipを使わず名前で探した使っていない依存は、カードに名前で探した概算であることを添え、表の上の注意の欄で消す前に1つずつ確かめるよう伝えます。
数の帯の日本語の見出しは、辞書が`\u200b`で示す句の切れ目でだけ折り返します。

報告には5つのタブがあり、各タブの名前の横に、そのタブが持つ行の数を出します。

| タブ | 持つ物 |
|---|---|
| 優先順 | 直す順に並べたファイルと、押したファイルの詳しい中身 |
| 変更の履歴 | 変更の集中とTODOなど |
| コード | 名前の合うテストが無いファイル、長い関数、大きいファイル、重複 |
| 依存 | 使っていない依存と非推奨の呼び出し |
| ツール | 走査で動いたツールごとの指摘 |

優先順のタブは、各ファイルの0から1の点数を、`scan`の要約と同じ小数2桁の数と、同じ値の棒で並べます。
行を押すと、その行の項目と点数とエージェントの注記を一覧の横に出し、一覧と詳しい中身は別々にスクロールします。
幅が860px以下の画面では、詳しい中身が一覧に代わって出て、一覧へ戻るボタンと、前と次のファイルへのリンクを持ちます。
ページのアドレスは開いている物を持ちます。
開いたファイルは`#item-<path>`、タブは`#history`のような`#<tab>`、項目は`#markers`のような`#<measure>`、順位の一覧は`#list`で表します。
これらを持つリンクは同じ場所でページを開き、ブラウザの戻るはファイルから一覧へ戻ります。
どの表も見出しの行と最初の列を見える所に保ち、自分の枠の中で横にスクロールします。
10行を超える表は、列の見出しを押すと並べ替わります。
50行を超える表は検索の欄と絞り込みを持ち、見えている行の範囲を示し、50行ずつのページに分けて上と下にページの切り替えを置きます。
変更の集中の表は、変更回数×行数の値の横に、一覧で最も大きい値に対する長さの棒を置きます。
ツールごとに「動いた」「動かしていない」「止まった」のどれかの札をアイコン付きで出し、止まったツールから動いたツールの順に並べます。
動かなかったツールは、何が起きたかと次にすることを報告の文で出します。
どのタブでも、タブの下の節に各値の測り方を出し、走査で試したツールごとに、使い道と、札と結果を表で出します。
幅が600px以下の画面では、これらの表を名前と値の並びで出します。

- `design-formats`のプラグインの`page-design`のスキルが入っていれば、エージェントはその形式`structure`と`look`、ページの型`report`を読みます。`musubi.json`はこれらに任意の準拠で従います。仕上がった`report.html`には`page-design`の`verify`を回します。ほかのプラグインからはこれ以外を読みません
- `musubi`のコマンドが入っていれば、エージェントはこれらを読む前に`musubi check`を回し、失敗したら止まります。`design-formats`が入っていない時、`musubi check`は警告を出してこれらの準拠を飛ばします。従うコンテンツが変わると、フィンガープリントを確かめ直すまで`musubi check`は`techdebt`を拒否します
- `page-design`が無ければ、`templates/base.html`だけで報告を作ります。プラグインのどこも`design-formats`を求めません

## 残す物

調べたフォルダごとに3つのファイルを`~/.local/share/techdebt/<フォルダ名>-<ハッシュ>/`に置きます。`TECHDEBT_HOME`を設定している時はその下です。
このフォルダはあなただけが読め、消すまで残ります。

| ファイル | 中身 |
|---|---|
| `scan.json` | すべての項目、順位、調べたフォルダのパス |
| `notes.json` | エージェントの説明 |
| `report.html` | 報告のページ。データはページの中にあり、ネットワークから何も読み込みません。データは調べたフォルダのパスを持たず、ホームフォルダを`~`と書くので、ページを人に渡してもユーザー名は伝わりません |

`scan.json`は形式の版を持ち、今の版は非推奨の呼び出しを足した3です。`explain`と`report`は、別の版のプラグインが書いた`scan.json`を断り、`scan`のやり直しを求めます。読めないデータから報告を作らないためです。

### TODOなどのコメントの行で隠す物

`scan.json`と報告は、TODOなどのコメントの行を200文字まで残します。秘密の値を書いたコメントがあると、その値がこの2つに入り、その行を引いたIssueにも入ります。
そのため行を残す前に、次の文字列を置き換えます。置き換えは200文字に切る前に、行の全体に対して行います。

| 文字列 | 表示 |
|---|---|
| ホームフォルダ | `~` |
| 決まった形の鍵。秘密鍵の見出し、AWSのアクセスキーID、GitHub、GitLab、Slack、Stripe、Google API、npmのトークン、`sk-`で始まる鍵、JSON Web Token | `***` |
| URLの中のユーザー名とパスワード | `https://***@host` |
| `Bearer`か`Basic`の後のトークン | `Bearer ***` |
| `NAME=`の後の8文字以上の値。名前が大文字の時か、key、token、secret、password、sessionのような語を含む時に隠します。`name:`の後は、そのような名前に引用符付きの値か、数字や記号を含む値が続く時に隠します | `NAME=***` |
| 大文字、小文字、数字を含む32文字以上の英数字の並びで、語の平均の長さが4文字未満の物。乱数のトークンはこの形になります。camelCaseの名前は平均が4文字以上なので残ります | `***` |

どれにも当たらない文字列はそのまま残ります。報告の外へTODOなどのコメントの行を引く前に、その行を読んで確かめてください。

## 決してしないこと

- プロジェクトのファイルを書き換える、整形する、消すこと
- パッケージやツールを取り寄せる、入れる、更新すること
- ネットワークにつなぐこと
- コードや履歴をどこかへ送ること
