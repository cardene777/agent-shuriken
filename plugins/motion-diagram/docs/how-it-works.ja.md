# Motion Diagramの仕組み

[English](how-it-works.md) · 日本語

このページは、仕様の確かめ方、部品の並べ方、カードの流れ方、書き出しが動画を描く手順を説明します。
`skills/motion-diagram/scripts/motion_diagram.py`がPythonの標準ライブラリだけで確かめて書き出し、`export.sh`がNode.jsでヘッドレスブラウザを動かし、ffmpegでコマをつなぎます。

## 仕様を確かめる

`check`は仕様を5段で読みます。
最初の3段は一緒に確かめ、順序と数は3段で何も見つからなかった時だけ確かめるため、出す1行ずつがそれだけで誤っている欄を指します。

| 段 | 確かめる事 |
|---|---|
| 欄 | `version`、`lang`、最初の1文と、全ての文字の幅が上限に収まるか |
| 部品 | `id`が重ならず形が正しいか、`kind`が知っている種類か、`count`と`keep`がそれを持てる種類にだけ付いているか |
| 線と境界 | 線が部品を2つ指すか、落とす線が絞り込みか人から置き場へ向かうか、置き場への線が落とす線か、置き場と行き先が何も送らないか、入口が何も受け取らないか、境界の外の部品に触れる線が無いか |
| 順序 | 本線が輪になっていないか、戻る線が前の部品を指すか |
| 数 | 数を持つ仕様で、全ての入口に`count`があり、全ての絞り込みと人に受け取る数を超えない`keep`があり、2つ以上へ送る部品が線の`count`で分けているか |

幅は日中韓の文字を2、ほかの文字を1と数えます。
このため、日本語で12文字の名前と英語で24文字の名前は、ページの上でほぼ同じ幅になります。
`render`も同じ段を通し、1つでも落ちると何も書きません。

## 部品を並べる

部品の列は、その部品に届く本線の一番長い道筋で決まります。
このため、部品は自分にカードを送る全ての部品より後ろに必ず並びます。
戻る線と落とす線は列の計算に入れないため、戻る線を出す部品やカードを落とす部品は、本線が決めた場所から動きません。

| 部品 | 置く場所 |
|---|---|
| 流れを始める入口 | 最初の列 |
| 後ろの部品に合流する入口 | 合流する部品の列の、本線の段の下 |
| 箱、絞り込み、人、行き先 | 一番長い道筋の列の、本線の段 |
| 落とした物の置き場 | 本線の段の下で、そこへ落とす部品の列にまたがる |
| 境界の外の部品 | 絵の下の境界の中で、線を持たない |

本線の段の下で2つの部品が同じ列を使う時は、後の部品を1段下げます。
ページはこの配置を左から右へ流します。
幅が600ピクセルより狭い時か、1列が92ピクセルより狭くなる時は上から下へ流し、本線の段を左の筋にして、その下の部品を右へ移します。

## カードを流す

何千件もある絵でも読めるように、ページが流すカードは最大24枚です。
カードは入口の数の割合で入口ごとに分け、どの入口にも1枚は残し、0.16秒ずつずらして順に出します。
部品から次の部品へ動くのに0.75秒かかります。

絞り込みと人では、カードが先へ進むか置き場へ落ちます。
先へ進むカードを流れ全体に均等に散らすため、落ちる割合は仕様が落とす割合と合います。
人が通したカードには印が付き、戻る線は、その線が出る部品をカードが通るたびに光ります。
部品ごとの数はカードが通るたびに増え、最後のカードが着いた時に仕様の数に届きます。
先へ進む線を持たない部品に着いたカードは、その部品の内側の右上に重なって止まり、アイコンと名前と数にも、縁から出入りする線にもかかりません。

流れにはでたらめな要素がありません。
同じ仕様なら、どのブラウザでも書き出しでも同じ流れになります。
流れが終わると何も動きません。
もう一度流すボタンで最初から流し直し、動きを減らす設定にした人には動かさずに最後の数を見せます。

## ページ

ページは1つのHTMLファイルで、型、データとしての仕様、英語と日本語の画面の言葉の辞書を持ちます。
フォントもスクリプトも画像もネットワークから読み込みません。
色は共通のテーマのファイルのキー (`bg`、`surface`、`ink`、`sub`、`line`、`accent`、`accent-ink`、`accent-soft`、`bar`、`label`)、フォントは`--sans`と`--mono`という名前を持ちます。
このため、`page-design`の`theme`の命令が利用者の色とフォントに差し替えられます。
ページは明るい色と暗い色を自分で持ち、読む人のシステムがどちらかを選び、見出しのボタンで切り替えると選んだ方をブラウザに保ちます。

## 書き出す

`export.sh`はNode.jsを確かめ、仕様を一時フォルダに書き出し、要る物を次の順で探します。

| 要る物 | 出どころ |
|---|---|
| `playwright-core` 1.65.0 | `~/.local/share/motion-diagram/node/`。最初に`npm`でそこへ入れます |
| ffmpeg | `PATH`の`ffmpeg`。無ければ同じ形で入れた`ffmpeg-static` 5.3.0 |
| ブラウザ | `MOTION_DIAGRAM_BROWSER`の道筋、Playwrightのchrome-headless-shell、Google Chrome、Chromium、Microsoft Edge、Braveの順。どれも無ければPlaywrightのヘッドレスブラウザをPlaywrightの置き場に取得します |

`export.mjs`はそのブラウザで、幅1000ピクセル、画素の細かさ2倍でページを開き、手元のファイル以外への通信を全て止めます。
ページは書き出しの形で開き、自分では流れません。
命令が1秒に15コマの時刻をページに尋ねて、そのたびにページの画像を保存し、最後のコマを1秒保ちます。
ffmpegがコマをつないでMP4の動画 (H.264) と、専用の色の表を作った幅960ピクセルのGIFにし、最後のコマをPNGの画像として保存します。
3つのファイルを指定したフォルダへ移し、一時フォルダを消します。
`--width`と`--fps`で幅と1秒のコマ数を変えられます。

## ファイルの置き場

| ファイル | 置き場 |
|---|---|
| 仕様とページ | あなたが指定したフォルダか、材料の隣 |
| `<name>.mp4`、`<name>.gif`、`<name>.png` | `export`に`--out`で渡したフォルダ |
| `playwright-core`と`ffmpeg-static` | `~/.local/share/motion-diagram/node/`か`$MOTION_DIAGRAM_DATA`の`node/`で、あなただけが読めます |
| 取得した時のPlaywrightのヘッドレスブラウザ | Playwright自身の置き場 |
| コマ | 一時フォルダで、`export`が終わると消えます |
