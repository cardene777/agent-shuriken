# Diagram Explainerの仕組み

[English](how-it-works.md) · 日本語

このページには、エージェントが踏む手順、資料に入る物、あなたが見る前に確かめる物、ファイルを置く場所を載せています。
手順は`skills/diagram-explainer/SKILL.md`にあり、そこから指す説明は`skills/diagram-explainer/references/`にあります。

## 手順

| 手順 | 誰が | 何をするか |
|---|---|---|
| 調べる | エージェント | 規格、API、プロトコルの説明では、公式の仕様を読み、版と読んだ日を記録します。あなたの仕組みの説明では、あなたが指したコードと文書を読みます |
| 構成を立てる | エージェント | 読み手が知りたいことを挙げ、ページ、節、節ごとの図を決めます |
| 構成を決める | あなた | 合うまで節や図を直します |
| 書く | エージェント | ページ、節、本文、図、グラフ、表を、JSONで書きます |
| 組む | エージェント | プラグインのスクリプトで、JSONを1つのHTMLファイルにします |
| 確かめる | エージェント | 資料の検査を回し、出た指摘をすべてJSONで直して組み直します |
| 読み直す | エージェント | 数字と単位、図が本文のとおりかを読み直し、すべての節をパソコンの幅とスマホの幅で見ます |
| 直す | あなたとエージェント | 直してほしい所を伝えると、エージェントがJSONを直して資料を組み直します |

## 資料に入る物

| 部分 | 中身 |
|---|---|
| 目次 | 今のページの節を並べます。押した節だけを出します |
| 見出し帯 | 題、話題が2つ以上ある時のページのタブ、「PDFで保存」のボタン、言語の切り替え、明るい色と暗い色の切り替え、使い方を窓で開く`?`のボタンを持ちます。ページのタブは、矢印のキーとHomeとEndで移れます |
| 事実の表 | 最初の題の下に置きます。資料が表す時点と、書いてあれば、従う仕様とその版、出典を読んだ日を示します |
| 節 | 本文と、拡大のボタンを持つ図と、要点の数字、同じ項目を同じ順に持つカード、印と題の付いた枠の注意、題の付いた段落の説明、前と後の比較、題を付けて単位を列の見出しに書いた表、コード、中身を示す名前の下に畳んだ10行以上の生のデータを持ちます |
| スマホの画面 | 今の節の名前と、目次を横から出すボタンの帯を出します。文字を12pxより小さくしないと収まらないグラフと段の並びは、文字の大きさを保って枠の中で横にスクロールし、切れた端を薄くして、下に横にスクロールできることを示す1行を出します |
| 印刷の形 | 見出し帯と目次と拡大のボタンを隠し、畳んだ欄を全部開き、すべての節を明るい色で1枚に1節ずつ順に並べます。「PDFで保存」のボタンで、今のページか全部のページかを選んで刷ります |

図はすべてページの中に描きます。

| 図 | 向く中身 |
|---|---|
| HTMLで描く箱と矢印 | 部品のつながり、流れ、層、受け持ち |
| 時刻の帯 | 開いている時間と、物事が起きる時刻を段ごとに並べます |
| 量の棒 | 上限に対する量と、削る前と後です |
| 数字のグラフ | 2つ以上の数字の大小を比べます |
| 期間の図 | 期間を年の軸に並べます |
| 段の並び | 呼ぶ物、関門、動かす側のように、項目の多い手順を段に並べます |
| 動く図 | 物が入り、関門で一部が落ち、残りが人や行き先へ届く仕組みを、`motion-diagram render`が書いたページで見せます |

動く図は、motion-diagramのプラグインの`motion-diagram render`が書いたページです。`render.py`は内容のJSONから見た位置で名指したそのファイルだけを読み、図の枠にそのまま入れるため、資料は通信をしない1つのファイルのままです。図は節が初めて表示された時に1回流れ、それまでと紙では流れ終えた絵を見せます。枠の高さは絵に合わせ、色は資料の明るい色か暗い色に従います。motion-diagramが無い時は、ほかの図を使います。

グラフは枠の幅で描くので、どの画面の幅でも文字の大きさが変わりません。段の並びは枠の中央に置きます。グラフの線は文字の下を通り、棒は明るい色と暗い色のどちらでも見分けられる濃さを保ちます。

どの図も、説明書きの右に拡大のボタンを持ちます。ボタンか図そのものを押すと、図を2倍の大きさで窓に開き、窓を閉じるとボタンへ戻ります。
枠より広い図と表は、キーボードで移れる名前付きの範囲の中でスクロールし、続く側を薄くします。長い表は、見出しの行と最初の列を見える所に残します。

資料のボタンや見出しの文字は、資料の言語 (英語か日本語) で始まります。

## ひな形と切り替え

`render.py`がスキルのひな形に中身を入れ、`build.py`が`assets/`のスタイルとスクリプトをページへ写します。表のパスは`skills/diagram-explainer/`から見た位置です。

| ファイル | 持つ物 |
|---|---|
| `templates/starter-doc.html` | 資料の枠。見出し帯、事実の表、目次、切り替えと、`build.py`が`assets/`の中身を入れる目印を持ちます |
| `assets/` | どの資料にも写すスタイルとスクリプト。画面の配置と明るい色と暗い色、グラフ、段の並び、印刷の形、切り替えのスクリプトです |
| `assets/ui.json` | 英語と日本語の画面の文字。ここにだけ書きます。`render.py`と`ladder.py`がページを書く時に読み、`build.py`がページへ写し、切り替えがそれを読みます |
| `musubi.json` | musubiでの`page-design/structure`、`page-design/look`、`page-design/document`、`page-design/verify`、`page-design/theme`への任意の準拠。それぞれにバージョンの範囲 (`structure`と`theme`は`^1.0.0`、ほかは`^2.0.0`) と、最後に確かめた時のコンテンツのフィンガープリントと、`"optional": true`を持つ |

資料の見出し帯には、2つの切り替えが並びます。言語の切り替え (English / 日本語) は、目次のボタン、前と次のボタン、「PDFで保存」のメニュー、使い方、グラフの単位のような画面の文字だけを変えます。もう1つは明るい色と暗い色の切り替えです。
資料の本文は書いた言語のままで、印刷はいつも明るい色です。
ページは資料の言語と、システムの明るい色か暗い色かの設定で始まります。読み手が選んだ物は、ブラウザーがローカルストレージに`diagram-explainer-lang`と`diagram-explainer-theme`の名前で覚えます。どこへも送りません。

- `design-formats`のプラグインの`page-design`のスキルが入っていれば、エージェントはその形式`structure`と`look`、ページの型`document`を読みます。`musubi.json`はこれらに任意の準拠で従います。`scripts/check.py`が通った後、仕上がった`<名前>.html`に`page-design`の`verify`を回し、名指された行を`content.json`で直し、`ok`が出るまで組み直して確かめます。ほかのプラグインからはこれ以外を読みません
- `musubi`のコマンドが入っていれば、エージェントはこれらを読む前に`musubi check`を回し、失敗したら止まります。`design-formats`が入っていない時、`musubi check`は警告を出してこれらの準拠を飛ばします。従うコンテンツが変わると、フィンガープリントを確かめ直すまで`musubi check`は`diagram-explainer`を拒否します
- 組んだ後、エージェントは仕上がった`<名前>.html`に`page-design`の`theme --keys light,dark,font.sans,font.mono`を回します。repoの根の`.design-theme.json`か、無ければ`~/.design-theme.json`の色と書体を頁に書き、どちらも無ければ頁を変えません。`assets/doc.css`は基の色を意匠のfileの鍵 (`bg`、`surface`、`ink`、`sub`、`line`、`label`と強調の色) の名前で持ち、ほかの濃淡を`color-mix()`でそこから混ぜるので、濃淡も意匠の色に付いて変わります
- `page-design`が無ければ、`templates/starter-doc.html`と`assets/`だけで資料を組みます。プラグインのどこも`design-formats`を求めません

## あなたが見る前に確かめる物

`scripts/check.py`は、次のすべてが満たされるまで資料を落とします。

- ネットから何も読み込みません。URLから読むスクリプト、スタイルシート、Webフォント、画像を持ちません
- すべての節が図を持つか、図を置かない理由を書いています
- 目次、節の見出し、ページのタブ、ページが食い違いません
- すべての図が説明書きを持ち、1つのページの中で図の番号が飛ばず、重なりません
- 表のすべての行が、見出しの行と同じ数のセルを持ちます
- 畳んだ詳細を開いたまま配らず、題と最初の節の間には導入の文1つと事実の表だけを置きます
- 畳んだ欄はどれも10行以上を持ち、その名前は「詳細」や「もっと見る」だけでなく中身を示します
- 1つの節に注意を3つ以上置きません
- idが重ならず、図の中の参照がすべて解決します
- 用語表で言い換えると決めた語が、本文にも図にも残っていません
- ブラウザーがある時は、いくつかの画面の幅で、読み込みの間にページの高さが動かず、横にはみ出さないことを確かめます

日本語の資料は、同梱の語の一覧でも本文を確かめます。回りくどい言い回し、読み手が知らない語、本文に残った作業の記録、表記の揺れ、見出しの読点、識別子を主語にした比喩の動詞が対象です。
段落と文の長さ、同じ文の繰り返し、図にだけ出てくる名前は数えるだけで、落としません。

## ファイルを置く場所

資料ごとに、作業中のプロジェクトの`docs/explainers/<名前>/`か、あなたが指したフォルダーを持ちます。
フォルダーには、元になる`content.json`、段の並びの定義 (ある時)、用語表 (ある時)、出来上がった`<名前>.html`を置きます。
PDFを頼んだ時は、HTMLファイルの隣に書きます。
ほかの場所には何も残さず、確かめる時の一時ファイルは確かめ終わった時に消します。

## 実行する物とつなぐ先

- あなたが指したコードと文書。公開されている題材では、エージェントのWeb検索とWebページの読み込みを使い、検索には題材、規格、製品、提供元の名前だけを入れます
- 資料を組む時と確かめる時の`python3`
- 崩れを測る時とPDFを作る時の、パソコンに入っているChromium系のブラウザー (Chrome、Chromium、Edge、Brave、PlaywrightのHeadless Shell)。画面に出さずに動かし、使い捨てのプロフィールを使って、終わったら消します。`DIAGRAM_EXPLAINER_BROWSER`で使うブラウザーを選べます

このプラグインは何もインストールせず、書いた資料もネットから何も読み込みません。
