# Mechanism Explainerの仕組み

Mechanism Explainerは、題材を、読み手の問いに順に答える説明資料にします。
材料が1種類で問いが5個以下なら話題を1つにして1つの頁に、問いが6個以上か材料が2種類以上なら話題を2つ以上に分けて全体像の頁と話題ごとの頁にし、頁の上のタブの代わりに3段の横の目次から開きます。
頁はdragonの説明の頁の形のMarkdownで書き、確かめと描画と書き出しはdragonが行い、PDFは手元のブラウザで印刷します。
スキルが持つのは手順と構成案のスクリプトとPDFのスクリプトだけで、図の種類と頁の形はdragonが持ちます。
構成案の頁を作る決まりと、その出典は[outline-design.md](../skills/mechanism-explainer/references/outline-design.md)にあります。

## 手順

| 段 | 起きること | 実行する物 |
|---|---|---|
| 準備を確かめる | エージェントがdragon 0.89.0が動くかを確かめます | `npx -y @cardenelabs/dragon@0.89.0 --version` |
| 構成案を立てる | 題、章、章の中の頁、頁の中の節を、それぞれの要点の1文と共に`outline.json`に書きます。構成案を明るい頁にしてブラウザで開き、承認を受けるまで直します | `scripts/outline.py` |
| 図の案を立てる | 全体像の図と、問いごとに構成案の`####`の見出しの下に置く図1枚 (多くて2枚) を決め、合うまで直します | なし |
| 書く | `layout: guide`と`note: pop`を持つ`<name>.md`と、語を集めた`glossary.md`を書きます | なし |
| 日本語の文を確かめる | 日本語の頁で、japanese-writingが入っている時は、スキルがmusubiで従う`japanese-writing/rules`に照らして文を確かめます | `musubi`コマンドが入っている時は`musubi check` |
| 確かめる | 全ての図の記法の誤りと配置の崩れを確かめ、dragonが出した行を全て直します | `dragon check`と`dragon check --layout` |
| 書き出す | dragonが頁を書き、スクリプトを中に持つ写しも書きます | `dragon export`と`dragon embed` |
| 印刷する | 頁を既定でA3の紙のPDFにします | `scripts/to-pdf.py` |

## 構成案の頁が持つ物

| 部品 | `outline.json`の元 | 見え方 |
|---|---|---|
| 題 | `title`と`point` | 頁の頭の見出しになり、その下に要点が来ます |
| 全体像 | `overview` | 全体像の頁の部分が、見出しと要点の組で白い枠に並びます |
| 章 | 章の`name`と`point` | 行全体で開け閉めする閉じた形で並び、左に印、名前の下に要点が来ます |
| 頁 | 頁の`name`と`point` | 開いた章の中の見出しになり、その下に要点が来ます |
| 節 | 節の`name`と`point` | 淡い面の上で、太字の見出しの下に要点が来ます |
| ボタン | なし | 章の上の1つのボタンで、全ての章を開け閉めします |

頁は明るい表示だけを持ちます。
`scripts/outline.py`は、書き方の決まりに反する構成案を断り、頁を書きません。

| 断る物 | 例 |
|---|---|
| 問いの印がある名前か、番号で始まる名前 | `DNSの仕組みとは？`、`1-1 リゾルバー` |
| 空の要点 | `"point": ""` |
| 2度書いた要点 | 章の要点を、その中の頁の要点に繰り返した物 |
| 箇条書きの印で始まる行 | `- ルートサーバー` |

## 頁が持つ物

| 部品 | 書き方 | 見え方 |
|---|---|---|
| 全体像 | 最初の話題より前の頁の説明に置く`dragon`の囲み | 頁の頭に仕組みの全体の図が出て、その下に話題が読む順に並びます。`link: #<話題のid>`を書いた箱を押すと、その話題の頁が開きます |
| 話題 | `## <話題>` | 横の目次と頁の見出しになります。話題が2つ以上の時は、話題ごとに1つの頁になり、横の目次から開きます |
| 問い | `### <頁の名前> [menu: <短い名前>]` | 頁の中で話題ごとに番号が付く問いになり、横の目次には番号を付けずに短い名前で並び、話題の中で1つの頁になります。開いている間は、横の目次にその問いの見出しが並びます |
| 答え | 見出しのすぐ下の`> <頁の要点>` | 見出しの下の答えになります |
| 見出し | `#### <節の名前>`と、それに続く要点 | 問いの頁を分ける見出しになり、横の目次で問いの下に並び、押すとその見出しへ移ります |
| 図 | 1文、`dragon`の囲み、2〜4文の順で、問いごとに1枚、多くて2枚 | dragonが流れか仕組みを追って描く図の前に見る所が、後に図が示すことが来ます |
| 表とコード | Markdownの表かコードの囲み | 図の要らない値の一覧、記録の欄、コマンドになります |
| 札 | 箱の`note:` | 箱に印が付き、押すとすぐ下に札が開きます |
| 語 | `glossary.md`へのリンク | 下線の付いた語になり、押すと意味の札が開きます |
| 確かめの問い | `<details>`の囲み | 押すと答えが開く問いになります |

## 何がどこで動くか

| 物 | 動く場所 | 繋ぐ先 |
|---|---|---|
| dragon | 手元のマシンで`npx`経由 | 初回に1度だけ、パッケージをnpmのキャッシュへ取るためにnpmのレジストリ |
| `scripts/outline.py` | 手元のマシンでPython 3の標準ライブラリだけ | なし |
| `scripts/to-pdf.py` | 手元のマシンでPython 3の標準ライブラリだけ | なし |
| 印刷するブラウザ | 手元のマシンでheadlessの形と、終わると消す使い捨てのプロファイル | なし。印刷する頁はスクリプトを中に持ちます |

ブラウザは、`MECHANISM_EXPLAINER_BROWSER`が在ればそれを使います。
無ければPlaywrightのheadless shell、それも無ければ入っているGoogle Chrome、Chromium、Microsoft Edge、Braveを使います。
`to-pdf.py`は紙の大きさを足した頁の写しを頁の横に書き、写しを印刷してから消します。

## ファイルの置き場

`outline.json`、`outline.html`、Markdown、`glossary.md`、HTML、ネットに繋がずに開けるHTML、PDFは、作業しているフォルダの`explainer/<name>/`か指定のフォルダに書きます。
プラグインは状態を持たず、npm自身のキャッシュを除いて、そのフォルダの外には何も書きません。
