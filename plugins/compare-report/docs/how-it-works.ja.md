# Compare Reportの仕組み

[English](how-it-works.md) · 日本語

このページには、エージェントが従う手順、レポートに入る物、あなたが読む前に確かめる物、ファイルを置く場所を載せています。
手順の本体は`skills/compare-report/SKILL.md`にあり、そこから参照するページは`skills/compare-report/references/`にあります。

## 手順

| 手順 | 誰が | 何が起きるか |
|---|---|---|
| 候補を挙げる | エージェント | 題材でWebを検索し、10〜15の候補をそれぞれ1行の説明と一緒に挙げます |
| 候補を決める | あなた | 候補を残す、足す、外すを決めます。比べるのはふつう3〜8個です。同じ問いで、表紙に載せる作者名を伝えるか、載せないことを選びます |
| 観点を選ぶ | エージェント | 性能、費用、信頼性、使いやすさ、周りの道具、リスクのように、題材に合う評価の観点を5〜8個示します |
| 観点を決める | あなた | 観点をそのままにするか、直します |
| 調べる | エージェント | 候補ごとに、公式の情報、数値、使っている所、リスクを集め、すべての主張に出典と日付を付けます。Claude Codeでは候補を並べて調べます |
| 書く | エージェント | レポートの型を埋めます |
| 確かめる | エージェント | レポートの確かめを動かして出た所をすべて直し、公平さと食い違いが無いかを読み直します |
| 印刷する | エージェント | 目次に各節のページを載せたPDFを作り、レポートを開きます |
| 直す | あなたとエージェント | 直してほしい所を伝えると、エージェントがHTMLとPDFを直します |

## レポートに入る物

| 節 | 中身 |
|---|---|
| 表紙 | 題名、比べた物、候補と観点と出典の数と調べた日と伝えた時は作者名を載せた事実の表 |
| 要約 | 比べる理由、上位3つの推奨、5〜7個の分かったこと |
| 候補 | 全候補の表と、要約、種類、使う人、強み、弱みを書いた候補ごとのカード。画面ではカードが候補の一覧になり、押した候補の詳細を横に出します |
| 観点ごとの節 | 全候補の点数と判定の根拠を並べた表、数値がある時の棒グラフ、データの出どころの注記 |
| リスク | 深刻な順に並べたリスクごとの深刻さ、和らげる手、判定の根拠と、いちばん大事なリスクを題名にした注意 |
| 順位 | すべての点数と総評を並べた採点表と、第1の推奨、代わりの案、控えの案と、それぞれを選ぶ条件 |
| 出典 | 引いた順に番号を付けたすべての出典と、読んだ日 |

PDFの目次では、各項目を点線でつなぎ、その節が始まるページ番号を添えます。表紙を除く各ページの下にもページ番号を入れます。
ページは表紙を1ページ目として数え、PDFの閲覧ソフトの数え方と揃えます。
HTMLの目次には番号を付けません。

点数はS(とても良い)からD(弱い)までの5段階です。
比べられる数値が無く、ある観点で公平に判定できない候補は、推測せず「採点しない」と書きます。

## データを正しく保つやり方

- 公開されていない数値は「非公開」と書きます
- 計った条件が違う数値は注記し、比べられる物のように1つのグラフへ並べません
- 提供元の主張と第三者の計測は分けて書きます
- すべての主張に、番号を付けた出典を引きます

## あなたが読む前に確かめる物

`scripts/check-report.py`は、次のすべてが満たされるまでレポートを通しません。

- 型の差し込み箇所が残っていない
- ネットから何も読み込まない。URLからスクリプト、スタイルシート、Webフォント、画像を読み込まない
- 要約、候補、リスク、順位、出典の節があって中身が入っており、観点ごとの節が1つ以上ある
- 点数かリスクの段階を含む表には、すべて判定の根拠の列がある
- 点数の文字と段階が合い、リスクの段階が書かれ、棒グラフの幅が0%から100%の間にある
- 出典の節が1つ以上のページへリンクしている
- 表紙の事実の表の候補と観点と出典の数がレポートの中身と合い、調べた日がYYYY-MM-DDの形で書かれ、作者の行は空で隠れているか名前が入っており、空白だけではない
- 候補のカードごとに、英小文字と数字とハイフンでできた別々のキーがあり、候補を名指す表の行はどれもカードのキーを使う
- 注意の題名が「リスク」や「注意」だけでなくリスクそのものを名指し、注意は最初からページにあるので`role="alert"`を持たない
- 描かれていないdragonの図が残っていない。図はどれも`dragon embed`でレポートに描き込まれている

## レポートのページと切り替え

エージェントは、スキルのひな形にレポートを書きます。表のパスは`skills/compare-report/`から見た位置です。

| ファイル | 持つ物 |
|---|---|
| `templates/base.html` | レポートのページ。スタイル、明るい色と暗い色、切り替えと候補の一覧のスクリプトを中に持ちます |
| `musubi.json` | musubiでの`page-design/structure`、`page-design/look`、`page-design/report`、`page-design/verify`、`page-design/theme`への任意の準拠。それぞれにバージョンの範囲 (`^1.0.0`か`^2.0.0`) と、最後に確かめた時のコンテンツのフィンガープリントと、`"optional": true`を持つ |

レポートの表紙の右上には2つの切り替えがあります。
言語の切り替え(English / 日本語)は枠の言葉を変えます。事実の表の見出し、目次の見出し、候補の一覧と詳細のボタン、点数の凡例、候補のカードの見出し、グラフの操作がこれに当たります。
レポートの本文は、書いた言語のままです。
明るい / 暗いは色を変えます。
選ぶまでは色がシステムの設定に従い、選んだ物はブラウザーがローカルストレージに`compare-report-theme`と`compare-report-lang`の名前で覚えます。どこへも送りません。
PDFは切り替えを除き、いつも明るい色で印刷します。

幅が860pxより広い画面では、候補の節の左に候補の一覧を、右に押した候補の詳細を出します。詳細には、その候補の要約、種類と使う人、観点ごとの点数と判定の根拠、リスクが入り、前と次の候補へのリンクが付きます。
押した候補はアドレスに`#item-<キー>`として残るので、ブラウザーの戻るボタンでその候補へ戻れます。`#item-<キー>/full`は詳細だけを出します。
それより狭い画面では一覧と詳細を切り替えて出し、戻るボタンで一覧へ戻ります。
PDFでは候補のカードを順に載せます。

- `design-formats`のプラグインの`page-design`のスキルが入っていれば、エージェントはその形式`structure`と`look`、ページの型`report`を読みます。`musubi.json`はこれらに任意の準拠で従います。`scripts/check-report.py`が通った後、レポートに`page-design`の`verify`を回し、`ok`が出るまで、名指された行を書いた文の中で直します。ほかのプラグインからはこれ以外を読みません
- `report.html`を作った後、エージェントはそれに`page-design`の`theme --keys light,dark,font.sans,font.mono`を回します。repoの根の`.design-theme.json`か、無ければ`~/.design-theme.json`の色と書体をレポートに書き込み、どちらも無ければレポートをそのまま残します。`templates/base.html`は基本の色を意匠のfileの鍵 (`bg`、`surface`、`ink`、`sub`、`line`、`label`とアクセントの色) の名前で持ち、ほかの色 (`--faint`、行の線の`--rule`、`--stripe`、`--selected`) は`color-mix()`で基本の色から混ぜるので、意匠の色に従います。表紙と状態の色と種類の札、文字の大きさと幅と角は自分の値のままです
- `musubi`のコマンドが入っていれば、エージェントはこれらを読む前に`musubi check`を回し、失敗したら止まります。`design-formats`が入っていない時、`musubi check`は警告を出してこれらの準拠を飛ばします。従うコンテンツが変わると、フィンガープリントを確かめ直すまで`musubi check`は`compare-report`を拒否します
- `page-design`が入っていれば、エージェントは棒グラフを`page-design`が使う図の道具のdragonで、動かない図のブロックとしてレポートに描きます。ブロックを`dragon check`で確かめてから`dragon embed`を回し、すべてのブロックをSVGとしてレポートに描き込みます。Node.jsが無い時や`dragon embed`が失敗した時は、ひな形のCSSの棒グラフのままにします
- `page-design`が無ければ、`templates/base.html`だけでレポートを書きます。プラグインのどこも`design-formats`を求めません

## ファイルを置く場所

レポートごとに`~/.local/share/compare-report/<題材>-<日付>/`のフォルダーを作り、`report.html`と`report.pdf`を置きます。
別の場所に置く時は`COMPARE_REPORT_HOME`を設定するか、置くフォルダーをエージェントに伝えます。
フォルダーはあなただけが読め、既にあるレポートは上書きしません。

表紙に載せると伝えた作者名は、同じ場所(`~/.local/share/compare-report/`か`COMPARE_REPORT_HOME`)の`author.txt`に、あなただけが読める形で残します。
空のファイルは、名前を載せないと選んだことを表します。
エージェントは次のレポートで残した答えを最初の案にし、名前を忘れるよう頼むとファイルを消します。
名前はあなたの答えからだけ取り、`git config`、システムのユーザー名、アカウントからは取りません。

## 実行する物と接続する先

- エージェントのWeb検索とWebページの読み込み。検索には、題材と、候補と提供元の名前だけを使います
- レポートを確かめる`python3`
- PDFにするための、既に入っているChromium系のブラウザー(Chrome、Chromium、Edge、Brave)。画面に出さずに動かし、使い捨てのプロフィールは終わったら消します。使うブラウザーは`COMPARE_REPORT_BROWSER`で選べます
- ページ番号を求める`python3`。`scripts/toc-pages.py`が、ブラウザーが1回目のPDFに書いた行き先から各節のページを読み、番号を足したレポートの写し`.print-*.html`をレポートの隣に書きます。写しは印刷した後に消し、各節が同じページのままの時だけ新しいPDFで1回目のPDFを置き換えます。ページが分からない時は、題名だけの1回目のPDFを残し、理由を1行出します
- 棒グラフを確かめて描くための`npx -y @cardenelabs/dragon@<version>`。`page-design`が入っている時だけ使います。`npx`はdragonをnpmのレジストリーからnpmのキャッシュに取ってきます。`<version>`は`page-design`が名指すバージョンです
- レポートを見せるための、macOSの`open`かLinuxの`xdg-open`

このプラグインは何もインストールせず、作るレポートはネットから何も読み込みません。
