# 仕組み

[English](how-it-works.md) · 日本語

このページは、Docs Publishが読む物、書く物、動かす物、残す物と、スクリプトが当てはめる決まりをすべて説明します。
ページを書いて訳すのはエージェントです。スクリプト`skills/docs-publish/scripts/docs_publish.py`は、フォルダを並べ、翻訳の対応表を保ち、結果を確かめます。
スクリプトはPythonの標準ライブラリだけを使い、ドキュメントのフォルダだけを読み書きします。

## 読む物

| 誰が | 読む物 |
|---|---|
| エージェント | あなたのプロジェクトのファイル。README、パッケージの定義ファイル、公開している入口、コマンドのヘルプ、例、テスト、変更履歴、今あるドキュメントです。あなたが同意すれば、`gh`で、プロジェクトのよく議論されたGitHubのIssueの題名、本文、コメントも読みます。同じく同意すれば、あなたが名指した倣うプロジェクトごとに、ドキュメントの目次と5ページまでを、GitHubのリポジトリなら`gh api`で、ほかのサイトならエージェントのWebページを読む道具で読みます。取り入れるのは形だけで、文は取り入れません |
| スクリプト | エージェントが渡す計画、`_translation-map.json`、ドキュメントのフォルダにある言語ごとのフォルダのMarkdownのファイル |

読んだ物はすべてデータとして扱い、指示としては扱いません。

## 計画

エージェントは計画を提案し、`scaffold --dry-run`であなたに見せ、あなたが同意してからフォルダを並べます。
計画はJSONです。

```json
{"project": "Acme Shop",
 "languages": [{"code": "en", "name": "English"}, {"code": "es", "name": "Español"}],
 "concepts": [{"slug": "carts", "title": "Carts"}],
 "api": [{"slug": "createCart", "title": "createCart"}],
 "cookbook": [{"slug": "apply-a-coupon", "title": "Apply a coupon"}]}
```

| 項目 | 決まり |
|---|---|
| `project` | プロジェクトの名前。1行で80文字まで |
| `languages` | 1つ以上の言語で、元の言語が先。`code`は`en`、`ja`、`pt-BR`のような言語タグで、その言語のフォルダの名前になります。`name`はその言語自身での言語の名前で、言語の切り替えに出ます。同じコードは1回だけです |
| `follow` | 任意です。倣ったプロジェクトの並びで、それぞれ`name`(1行で80文字まで)、`url`(`https://`で始まり、空白を含まない)、`adopted`(倣った所。1行で200文字まで)を持ちます。無い時は倣ったプロジェクトが無いとみなし、対応表がこの並びを残します |
| `concepts`、`api`、`cookbook` | それぞれ1ページ以上。`slug`はファイルの名前で、英字か数字で始まり、英字、数字、`.`、`_`、`-`を使い、サブフォルダには`/`を使います。末尾の`.md`は外し、`README`は使えません。`title`は1行で80文字まで |

題名と言語の名前はリンクの文字になるので、`[`と`]`を含められません。
計画に問題がある時、スクリプトは見つけた問題をすべて並べ、何も書かずに2で終わります。

## ページの並び

ドキュメントのフォルダは、`--root`でほかを指定しない限り`docs`です。
言語ごとにコードの名前のフォルダを持ち、同じページを同じパスに置きます。

```text
docs/_translation-map.json
docs/<code>/README.md              目次
docs/<code>/quickstart.md
docs/<code>/concepts/README.md     とconcepts/<slug>.md
docs/<code>/api/README.md          とapi/<slug>.md
docs/<code>/cookbook/README.md     とcookbook/<slug>.md
docs/<code>/faq.md
```

決まった6つのページは常にあります。`concepts/`、`api/`、`cookbook/`の下のページは、計画か`add`から来ます。
対応表の最初の言語が元の言語で、ほかの言語はすべてそこから訳します。
ドキュメントのフォルダのうち言語のフォルダの外にあるファイル(`docs/assets/`に置く共通の画像など)は、対応表に含めず、リンク先としてだけ確かめます。

## 書き始めのページ

`scaffold`は、すべての言語のすべてのページに書き始めのページを書き、最後に対応表を書きます。
ファイルを上書きすることはありません。すでにあるページはそのまま残し、残したと出力します。
`_translation-map.json`がすでにある時は、何も書かずに3で終わります。

元の言語の書き始めのページは、題名、言語の切り替えの行、その部の骨組みを持ち、各節にやることの印を置きます。印は`docs-publish:todo`で始まるHTMLのコメントです。

| ページ | 題名 | 骨組み |
|---|---|---|
| `README.md` | プロジェクトの名前と「documentation」 | 冒頭の段落のための印と、部ごとにそのページへリンクする節 |
| `quickstart.md` | Quickstart | Requirements、Install、First run、ConceptsとCookbookの目次へリンクするNext steps |
| `concepts/README.md`、`api/README.md`、`cookbook/README.md` | Concepts、API reference、Cookbook | 冒頭の段落のための印と、その部で計画したすべてのページへのリンク |
| `concepts/<slug>.md` | 計画から | Why、How it works、Example、Related |
| `api/<slug>.md` | 計画から | Signature、Parameters、Returns、Errors、Example、Related |
| `cookbook/<slug>.md` | 計画から | Before you start、Steps、Check the result、Related |
| `faq.md` | FAQ | 質問の書き方を伝える印が1つ |

Relatedの節は、その部の`README.md`へ戻るリンクを持ちます。
ほかの言語の書き始めのページは、題名、言語の切り替えの行、訳す元のページを示す印を1つ持ちます。
言語の切り替えの行は題名の下にあり、そのページ自身の言語の名前を書き、ほかのすべての言語の同じページへ相対パスでリンクします。たとえば`en/quickstart.md`からは`../es/quickstart.md`です。
言語が1つの時、ページに切り替えの行はありません。

## 翻訳の対応表

`_translation-map.json`は、言語と、ドキュメントが倣うプロジェクトと、ページを読む順に持ちます。

```json
{
  "version": 2,
  "languages": [
    {"code": "en", "name": "English"},
    {"code": "es", "name": "Español"}
  ],
  "follow": [],
  "pages": [
    {"path": "README.md", "source_sha256": {"es": "<sha256 of en/README.md when es/README.md was recorded>"}},
    {"path": "quickstart.md", "source_sha256": {}}
  ]
}
```

`source_sha256`は、翻訳の言語コードごとに、その翻訳を記録した時点の元のページのsha256を持ちます。
空のオブジェクトは、そのページの翻訳をまだ1つも記録していないことを表します。

スクリプトが読むのはバージョン1と2で、ほかのバージョンなら、見つけたバージョンを示して2で終わります。
バージョン2で`follow`を足しました。バージョン1の対応表は倣うプロジェクトが無い物として読み、次に命令が対応表を書く時にバージョン2で書き直します。バージョン1だけを読むスクリプトは、並びを落とさずにバージョン2の対応表を断ります。
`follow`の項目が計画の決まりを破る時も、2で終わります。
ページのパスが並びの外にある時、同じパスが2回ある時、`source_sha256`が知らない言語か元の言語を指す時やsha256の値でない時、決まった6つのページが対応表から消えた時も、2で終わります。
対応表は、ドキュメントのフォルダの一時ファイルに書いてから古いファイルへ名前を変えて置き換えるので、書き込みに失敗しても対応表が半分だけ残ることはありません。失敗した時は一時ファイルを消します。

## コマンド

どのコマンドも`--root <ドキュメントのフォルダ>`を取り、指定しなければ`docs`です。

| コマンド | すること | 終了コード |
|---|---|---|
| `scaffold <plan>` | 計画をファイルから、`-`なら標準入力から読み、書き始めのページと対応表を書きます。`--dry-run`はファイルを並べるだけで何も書きません | 0 書いた、2 計画に問題がある、3 対応表がすでにある |
| `add <path> --title <title>` | `concepts/`、`api/`、`cookbook/`の下にページを1つ、すべての言語と対応表に足します。`.md`が無ければ付けます。すでにあるファイルは残します | 0 足した、2 パスがそれらのフォルダの外にある、決まったページである、すでに対応表にある |
| `drop <path>` | ページを対応表から外し、まだ残っているファイルを並べます。ファイルは消しません | 0 外した、2 決まったページか、対応表に無いページ |
| `translated <path>...` | 各翻訳が今の元のページに合っていると記録します | 0 すべて記録した、1 記録しなかったページがある、2 入力が正しくない |
| `check` | ページを対応表と、ページどうしで確かめます。何も書きません | 0 問題なし、1 問題を並べた、2 対応表を読めない |

`translated`は、`quickstart.md`、`es/quickstart.md`、`docs/es/quickstart.md`のどの形でも受け取ります。
翻訳が2つ以上ある時は、`--lang <code>`で翻訳の言語を指定します。
パスが元の言語を指す時、言語が対応表に無い時、言語が1つしかない時は2で終わります。
対応表に無いページ、元のページか翻訳が無いかUTF-8でないページ、元のページか翻訳にやることの印が残っているページ、見出し、コードブロック、表の行が元のページと違うページは記録せず、それぞれ理由を出力します。
対応表を書くのは、1ページ以上を記録した時だけです。

## 確かめること

`check`は、対応表にあるすべてのページをすべての言語で読み、問題を種類ごとにまとめて1行ずつ並べます。

| 種類 | 決まり |
|---|---|
| `missing` | 対応表のすべてのページが、すべての言語のフォルダにあり、UTF-8である |
| `unmapped` | 言語のフォルダの下にあるすべての`.md`のファイルが対応表にある |
| `todo` | どのページにも、コードブロックの外に`docs-publish:todo`の印が残っていない |
| `content` | 元の言語で、`concepts/`の下の`README.md`以外のすべてのページに`mermaid`のコードブロックがあり、`quickstart.md`と、`api/`と`cookbook/`の下の`README.md`以外のすべてのページに`mermaid`ではないコードブロックがある。やることの印が残るページは飛ばします |
| `structure` | 各翻訳が、元のページと同じ見出しの段を同じ順に、同じ言語のコードブロックを同じ順に、同じ数の表の行を持つ |
| `untranslated` | 各翻訳のsha256が対応表に記録されている |
| `stale` | 記録したsha256が、今の元のページのsha256と同じ |
| `link` | すべての相対リンクが、ディスク上と同じ大文字小文字で、ファイルかフォルダを指す |
| `crosslink` | ほかの言語のフォルダを指すリンクは、その言語の同じページ、つまり言語の切り替えを指す |
| `switch` | すべてのページが、ほかのすべての言語の同じページへリンクしている |
| `orphan` | すべてのページに、その言語の`README.md`からリンクをたどってたどり着ける |

`structure`、`untranslated`、`stale`は、そのページか元のページが無い時、またはやることの印が残る時は飛ばします。
`orphan`は、書き始めのページがまだすべてにリンクしていないので、その言語のどのページにもやることの印が無くなってから確かめます。

出力は、ドキュメントのフォルダ、ページの数、言語を示す行で始まり、問題の数と、確かめたリンクと切れたリンクの数で終わります。

### ページの読み方

- コードブロックは、3つ以上のバッククォートかチルダで始まり(字下げは3つの空白まで)、同じ文字が同じ数以上並び、ほかに何も無い行で終わります。言語の部分にバッククォートを含むバッククォートの行は、コードブロックではありません
- 見出しは、1から6つの`#`で始まり(字下げは3つの空白まで)、空白、タブ、行の終わりが続く行です
- 表の行は、空白以外の最初の文字が`|`の行です
- コードブロックの言語は、最初のバッククォートの後の最初の単語を小文字にした物です。言語の無いブロックはplainと数えます
- コードブロックの中は、見出し、表の行、やることの印、リンクのどれとしても読みません

### リンクの読み方

- インラインのリンクと画像、`[label]: path`のような参照の定義、HTMLのタグの`src`と`href`の属性を、コードブロックの外で、コードスパンを取り除いてから読みます。`[^1]: text`のような脚注はリンクではありません
- 山かっこで囲んだリンク先は山かっこを外して読み、リンク先の後のタイトルは無視します
- 空のリンク先、`#`か`//`で始まるリンク先、`https:`や`mailto:`のようなスキームで始まるリンク先は確かめません
- `/`で始まるリンク先は、意味がドキュメントを配信する場所で変わるので確かめず、最後の要約で数を示します
- 残りは、`#`か`?`より後を取り除き、パーセントエンコードを戻し、リンクを持つページのフォルダから解決します。アンカーは確かめません
- ファイルかフォルダが存在し、パスのどの部分もディスク上と大文字小文字が一致している必要があります。あなたのディスクが区別しなくても、GitHubやほとんどのWebサーバーではリンクが大文字小文字を区別するからです
- たどり着けるかを確かめる時、フォルダへのリンクはその`README.md`へのリンクと数えます

## 動かす物とつなぐ先

- スクリプトはほかのプログラムを動かさず、どこにもつなぎません
- エージェントは`python3`でスクリプトを動かします。プロジェクトのQuickstartとCookbookのコマンドは、新しく何もインストールせずに動く時だけ、本当の出力を見せるために動かします。何かをインストールする前には尋ねます
- あなたが同意すれば、エージェントはプロジェクトに対して`gh issue list`と`gh issue view`を動かします。あなた自身の`gh`のサインインで、リポジトリの名前をGitHubに送ります
- あなたが同意すれば、エージェントはあなたが名指した倣うプロジェクトのドキュメントを読みます。GitHubのリポジトリなら`gh api`で、あなた自身の`gh`のサインインでその名前をGitHubに送り、ほかのサイトならエージェントのWebページを読む道具で、そのサイトにページを求めます。道具が無いエージェントでは、そのプロジェクトを飛ばしてあなたに伝えます。ほかには何もどこへも送りません

## 残す物

- ドキュメントのフォルダのページと`_translation-map.json`。消すまで残ります
- プロジェクトの外には何も残しません。設定、キャッシュ、状態を置くフォルダはありません
- 一時ファイルは残しません。対応表を書く時の一時ファイル1つは、名前を変えて置き換えるか、消します
- 何もコミット、プッシュ、公開しません。新しいファイルはあなたが見直してコミットします
