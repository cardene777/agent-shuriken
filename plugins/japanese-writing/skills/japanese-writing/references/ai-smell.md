# AI 臭さの 3 つの形

この file は手元で書いた。 上流には無い。

AI 臭い文章を分析した発表 (2026 年 9 月) と、読みやすさの技 `yomiyasu` (MIT) の README と解説記事の論点を、上流と重ならない所だけ手元の言葉で書いた。
例文は手元で作った。

## 3 つの形と、どこが扱っているか

AI 臭さは語の選び方より、文の組み立てから来る。
組み立ての崩れ方は 3 つに分けられる。

| # | 形 | 読み手に起きること | 扱っている所 |
|---|---|---|---|
| 1 | 対比・否定・留保から入り、主文を直接書かない | 打ち消された側を一度思い浮かべてから本題に戻る | 上流の本文の「2. 書くときの原則」の原則1 (前置き) / 原則9 (打ち消し) / 原則10 (語尾のぼかし) と、「打ち消しは、中身のあるものだけを残す」の節。 反復は `lint.py` の `antithesis_repetition` |
| 2 | 抽象語と比喩の動詞で、何をするかを言わない | 実際の操作を自分で訳す | 手元の `subject-and-verb.md`。 行ごとの疑いは `suspects.py` |
| 3 | 短文・対句・不自然な読点・名詞化で、中身以上に見せる | 印象だけが残り、手順や理由が残らない | 上流の本文の「演出の言葉は、削るだけで外す」の節と原則6 (太字)。 密度は `lint.py` の `high_bold_density` ほか。 上流に無い分は下の節 |

## 指摘する時は形と語を名指す

「AI っぽい」 だけで返さない。
3 つの形のどれに当たるか、どの語か、読み手に何が起きるかを書く。
直しの返し方 (`references/rules.md` の §7) の〔理由〕 にも形の名前を入れる。

**意味が取れない文は推測で直さない**。
「この文の『揃える』 は、値を同じにすることか、順番を合わせることか」 のように書き手へ聞く。
推測で直すと、書き手が言っていない意味を足すことになる (§ 意味を足さない)。

## 語を置き換えても組み立ては直らない

指摘された語を同じ意味の別の語に替えると、組み立ての崩れが残る。
「解像度を上げる」 を「粒度を上げる」 に替えても、何をどこまで細かくするかは書かれないままになる。

直すのは文の組み立てで、誰が・何を・どうするかを書き直す。
用語表に語を足しても組み立ては変わらないので、語の一覧を増やして直したことにしない。

## サ変名詞で止めた文を動詞に戻す

名詞を「の」 でつなぎ、最後をサ変名詞 (「する」 を付けて動詞になる名詞) で止めた文は、誰が何をするのかを読み手が組み立て直すことになる。

| 元 | 直した形 |
|---|---|
| 設定値の検証処理の追加。 | 読み込んだ設定値を検証する処理を足す。 |
| 障害発生時の連絡経路の明確化。 | 障害が起きた時に、誰が誰へ連絡するかを決めておく。 |

直す手順は 3 つ。

1. 各サ変名詞に隠れている動詞を出す (検証 → 検証する、明確化 → 決める)
2. その動詞の動作主と対象を、前後の文から持ってくる
3. 名詞のまま残す語を選ぶ (分野の用語として定着している語は残す)

**見出しと表のセルと箇条書きの項目名は対象外**。
短く名指すことが役割の場所で、地の文の決まりを当てると読みにくくなる。

上流は C2 で「サ変名詞化そのものの検出は未実装で、目視で判断する」 としている。
`suspects.py` は地の文で「。」 の直前がサ変名詞の文を指す。
「の」 の連鎖そのものは `lint.py --reading-load` の `no_chain` が指すので、`suspects.py` は数えない。

## 文長のばらつきを決め台詞で作らない

`lint.py` の `low_sentence_variance` は文長が揃いすぎた時に出る。
上流の `lint.py` もこの指摘に、リズムのためだけに短い文を差し込まない直し方を添える。
機械的に当てると「ここが勝負所だ。」 のような、情報を持たない短い断定が差し込まれる。
それ自体が新しい AI 臭さになる。

ばらつきは、文の中身から作る。

| やること | 例 |
|---|---|
| 原因を共有する 2 文をつなぐ | 「設定が古い。 そのため検査が落ちる。」 → 「設定が古いため、検査が落ちる。」 |
| 2 つの主張を持つ文を割る | 理由と手順を 1 文に詰めた文を、理由の文と手順の文に分ける |

**事実を運ぶ短い文は残してよい**。
「3 件とも失敗した。」 は短くても情報を持つ。
`suspects.py` の「短い断定」 は、数字も識別子も含まない短い文を指すので、指された文が事実を運んでいるかで判断する。

## 意味を足さない

動作主を戻す時も、比喩を操作に替える時も、**材料は原文と前後の文から取る**。
原文に無い動作主や仕様を足すと、読みやすくなった代わりに誤った文になる。

`設定が静かに上書きされる` を直す時、何が上書きするのかが前後に書かれていなければ、「配布の処理が上書きする」 と書かない。
書き手に聞くか、「どの処理が上書きするかは書かれていない」 と〔理由〕 に残す。

免責の一文や一般論も足さない (上流の本文の「どの文書でもしないこと」)。
原文の数値と制約は落とさない。

## 数値の目安と手元の決まり

外部の技が示す目安と、手元でどれが優先するかを並べる。
目安は読み手の負担を見積もる材料で、合わせにいく目標にしない (上流の本文の「2. 書くときの原則」の、長さだけを理由に文を削らない決まり)。

| 目安 | 値 | 手元での扱い |
|---|---|---|
| 1 文の長さ | 平均 30-45 字 | 上流 B1 は 40-60 字を目安とし、絶対の閾値にしない。 主体を明示して長くなった文を戻さない |
| 1 文の読点 | 0-2 個 | 上流 B4 (読点の位置) で目視する |
| 太字 | 1000 字あたり 2 個以下 | `lint.py` の `high_bold_density` が数える |
| 箇条書き | 行の 15% 以下 | `lint.py` の `high_bullet_ratio` が数える。 表は箇条書きに数えない |
| 絵文字 | 使わない | `lint.py` の `high_emoji_symbol_density` が数える |
| 文末のコロン | 使わない | `suspects.py` が指す。 「ラベルとコロンの 2 項の列挙」 も `references/rules.md` の §2 で書かない |
| 日本語と英数字の間の空白 | 入れない | 使う repo に決まりがあればそちらに従う |

## 技の本文も同じ基準で書く

指示を受けて書く側は、指示の文体に寄る。
技の本文が比喩の動詞で書かれていると、直した文章にも比喩の動詞が残る。

本技の手書きの file は、地の文に `suspects.py` の比喩の動詞と比喩の副詞が 0 件であることを検査で確かめる。
例として載せる比喩は backtick か code block に入れる (`suspects.py` は数えない)。
