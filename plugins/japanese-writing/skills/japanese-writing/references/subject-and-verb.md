# 主語と動詞

この file は手元で書いた。 上流には無い。

技術の文章でいちばん読みにくくなるのは、**物が主語に立って比喩で動く文**。
語を 1 つも知らなくても読めるのに、誰が何をするのかが取り出せない。

機械が指せるのは疑いまでなので (§ 機械が見る範囲)、直すかは読んで判断する。

## 何が起きるか

2 つが重なった時に読めなくなる。

| # | 形 | 読み手に起きること |
|---|---|---|
| 1 | 非生物が主語に立つ | 動作主を自分で補うことになる |
| 2 | 操作を比喩の動詞で言う | 何が起きるのかを自分で訳すことになる |

重なった文は必ず直す。
片方だけなら既定では残し、比喩の動詞が操作を隠している時だけ直す (§ 片方だけの文)。

重なった例を 1 つ。

```
shared/ は 2 つの置き場の隣に立ち、技の実体を預かる。
```

`shared/` は dir なので `立つ` ことはできず、`預かる` 相手も居ない。
読み手は「実体を 1 つだけ置いてある」 まで自分で訳す。

直した形。

```
どちらの置き場からも使う技は shared/ に実体を 1 つだけ置き、2 つの置き場がそこへ繋ぎを張る。
```

主語が `技` と `置き場` に変わり、動詞が `置く` と `張る` になった。
意味は 1 つも変えていない。

## 直す順番

**主語から直す**。 動詞だけ替えると文がねじれる。

1. その文で実際に動くのは誰かを決める (人 / 処理 / 書き手 / 読み手)
2. 決めた主語に合う動詞へ替える
3. 替えた動詞が実際の操作を名指しているかを見る

動作主が文の中に居ない時は、**節の外から連れてくる**。
説明資料で多いのは「配る処理」「取り込みの処理」「検査」 のような、図の箱に既に名前が付いているもの。
図と同じ呼び名を使えば、本文と図のつなぎ目も揃う。

**連れてくる先が前後の文にも無い時は、動作主を作らない**。
書き手に聞くか、書かれていないことを〔理由〕 に残す (`references/ai-smell.md` § 意味を足さない)。

動作主が本当に存在しない時 (状態の記述) は、**存在の文に替える**。

| 元 | 後 |
|---|---|
| `my-config` は 2 つの置き場を持ち | この repo には 2 つの置き場があり |
| この構成は 3 通りの経路を許す | 経路は 3 通りある |

## 働きかけは 3 つに書き分ける

仕様書や案内で受け身を使うと、誰に何を求めているのかが消える。
`導入が推奨されます` は、誰が推奨し、誰が導入するのかを書いていない。

文が読み手に何を求めるかで、文末を 3 つに分ける。

| 種類 | 文末 | 元 | 直した形 |
|---|---|---|---|
| 依頼 (読み手にしてほしい) | 〜してください | 事前の承認が推奨されます | 実行する前に、承認を取ってください |
| 機能 (読み手ができる) | 〜できます | 設定画面からの変更が可能となっています | 設定画面から変更できます |
| 方針 (書き手の側で決めた) | 〜する / 〜にする | 古い記録は削除されます | 古い記録は、片付けの処理が 30 日後に消す |

3 行目の「30 日後」 と「片付けの処理」 は、原文か前後の文に書いてある時だけ書く。
無ければ書き手に聞く。

`suspects.py` は `推奨されます` のような働きかけの受け身を指す。

## 指示語を名詞に戻す

`これ` / `両者` / `片方` / `前者` のような指示語は、前の文を読んでいないと意味が取れない。
PR 本文や要約に 1 文だけ引かれた時に、その文が単独で読めるかを見る。

| 元 | 直した形 |
|---|---|
| 両者の差分を見る | repo の設定と、配備した先の設定の差分を見る |
| これが重要 | 設定の読み込み順が重要 |

上流は B7 (こそあど言葉の指示先不明) で指示語の頻度を数える検出を検証し、撤回している (質の低い人の文章でも拾えなかった)。
そのため `suspects.py` も指示語は数えず、目で見る。

## 直し方の対応表

左は比喩、右は操作。 **そのまま置き換える表ではない**。
同じ比喩が別の操作を指すことがあるので、実際に何が起きるかを見て選ぶ。

| 比喩 | 種類 | よく指している操作 |
|---|---|---|
| `立つ` / `立ち上がる` | 擬人 | 置く / 作る / 起動する |
| `預かる` / `面倒を見る` | 擬人 | 持つ / 保存する / 実体がそこに在る |
| `見張る` / `眠る` | 擬人 | 検査する / 使われていない |
| `迷う` / `困る` / `嫌がる` | 擬人 | 判定できない / 失敗する / 受け付けない |
| `覚える` / `忘れる` | 擬人 | 記録する / 記録が消える |
| `知っている` / `話す` | 擬人 | 参照できる / やり取りする |
| `踏み込む` / `引き返す` | 擬人 | 実行する / 中断する |
| `黙る` / `沈黙する` | 擬人 | 出力しない / 検知しない |
| `効く` / `効かない` | 操作 | 判定に入る / 判定に入らない / 期待した結果が出る |
| `倒す` / `潰す` | 操作 | 既定値にする / 1 つの値にまとめる / 除外する |
| `壊れる` | 操作 | 落ちる / 誤った結果を返す / 不整合が起きる |
| `溶かす` | 操作 | 時間を要する / 減らす |
| `着地させる` | 操作 | 完了させる / 合意する |

種類は 2 つある。
`擬人` は物が主語の時だけ比喩になる語で、人が主語なら普通の文になる (`読み手が知っている語`)。
`操作` は人が主語でも、実際の操作を言い換えて隠す語になる (`バグを潰す` は何をしたかを言っていない)。

**比喩を全部禁じるのではない**。
分野で定着した言い方 (`安全側へ倒す` / `待ち受ける`) はそのまま使う。
`倒す` で残すのは `安全側へ倒す` だけで、`残さない側に倒す` や `共通側に倒す` は `除外する` や `共通部品に寄せる` のように操作で書く。

対応表の語は `references/metaphor-words.tsv` にも同じ種類で載っており、検査が両者の一致を確かめる。
語を足す時は両方に足す。

## 比喩の副詞

動詞は操作を名指していても、副詞が比喩だと何が起きたかが消える。

| 比喩 | よく指している中身 |
|---|---|
| `静かに` | 記録を残さずに / error を出さずに / 誰も気付かないまま |
| `地味に` | 少しずつ / 目立たない所で |
| `ひっそり` | 告知せずに |

`黙って` も同じ働きをするが、人が主語なら普通の文になる (`黙って待つ`) ので、対応表の `黙る` と同じ `擬人` に入れる。

```
設定の差分が静かに増えていく。
```

何が「静か」 なのかが書かれていない。
差分を検査が見ていないのか、記録はあるが誰も読んでいないのかで、直す所が変わる。

```
設定の差分は検査の対象に入っていないため、差分が増えても誰も気付かない。
```

## 英語の直訳から来る形

比喩の動詞と副詞の多くは、英語の動詞をそのまま訳した形から来る。

| 英語 | 直訳 | 英語の側で言っていたこと |
|---|---|---|
| `fails silently` | `静かに失敗する` | error を出さずに失敗する |
| `X works for Y` | `X が Y に効く` | X を使うと Y が期待どおりに動く |
| `X breaks` | `X が壊れる` | X が落ちる / X が誤った値を返す |

直す時は、英語で何を言っていたかを思い出すと操作の語が見つかる。
上流の本文の「読み手が何のことか分からない言い回しは、ふだんの言葉に戻す」の 4 つ目 (英語の言い方の逐語訳) は英語の構文が透ける形を扱い、ここは動詞と副詞の語の選び方を扱う。

## 片方だけの文

人や処理が主語で、動詞だけが比喩の文は、既定では残す。
主語が文の中に居るので、読み手は誰が動くかを補わずに済む。

ただし、比喩の動詞が操作を隠している時は直す。

| 元 | 直した形 | 何が隠れていたか |
|---|---|---|
| `調査に時間を溶かした` | 原因の特定に 2 日を要した | かかった時間 |
| `判断できないものは残さない側に倒す` | 採否を判断できない項目は除外する | 除外という操作 |

残すか直すかは、動詞を操作の語に替えた時に読み手が新しく知ることがあるかで決める。
新しく知ることが無ければ残す。

## 残してよい形

| 形 | 例 | なぜ残すか |
|---|---|---|
| 物が主語 + 比喩でない動詞 | `この表が判定の根拠を持つ` | 動作主を補う必要が無い |
| 人や処理が主語 + 操作を隠さない比喩の動詞 | `判定を安全側へ倒す` | 動作主が文の中に居て、操作も読める |
| 分野で定着した言い方 | `待ち受ける` / `口を開ける` | 置き換えると別の概念になる |
| 実装の文字をそのまま見せる所 | error の本文 / 画面の文字 | 書き換えると実装が出していない文字になる |

4 つ目は資料で特に起きやすい。
動いている画面の文字を「読みやすく」 直すと、資料だけが実装と食い違う。

## 機械が見る範囲

比喩の語の一覧は `references/metaphor-words.tsv` の 1 つだけで、`scripts/suspects.py` がここを読む。

| script | 見る文章 | 指す条件 | 出し方 |
|---|---|---|---|
| 本技の `scripts/suspects.py` | 文章全般 (Markdown と平文) | `操作` の動詞と比喩の副詞は、地の文に出れば主語を問わずに指す。 `擬人` の動詞は、backtick で囲んだ識別子の直後に `は` か `が` が来る文だけを指す | 行ごとの疑い。 合否を出さない |

一覧は語の前後の文字で外す形も持つ。
`お握り` / `氷を溶かす` / `卒倒` / `主導権を握る` のように、比喩でない使い方を拾わないためで、語だけで当てると人が書いた文章でも大半が当たる。

**取り逃がす形を知っておく**。 件数が 0 でも「無い」 とは読めない。

| 取り逃がす形 | 例 |
|---|---|
| 一覧に無い比喩 | 一覧は実物に当てて足してきた語だけを持つ |
| 主語だけの問題 (動詞は比喩でない) | `この構成は 3 通りの経路を許す` |
| `擬人` の語で、主語が backtick の外 | `my-config は 2 つの置き場の隣に立ち` |

実測で、資料 2 本の同じ段落に取り逃がした文が 3 件あった
(検出器が指したのは 4 文のうち 1 文だけだった)。
**指された文を直す回に、同じ段落の残りも読んで当て直す**。

## 上流の材料を使う

上流が置いた 2 つの見本が、この観点の練習に使える。

| file | 中身 |
|---|---|
| `scripts/fixtures/ai-smelly.md` | 機械が書いたような日本語の見本 |
| `scripts/fixtures/natural.md` | 人が書いた日本語の見本 |

どちらも閾値を校正する実験の入力だったもので、呼ぶ script は手元に残していない。
読む材料として残してある。
