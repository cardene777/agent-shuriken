# Learning to Skillの仕組み

[English](how-it-works.md) · 日本語

このページでは、プラグインが読むファイル、それぞれのファイルを読むエージェントの数え方、似た行の見つけ方、変更の書き方を説明します。
ここに書いたことは全部`skills/learning-to-skill/scripts/learning_to_skill.py`が行い、Pythonの標準ライブラリだけを使います。
ほかのプログラムは動かさず、ネットワークも使わず、自分用のファイルも残しません。

## コマンド

| コマンド | すること | 書く物 |
|---|---|---|
| `files` | 指示のファイル、それぞれを読むエージェント、繰り返している行、大きさの目安を超えたファイルを並べます | 何も書きません |
| `check --text <line>` | 決まりと同じことを書いた行や、近い行を並べます | 何も書きません |
| `propose --file <file> --text <line>` | 変更の差分と、その変更の指紋を出します | 何も書きません |
| `apply ... --expect <fingerprint>` | 変更がまだその指紋のままの時だけ、変更を書きます | 名前を示した1つのファイル |

## どのファイルを読むか

プロジェクトは、今いるフォルダかその上で`.git`を持つ最も近いフォルダか、`--root`で渡したフォルダです。
上のどのフォルダにも`.git`が無い時は、今いるフォルダをプロジェクトとします。

プロジェクトの中を8段の深さまで探し、次のフォルダは飛ばします。

| 飛ばす物 | 理由 |
|---|---|
| `node_modules`、`vendor`、`dist`、`build`、`out`、`target`、`venv`、`env`、`__pycache__`、`coverage`、`bower_components`、`Pods`、`DerivedData` | 依存パッケージとビルドの出力だからです |
| `.claude`、`.github`、`.gemini`、`.agents`のほかの隠しフォルダ | エージェントの指示を持たないからです |
| 自分の`.git`を持つフォルダ | 別のリポジトリ、サブモジュール、worktreeで、それぞれに指示があるからです |
| フォルダへのシンボリックリンク | プロジェクトの外へつながることがあるからです。エージェントのスキル用フォルダに置いたスキルへのリンクは例外です |

次のファイルを集め、次のエージェントを読み手として数えます。
これは、このリリースの時点で分かっている、各エージェントが読む場所です。エージェントは読む場所を少しずつ増やしています。

| ファイル | 読むエージェント |
|---|---|
| 各フォルダの`AGENTS.md` | CodexとGitHub Copilot CLIです。プロジェクトに`CLAUDE.md`という名前のファイルが1つも無い時は、最近のClaude Codeも読みます。Gemini CLIは、設定が`AGENTS.md`を挙げている時に読みます |
| 各フォルダの`AGENTS.override.md` | Codexです。同じフォルダの`AGENTS.md`の代わりに読みます |
| 各フォルダの`CLAUDE.md`と`.claude/CLAUDE.md` | Claude Codeです。プロジェクトの一番上の`CLAUDE.md`はGitHub Copilot CLIも読みます |
| `CLAUDE.local.md` | Claude Codeです。個人用で、普通はコミットしません |
| 各フォルダの`GEMINI.md`か、設定が挙げた名前 | Gemini CLIです。プロジェクトの一番上の`GEMINI.md`はGitHub Copilot CLIも読みます |
| `.github/copilot-instructions.md` | GitHub Copilot CLIです |
| `.github/instructions/**/*.instructions.md` | GitHub Copilot CLIです。`applyTo`が挙げたファイルにだけ当てはまります |
| `.claude/rules/**/*.md` | Claude Codeです。先頭の設定に`paths`か`applyTo`がある時は、`paths`が挙げたファイルにだけ当てはまります |
| `SKILL.md` | 置かれたスキル用フォルダのエージェントで、次の表のとおりです。それ以外の場所の`SKILL.md`は、プロジェクトが配っているスキルのように、どのエージェントも読み込まない物として並べます |

下のフォルダにあるファイルはそのフォルダでの作業にだけ当てはまり、一覧にもそう書きます。

| スキル用フォルダ | 読むエージェント |
|---|---|
| `.claude/skills/<skill>/SKILL.md` | Claude CodeとGitHub Copilot CLI |
| `.agents/skills/<skill>/SKILL.md` | Codex、Gemini CLI、GitHub Copilot CLI |
| `.github/skills/<skill>/SKILL.md` | GitHub Copilot CLI |
| `.gemini/skills/<skill>/SKILL.md` | Gemini CLI |

これらのフォルダのスキルは、ほかの場所のフォルダへのシンボリックリンクでも見つけます。一覧には、各スキルのフォルダにあるほかの`.md`ファイルの数も出します。

### リンク、読み込み、設定

| 対象 | 読み方 |
|---|---|
| シンボリックリンクのファイル | リンクを読むエージェントは、リンク先のファイルを読みます。`through the link <file>`と表示し、エージェントごとの一覧にはリンク先のファイルを出します |
| Claude CodeかGemini CLIが読む、`SKILL.md`ではないファイルの中の`@<path>` | `@`が行の頭か空白の後にあり、コードブロックとインラインコードの外にあり、パスが実在するファイルを指す時、同じエージェントがそのファイルも読みます。`imported by <file>`と表示します。パスはファイルのフォルダからの相対パス、絶対パス、`~/`で始まるパスのどれかです。読み込みは5段までたどります |
| `.gemini/settings.json` | `context.fileName`が名前1つか名前の並びの時、Gemini CLIは`GEMINI.md`の代わりにその名前のファイルを読みます |

### ホームフォルダ

`--home`を付けると、次のファイルも読み、次のフォルダにあるスキルも並べます。どれもすべてのプロジェクトで読まれます。
`--home`が無い時にホームフォルダのファイルを読むのは、プロジェクトのファイルが`@~/...`で読み込んでいる時と、そのファイルを`propose`か`apply`に渡した時だけです。

| ファイル | 読むエージェント |
|---|---|
| `~/.claude/CLAUDE.md`と`~/.claude/rules/**/*.md`。`CLAUDE_CONFIG_DIR`があればその下の同じファイル | Claude Code |
| `~/.codex/AGENTS.override.md`。無ければ`~/.codex/AGENTS.md`。`CODEX_HOME`があればその下の同じファイル | Codex |
| `~/.gemini/GEMINI.md`か、`~/.gemini/settings.json`が挙げた名前 | Gemini CLI |
| `~/.copilot/copilot-instructions.md` | GitHub Copilot CLI |
| `~/.claude/skills/<skill>/SKILL.md` | Claude CodeとGitHub Copilot CLI |
| `~/.codex/skills/<skill>/SKILL.md` | Codex |
| `~/.agents/skills/<skill>/SKILL.md` | Codex、Gemini CLI、GitHub Copilot CLI |
| `~/.gemini/skills/<skill>/SKILL.md` | Gemini CLI |
| `~/.copilot/skills/<skill>/SKILL.md` | GitHub Copilot CLI |

## 一覧に出る物

| 部分 | 作り方 |
|---|---|
| ファイルごとの行 | 行数、読むエージェント、`for work in web/`、`imports AGENTS.md`、`link to AGENTS.md`のような注記です |
| エージェントごとの、毎回の会話で読むファイル | 各エージェントが毎回の会話で読むファイルです。プロジェクトの一番上にあって、一部のファイルだけに限られないファイルと、`--home`を付けた時のホームフォルダのファイルです。名前で読むファイルを先に出します。何も読まないエージェントには、読むはずのファイルの名前を出します |
| 最も多くのエージェントに届くファイル | そのプロジェクトの一番上のファイルのうち、読むエージェントが最も多い物です。同じ数の時は先に並んだ物です |
| 繰り返している行 | 次の節のとおりに整えた後に12文字以上残り、ファイルをまたいで2回以上か、1つのファイルの中で2回出る行です。20件まで出します |
| 大きさの目安を超えたファイル | 200行を超えるファイル(`SKILL.md`は500行)と、プロジェクトの一番上から下へCodexが読む`AGENTS.md`の合計が32 KiBを超えるフォルダです。32 KiBは、Codexが既定で読む量(`project_doc_max_bytes`)です |

## 似た行の見つけ方

比べるのは文の行だけで、見出し、コードブロック、YAMLの先頭の設定、表の区切りの行は比べません。
それぞれの行は、箇条書きの印とチェックボックスを外し、英字を小文字にし、記号を空白に変え、続いた空白を1つにまとめてから比べます。

| 点数 | 当てはまる時 |
|---|---|
| `same` | 整えた行どうしが同じ時です |
| 0.90以上 | 整えた短い方の行が12文字以上あり、もう一方に含まれる時です |
| 0から0.99 | それ以外の時で、空白を除いた隣り合う2文字の組のDice係数です。日本語のように単語の間に空白が無い文も比べられます |

0.50以上を似た行と数え(`check --threshold`で変えられます)、高い順に5件出します。
点数は共通の文字を測っているだけで意味は測っていないため、エージェントは出た行を全部読みます。

## 変更の置き方

`propose`と`apply`が変えるのは、次のファイルだけです。

- プロジェクトの中のファイルか、`~/.claude`(または`CLAUDE_CONFIG_DIR`)、`~/.codex`(または`CODEX_HOME`)、`~/.gemini`、`~/.copilot`、`~/.agents`の中のファイル
- 名前が`AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md`、`CLAUDE.local.md`、`GEMINI.md`、`copilot-instructions.md`、`SKILL.md`、`.gemini/settings.json`が挙げた名前のどれかか、`.instructions.md`で終わるファイル
- または`.claude/rules/`の下の`.md`ファイルか、`SKILL.md`を持つフォルダとその4段下までのフォルダにある`.md`ファイル

名前は、渡したパスと、リンクが指すファイルの両方で確かめます。
UTF-8の文書でないファイルは、そのままにします。
整えた形がファイルの中の行と同じになる行は断り、同じ決まりを2回足しません。

| オプション | 行を置く場所 |
|---|---|
| `--section <heading>` | その節の、空でない最後の行の後です。節は、`#`の数が同じか少ない次の見出しで終わります |
| `--new-section <heading>` | ファイルの最後に新しい見出しを置き、その後に行を置きます。見出しの`#`の数はファイルの一番上の見出しと同じで、2つ以上にします |
| `--after-line <n>` | n行目のすぐ後に、渡したとおりに置きます |
| `--replace-line <n>` | n行目の代わりに、渡したとおりに置きます |
| どれも無い時 | 先頭の設定より下の、空でない最後の行の後です |

`--section`とファイルの最後に置く時は、箇条書きの後に続く箇条書きはその箇条書きにつなげ、それ以外は前に空行を1つ入れます。
空のファイルでは、渡した行からファイルが始まります。
次の行が空でない時は、置いた行の後に空行を1つ入れます。
見出しは大文字と小文字、`#`、記号を区別せずに照らし合わせ、コードブロックとYAMLの先頭の設定の中の見出しは節と見なしません。
2つの節が同じ見出しを持つ時は断り、違う節に書くことを防ぎます。

ファイルの改行はそのままにします。CRLFが1つでもあればCRLF、無ければLFです。
最後の改行は元のファイルに合わせ、新しいファイルと空のファイルには付けます。バイト順マークも残します。

## 変更の書き方

`propose`は指紋を出します。ファイルの実際のパス、今の中身、変更後の中身のSHA-256の、先頭16桁の16進数です。
`apply`は同じ引数と`--expect`を受け取り、今のファイルからもう一度変更を組み立て、指紋が同じ時だけ書きます。
ファイルの中身、行、置く場所のどれかが違えば指紋も変わり、何も書きません。

| 段階 | すること |
|---|---|
| 1 | 新しいファイルでは、無いフォルダを作り、ファイルには`umask`が許す権限を付けます |
| 2 | 新しい中身を、同じフォルダの`.learning-to-skill-*`という名前の一時ファイルに書き、元のファイルの権限を付けます |
| 3 | 元のファイルをもう一度読み、指紋を確かめた後に変わっていたら、一時ファイルを消して何も書きません |
| 4 | 一時ファイルで、実際のファイルを一度に置き換えます。渡したパスがリンクの時は、リンク先のファイルを置き換え、リンクはそのまま残ります |
| 5 | ファイルを読み直し、新しい中身と同じかを確かめます |

書くのに失敗した時は、一時ファイルを消します。

## 残す物

何も残しません。
書くのは変更を承認した指示のファイルだけで、一時ファイルは書いている間しかありません。

## しないこと

- gitやほかのプログラムを動かさず、コミットもプッシュもしません
- `propose`の指紋が無い時と、その後にファイルが変わった時は書きません
- 指示のファイルではないファイルと、プロジェクトとホームフォルダのエージェント用フォルダの外にあるファイルは変えません
- ネットワークには何も送りません

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 終わりました |
| 1 | `check`が似た行を見つけたか、`propose`と`apply`が変更を断りました。行がもうファイルにある、節が無い、2つの節が同じ見出しを持つ、のどれかです |
| 2 | 入力の誤りです。指示のファイルではない、`--create`無しで無いファイルを渡した、`--text`の中に改行がある、などです |
| 3 | `apply`が、ファイルか変更が提案と違うことに気付き、何も書きませんでした |

## 環境変数

| 変数 | 用途 |
|---|---|
| `CLAUDE_CONFIG_DIR` | `~/.claude`の代わりに使うClaude Codeのフォルダです。`--home`と、変えてよいファイルの判断に使います |
| `CODEX_HOME` | `~/.codex`の代わりに使うCodexのフォルダです。使い道は同じです |
