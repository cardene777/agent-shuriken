# Portmanの仕組み

[English](how-it-works.md) · 日本語

このページでは、台帳の置き場所、ポートの試し方、ポートの持ち主の見分け方、提案するポート、`apply`が書く物を説明します。
ここに書いたことは全部`skills/portman/scripts/portman.py`が行います。Pythonの標準ライブラリだけを使い、`lsof`、`docker`、`git`は入っている時に使います。

## 台帳

台帳は1つのJSONファイルです。

```json
{
  "version": 1,
  "projects": {
    "shop": {
      "ports": [
        {"name": "web", "port": 3101},
        {"name": "db", "port": 5433, "service": "postgres", "target": 5432}
      ],
      "dir": "/path/to/shop"
    }
  }
}
```

| 項目 | 意味 |
|---|---|
| `version` | ファイルの形式です。この版は`1`だけを読み、ほかの版は終了コード2で断ります。ファイルは変えません |
| `name` | ポートの用途です。大文字にして`-`を`_`に変えた`PORT_<NAME>`という変数になります |
| `port` | このマシンでのポートです。1から65535までです |
| `service`、`target` | ポートを公開するComposeのサービスと、そのコンテナの中のポートです。`--service`と`--target`を渡した時に入ります |
| `dir` | プロジェクトのフォルダです。`add --dir`で渡すか、`apply`が記録します。ポートを使っているプロセスがプロジェクトの中で動いているかを見分けるのに使います |

置き場所は`~/.local/share/portman/registry.json`で、`PORTMAN_HOME`があればその下です。
フォルダはモード700、ファイルはモード600で作り、あなただけが読めるようにします。
変更はすべて、同じフォルダの`registry.lock`のロックを取った上で行い、ファイルは1回で置き換えます。そのため、2つの実行が重なっても変更は失われません。
ポートを文字列で書いたなど、項目の型が違う台帳は、直す項目の一覧とともに終了コード2で断ります。

| コマンド | 読む物 | 変える物 |
|---|---|---|
| `list`、`check`、`suggest`、`doctor` | 台帳と、使われているポート | 何も変えません |
| `add` | 台帳と、使われているポート | 項目を1つ足し、`--dir`を渡した時はプロジェクトのフォルダも記録します |
| `remove` | 台帳 | 確認画面では何も変えません。`--confirm`を付けると、まだ一致する項目を外します |
| `apply` | 台帳と、プロジェクトの`.env.local`とComposeのファイル | 確認画面では何も変えません。`--confirm`を付けると、プロジェクトのファイルを書き、プロジェクトのフォルダを記録します |

`add`は、登録済みのポート、プロジェクトに既にある名前、`web-ui`と`web_ui`のようにほかの名前と同じ変数になる名前を断ります。
よく使われる既定のポート、1024未満のポート、今使われているポートは、断らずに注意を出します。

## ポートの試し方

待ち受け中のTCPポートは、実行ごとに1回、次のうち最初に使える物から読みます。

| 出どころ | コマンド | 分かること |
|---|---|---|
| `lsof` | `lsof +c 0 -nP -iTCP -sTCP:LISTEN -Fpcn` | ポート、プロセスID、プログラム名です。管理者の権限が無いと、あなた自身のプログラムだけが見えます |
| `/proc/net/tcp`と`tcp6` | `lsof`の無いLinuxで、ファイルとして読みます | ポートだけです。プログラムは名前を出せない物として表示します |

`docker`が入っている時は、`docker ps --format '{{json .}}'`で、動いているコンテナが公開しているポートを足します。コンテナの名前と、ラベルにあるComposeのプロジェクトとフォルダも取ります。
コンテナがポートを使っている時は、Dockerのためにそのポートを転送するプログラム(`com.docker.backend`、`vpnkit`、`docker-proxy`、`rootlessport`、`gvproxy`)を並べて表示しません。
`docker`が入っているのに応答しない時は`doctor`がそう伝え、ほかの出どころはそのまま使います。

どれにも出てこないポートは直接試します。`127.0.0.1`と`::1`で接続を試し、次に`0.0.0.0`と`::`でbindを試します。
接続できた時か、アドレスが使用中のためにbindできなかった時に、使われていると判断します。
これらのソケットはこのマシンの中だけで開いてすぐ閉じ、データは送りません。
こうして、ほかのユーザーが動かすプログラムのように`lsof`から見えない物も見つけ、「a program that could not be named」と表示します。

## ポートの持ち主

登録したポートが使われている時は、使っている物をプロジェクトと比べます。

| 使っている物 | このプロジェクト | ほかのプログラム | はっきりしない |
|---|---|---|---|
| コンテナ | Composeのプロジェクト名が、Composeの形(小文字、英数字、`-`、`_`)にしたプロジェクト名と同じか、Composeのフォルダがプロジェクトのフォルダの中にある | ほかのComposeプロジェクトの物 | Composeのラベルが無い |
| プロセス | `lsof -a -p <pid> -d cwd -Fn`で読む作業フォルダが、プロジェクトのフォルダの中にある | 作業フォルダがほかの場所にある | プロジェクトのフォルダが記録されていないか、作業フォルダを読めない |
| 名前を出せない物 | | | 常に |

`list`は、使っている物の後に`(this project)`か`(another program)`を付け、はっきりしない時は何も付けません。
`doctor`は「ほかのプログラム」だけを衝突として数え、はっきりしない物は別に並べます。そのため、プロジェクト自身の開発サーバーを問題として報告することはありません。

## 空きポート

`suggest`は`--from`(既定は3000、1024未満にはしません)から数え上げ、すべての確かめを通るポートを`--count`個(既定は5、最大50)返します。

- どのプロジェクトにも登録されていない
- [ポートの試し方](#ポートの試し方)の確かめで、使われていない
- `--allow-common`を付けない限り、よく使われる道具が既定で取るポートではない
- 32767以下。macOSとLinuxが一時的なポートに使う範囲より下です

飛ばす既定のポートは、1433(SQL Server)、3000と3001(Node.js、React、Next.js、Rails、Grafanaの開発サーバー)、3306(MySQL)、4000(Phoenix、Jekyll、GraphQLの開発サーバー)、4200(Angular)、4321(Astro)、5000と7000(Flask、macOSのAirPlayレシーバー)、5173と5174(Vite)、5432(PostgreSQL)、5672(RabbitMQ)、6006(Storybook)、6379(Redis)、8000(Django、uvicorn、Pythonの`http.server`)、8008と8080と8443(HTTPとHTTPSの代わりのサーバー)、8081(React Nativeのバンドラー)、8888(Jupyter)、9000(PHP-FPM、SonarQube、MinIO)、9200(Elasticsearch)、9229(Node.jsのインスペクター)、11211(Memcached)、27017(MongoDB)です。
`check`もこれらの既定のポートを示します。
`doctor`は同じ確かめを使って、衝突ごとに空きポートを提案します。取られたポートから数え上げ、1回の実行で同じポートを2回提案することはありません。

## doctorが報告する物

| 行か節 | 中身 |
|---|---|
| `Registry` | 台帳のファイルと、プロジェクトとポートの数です |
| `Permissions` | 台帳のフォルダかファイルをほかの人が読める時に、直すための`chmod`のコマンドとともに出します。問題として数えます |
| `Listeners` | ポートを`lsof`で読んだか、`/proc/net`から読んだか、どちらも使えなかったかです |
| `Docker` | 動いている、入っているが応答しない、入っていない、のどれかです |
| `[Duplicates]` | 2回登録されたポート、プロジェクトの中で重なった名前、同じ変数になる名前です。問題として数えます |
| `[Collisions]` | ほかのプログラムが使っている登録済みのポートと、移す先の空きポートです。問題として数えます |
| `[In use, owner unclear]` | 使われているが、持ち主を見分けられない登録済みのポートです |
| `[In use by its own project]` | プロジェクト自身のプロセスかコンテナが使っている登録済みのポートです |
| `[Folders gone]` | 記録したフォルダが無くなったプロジェクトの登録済みのポートと、消すためのコマンドです。消したgit worktreeがこれに当たります。ある時だけ出し、問題として数えます |
| `[Unregistered]` | `lsof`、`/proc/net`、`docker`に出てくる1024から32767までのポートのうち、登録されていない物です。`lsof`も`/proc/net`も読めない時は、`none`ではなく`unknown`と出します |

最後の行が問題の数です。
`doctor`は問題が見つかっても見つからなくても終了コード0で終わります。見つけた物は出力に書きます。

## applyが書く物

`apply`は1つのプロジェクトのフォルダを対象にします。`--dir`か、今いるgitのリポジトリの一番上のフォルダか、今のフォルダです。
プロジェクトは`--project`か、記録したフォルダがそのフォルダであるプロジェクトか、フォルダの名前です。

### .env.local

スクリプトは`.env.local`を自分のプロセスの中で読み、自分が管理する行と行番号だけを出します。
管理するのは`# >>> portman >>>`から`# <<< portman <<<`までの行です。

```
# >>> portman >>>
PORT=3101
PORT_WEB=3101
PORT_DB=5433
# <<< portman <<<
```

`PORT`は`app`という名前のポートで、`app`が無い時はプロジェクトの最初のポートです。続いて、登録した順にポートごとの`PORT_<NAME>`を書きます。
ファイルにこのブロックがある時は、ブロックだけを置き換えます。
無い時は、空行を1つ挟んでファイルの最後に足し、ファイルの最後の行に改行が無ければ改行を足します。
ほかの行は1バイトも変えません。
ブロックの外の行が同じ変数を設定している時は、確認画面がその行番号を示し、その行はそのまま残します。
開始の行だけで終わりの行が無い時や、ブロックが2つ以上ある時は、`apply`は終了コード1で止まり、何も変えません。

### Composeのoverride

フォルダに`compose.yaml`、`compose.yml`、`docker-compose.yml`、`docker-compose.yaml`のどれか(この順で最初に見つかった物)がある時は、`apply`がそのサービスを読み、同じ名前に`.override`を付けたoverride(例えば`docker-compose.override.yml`)を書きます。

スクリプトはYAMLのライブラリを使わずに、Composeのファイルのよくある形を読みます。一番上の`services:`、サービスごとに1つのキー、各サービスの`ports:`です。`ports:`は、短い書き方(`"3000:3000"`、`"127.0.0.1:3000:3000"`、`"${WEB_PORT:-3000}:3000"`)、1行の書き方(`["3000:3000"]`)、長い書き方(`target`、`published`、`host_ip`、`protocol`、`mode`、`name`、`app_protocol`)を読みます。
アンカー、`<<`による結合、`extends`、ポートの範囲、タブ、そのほか読めない形を使うサービスはoverrideに入れず、手で直すよう確認画面で伝えます。

| 段階 | 決まり |
|---|---|
| どのサービスか | 項目の`service`か、項目と同じ名前のサービスです。どちらも無ければ、そのポートは`.env.local`にだけ書きます |
| コンテナのどのポートか | 項目の`target`か、サービスが公開している唯一のTCPポートです。公開しているポートが複数か0個の時は、`--target`を付けて登録し直すよう確認画面で伝えます |
| サービスの各ポート | コンテナ側のポートが登録した項目の物である対応は、ホスト側のポートを登録したポートに変えます。ホストのアドレスとプロトコルは残します。ほかの対応はそのまま残します |
| サービスがまだ公開していない登録済みのポート | `"<port>:<target>"`として足します |
| 置き換えるか足すか | Composeはoverrideのポートを元のファイルのポートに足すため、古いホスト側のポートが使われたまま残ります。サービスに既にポートがある時は、overrideに`ports: !override`と書いて置き換えます |

`!override`にはDocker Compose 2.24以降が要ります。
`docker`が入っている時は、`apply`が`docker compose version --short`を実行し、古い版なら注意を出します。

overrideの1行目は`# Written by portman from its registry. portman apply rewrites this file.`です。
overrideのファイルがあってこの1行目で始まっていない時や、フォルダにほかの名前のoverrideが既にある時は、`apply`は書かず、手で足す行を出します。

### 承認

`--confirm`が無い時、`apply`は変わる行だけの差分を前後の行を付けずに出し、合わせてトークンを出します。トークンは、フォルダ、プロジェクト、各ファイルの今の中身と新しい中身から計算したSHA-256の先頭12文字です。
`--confirm <トークン>`を付けると、台帳のロックを取り、台帳とファイルを読み直し、変更を計画し直し、トークンが同じ時だけ書きます。
その間に台帳かファイルが変わっていた時は、終了コード3で終わり、何も書きません。

ファイルは1回で置き換え、権限はそのまま残します。新しいファイルはあなただけが読めるように作ります。
書いた後、`apply`はプロジェクトのフォルダを台帳に記録し、`PORT`のアドレスを出します。
書いたファイルがgitの無視の対象になっていない時は、`git check-ignore`の結果をもとに、`.gitignore`に足すよう確認画面で伝えます。

## ポートを外す

`remove <project> [<name>...]`は、各項目を`project/name=port`の形で出し、何も変えません。
`remove --confirm <project>/<name>=<port>`は、台帳にその名前がまだそのポートである時だけ項目を外します。
無くなった項目や別のポートになった項目は理由を付けて飛ばし、コマンドは終了コード3で終わります。
最後のポートを外したプロジェクトは台帳から消えます。

## 残す物

| 何を | どこに | いつまで |
|---|---|---|
| 台帳 | `~/.local/share/portman/registry.json`。モード600で、モード700のフォルダに置きます。`PORTMAN_HOME`があればその下です | 項目を外すか、ファイルを消すまで |
| 空のロックファイル | 台帳の隣の`registry.lock`。モード600です | フォルダを消すまで |

プロジェクトの中では、`.env.local`とComposeのoverrideだけを、あなたの承認の後に書きます。
一時ファイルは置き換える対象のファイルの隣に作り、その名前に変えます。書くのに失敗した時は消します。

## しないこと

- プログラムやコンテナを止める、再起動する、変えること
- `.env.local`のブロックの外の行を出すこと
- `.env.local`のブロックの外の行や、自分が書いていないoverrideを変えること
- ネットワークに何かを送ること。ソケットの確かめはこのマシンの中だけで行い、`docker`は手元のDockerのデーモンとやり取りします
- `lsof`、`docker ps`、`docker compose version`、`git rev-parse --show-toplevel`、`git check-ignore`のほかを動かすこと

## 環境変数

| 変数 | 用途 |
|---|---|
| `PORTMAN_HOME` | 台帳を置く場所 |
| `PORTMAN_LSOF` | 検査で`lsof`の代わりに使う命令 |
| `PORTMAN_DOCKER` | 検査で`docker`の代わりに使う命令 |
| `PORTMAN_PROC_NET` | 検査で`/proc/net`の代わりに読むフォルダ |
| `PORTMAN_NO_PROBE` | `1`にすると、検査のためにソケットでの確かめを止めます |

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 終わりました |
| 1 | 頼んだ物について何も登録されていないか、登録済みのポートのように頼みを断りました |
| 2 | 入力が正しくないか、台帳を読めません |
| 3 | 確認画面の後に項目かファイルが変わったため、飛ばしたか何も書きませんでした |
