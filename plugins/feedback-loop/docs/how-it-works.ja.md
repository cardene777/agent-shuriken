# Feedback Loopの仕組み

[English](how-it-works.md) · 日本語

このページでは、記録を置く場所、各コマンドの働き、レビューの読み方、訂正を閉じる前にスクリプトが確かめる条件を全部説明します。
記録と検査は`skills/feedback-loop/scripts/feedback_loop.py`が受け持ち、Pythonの標準ライブラリと`git`だけを使います。
ユーザーが何を訂正したかを決めることやファイルを直すことのように判断が要る部分は、`SKILL.md`に沿ってエージェントが行います。

## ループ

| 手順 | 誰が | コマンド |
|---|---|---|
| リポジトリと記録の場所を見つける | スクリプト | `where --repo <ファイル>` |
| 訂正を記録する | エージェント。ユーザーの文を標準入力で渡します | `open` |
| どこまで当てはまるかを決める | エージェント | `classify <id> <範囲>` |
| 学んだことを残す | ルールはエージェントが書き、検査の文字列はスクリプトが持ちます | `case`、`rule` |
| ファイルを直す | エージェント | なし |
| ファイルを検査する | スクリプトが検査の文字列とエージェントの命令を動かします | `check <id> -- <命令>` |
| 直した内容をレビューする | 何も編集しない評価者が判定し、スクリプトがその答えを読みます | `status <id>`が評価者向けの説明を出し、`review <id>`が答えを保存します |
| 閉じる | 下の条件が全部そろった時にスクリプト | `close <id>` |

レビューが不合格なら、エージェントは直す手順に戻ります。
`status`をidなしで動かすと開いている訂正と各訂正の次の手順を並べ、`history`は閉じた訂正を並べ、`extend`は回数を増やし、`drop`はユーザーが取り下げた訂正を閉じます。

## どのリポジトリか

リポジトリは、訂正したファイルを含むgitの作業ツリーです。`--repo`に渡したパスから`git rev-parse --show-toplevel`で見つけます。
`--artifact`で渡すファイルは、その中にあり、`.git`の中ではなく、フォルダでもない物に限ります。`..`やシンボリックリンクを通して外へ出るパスは断ります。
gitのリポジトリの外では、スクリプトは何も記録せずに終了コード2で終わり、エージェントはその回だけの訂正として出力を直します。

## 記録を置く場所

| 選び方 | フォルダ | 権限 |
|---|---|---|
| 既定 | `~/.local/share/feedback-loop/repos/<リポジトリ>-<ハッシュ>/`。`FEEDBACK_LOOP_HOME`があればその下です。`<ハッシュ>`は、元のクローンのパスのSHA-256の先頭12桁です | フォルダもファイルもあなただけが読めます(700と600) |
| `where --use <フォルダ>`で選んだリポジトリの中のフォルダ | `<リポジトリ>/<フォルダ>/` | 普段どおりの権限です。コミットして共有できます |

リンクしたworktreeは、`git rev-parse --git-common-dir`で見つけた元のクローンの既定のフォルダを共有します。
`--use`で選んだフォルダは、使っている作業ツリーのルートからの位置です。
選んだ場所は既定のフォルダの`store`というファイルに残し、`where --private`がそれを消します。既に書いた記録は元の場所に残ります。

| 記録のフォルダのファイル | 中身 |
|---|---|
| `pending/<id>.json` | 開いている訂正1件 |
| `events.jsonl` | 閉じた訂正か取り下げた訂正1件につき1行です。閉じた時刻を加えた記録の全体です |
| `rules.md` | リポジトリのルールで、エージェントが書きます。スクリプトは見出しだけを付けて作ります |
| `cases/<ファイル>-<ハッシュ>.json` | 訂正したファイル1つ分の検査の文字列 |
| `reviews/<id>-<回>.md` | 回ごとの評価者の答えを、保存したとおりに残した物 |

末尾に行を足すだけの`events.jsonl`を除き、どのファイルも同じフォルダの一時ファイルに書いてから名前を変えて置くため、書きかけの状態を読まれることはありません。

## 記録の中身

| 項目 | 中身 |
|---|---|
| `id` | `fb-20330518-001`のような`fb-<日付>-<番号>`です。手元の時刻の日付ごとに番号を振ります |
| `status`、`drop_reason` | 開いている間は`open`、記録の一覧では`resolved`か`dropped`です。`dropped`にはユーザーの理由が付きます |
| `source_sha256` | 前後の空白を除いたユーザーの文のSHA-256です。文そのものは保存しません |
| `target_repository` | リポジトリのルートです。ホームフォルダの下なら`~/...`と書きます |
| `target_artifacts` | 訂正したファイルです。リポジトリのルートからの位置で書きます |
| `origin_skill` | 出力を作ったスキル、または`none`です |
| `feedback_subject`、`expected` | 何を訂正したか、ユーザーが代わりに何を望むかを、エージェントの言葉で書いた物です |
| `scope` | `artifact`、`repository`、`skill`、`global`、`one-off`のどれかです |
| `rule_files` | `rule`で書き留めたルールのファイルです。リポジトリの中ならそこからの位置、ホームフォルダの下なら`~`で始めます |
| `case_files`、`case_removals` | この訂正で変えた検査のファイル(記録のフォルダからの位置)と、取り除いた項目です |
| `opened_at`、`opened_artifacts`、`closed_at` | 開いた時刻、その時のファイルのハッシュ、閉じた時刻です |
| `verification.runs` | 検査ごとの時刻、訂正したファイルそれぞれのSHA-256(無ければ`missing`)、命令と終了コードです |
| `loop` | モード、回数の上限、基準、回ごとの記録(ファイルのハッシュ、評価者、その種類、判定、指摘、レビューのファイルとSHA-256)です |

記録には`"version": 1`が入っています。スクリプトは、版の違う開いた記録と検査のファイルを推測で読まずに断ります。

## 訂正を開く

`open`はユーザーの文を標準入力から読み、空なら止まります。
同じハッシュの訂正が既に開いていれば、`Already open as <id>`と出して何も足しません。
同じハッシュの訂正が前に閉じられていた時や、同じファイルへの訂正が前にあった時は、それを名指しします。繰り返したということは、前に学んだことが効かなかったということだからです。

どの訂正にも2つの基準があります。`user-feedback`(訂正が解消した)と`regression`(前から当てはまっていたルールと検査の文字列が守られている)です。
`--criterion <id>=<文>`で基準を足せます。idは小文字の英字、数字、`-`で40文字までとし、1回だけ使えます。
`--max-iterations`は、エージェントがユーザーに尋ねるまでの回数で、既定は3、1から10までです。

## 検査の文字列(case)

検査の文字列は、1つのファイルについて、含めてはいけない文字列、含めるべき文字列、評価者への問いを並べた物です。項目ごとに、それを足した訂正のidが付きます。
`check`は、ファイルをUTF-8として読み、大文字と小文字も区別して、文字列がそのまま含まれるかを照らし合わせます。
存在しないファイルは何も含まないと見なします。含めてはいけない文字列は通り、含めるべき文字列は通りません。
JSONとして正しくないか、決まった形になっていない検査のファイルは、飛ばさずに、`check`、`status`、`close`をそのパスとともに終了コード2で止めます。

## 検査

`check <id> -- <命令>`は、まず訂正したファイルの検査の文字列を照らし合わせ、次に命令をリポジトリのルートで動かします。時間の上限は600秒で、`--timeout`で変えられます。
命令の出力は端末に出るだけで、保存しません。
見つからない命令は終了コード127、時間の上限で止めた命令は124として数えます。

検査は、動かした時のファイルそのものに対してだけ数えます。
今のファイルについては命令ごとに最新の結果を使います。同じ命令が後で通れば前の失敗は置き換わり、どれか1つでも失敗していればレビューに進めません。

## レビュー

`status <id>`は、評価者向けの説明を出します。ファイル、基準、検査の文字列の結果と問い、ルールのファイル、今のファイルに対する検査、前の回の指摘、答えの書き方です。
答えには、基準ごとにちょうど1行を書きます。

```text
- user-feedback: PASS - the jargon is gone
- regression: PASS - the case checks hold
- plain: FAIL - step 1 does not say which command sets up the environment
```

行頭の`-`、`*`、`+`、idを囲むバッククォート、判定を囲む太字は書いてもかまいません。`PASS`と`FAIL`は大文字でも小文字でも読みます。
`review`は、基準の行が欠けている答えと、1つの基準に2行ある答えを、回を記録せずに断ります。
今のファイルを覆う通った検査が無い間もレビューを断ります。評価者がファイルを編集した場合も、これで見つかります。

| `--kind` | 使う時 |
|---|---|
| `independent_llm` | 別のエージェントか、読むだけの別のレビュー |
| `human` | ユーザー自身の判定 |
| `deterministic` | 検査だけで全部決まる`deterministic`モードの時だけ |

`independent-review`と`hybrid`のモードでは、種類が`deterministic`のレビューを断ります。
答えはSHA-256とともに`reviews/<id>-<回>.md`に保存し、その時のファイルのハッシュとともに回を記録します。

## 回数の上限

許された最後の回でレビューが不合格だと終了コード3で終わり、訂正は開いたまま残ります。
その後は、`extend --rounds <n>`で回数を足すまで、`--kind human`のレビューだけを受け付けます。
`drop --reason <文>`は、ユーザーが取り下げた訂正を理由とともに`dropped`として閉じます。

## 訂正を閉じられる時

`close`は、満たしていない条件を全部並べて終了コード1で終わるか、訂正を閉じて終了コード0で終わります。

- 範囲が決まっている
- 基準に`user-feedback`と`regression`が入っている
- 回が1つ以上記録され、最後の回が合格している
- 最後の回の後に、訂正したファイルが変わっていない
- 最後の回のレビューのファイルがあり、記録したSHA-256と一致し、基準ごとに`PASS`の行がある
- 最後の回の種類がモードに合っている
- 今のファイルに対する検査の最新の結果が、どれも終了コード0である
- `artifact`なら、ファイルのどれかの検査のファイルに、この訂正の項目がある
- `repository`、`skill`、`global`なら、`rule`で書き留めたルールのファイルが1つ以上あり、どれもまだ存在する

閉じると、記録を`status`が`resolved`、`final_verdict`が`pass`の状態で、最後のファイルのハッシュと検査ごとの最新の結果とともに`events.jsonl`へ移し、`pending/`のファイルを消します。

## 残す物

| 何を | どこに | いつまで |
|---|---|---|
| 開いている訂正、記録の一覧、ルール、検査の文字列、レビュー | 上で説明した記録のフォルダ | 消すまで |
| リポジトリの中のフォルダを選んだ時の、記録を置く場所 | 既定の記録のフォルダの`store` | `where --private`を動かすか、消すまで |

ほかには何も書かず、一時ファイルも残しません。

## しないこと

- 訂正の文を保存しません。残すのはSHA-256のハッシュだけです
- プロジェクトのファイルを変えません。スクリプトが書くのは記録のフォルダだけで、直すのはエージェントです
- `git rev-parse`と、エージェントが`--`の後に渡した検査の命令のほかは動かしません
- 判定を決めません。判定は評価者の答えから読みます
- プロジェクトのエージェント向けの指示、スキル、ユーザー全体の指示ファイルに書きません。書くのはあなたが同意した時のエージェントで、スクリプトはパスを書き留めるだけです
- ネットワークには何も送りません

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 終わった |
| 1 | その手順が通らなかった。検査かレビューが不合格だったか、閉じる条件がそろっていない |
| 2 | 入力の誤り。リポジトリの外のパス、知らないid、読めないレビュー、形の崩れた検査のファイルなど |
| 3 | 許された最後の回が不合格だったか、上限の後に`--kind human`以外のレビューが来た |

## 環境変数

| 変数 | 用途 |
|---|---|
| `FEEDBACK_LOOP_HOME` | 既定の記録のフォルダを置く場所。`~/.local/share/feedback-loop`の代わりに使います |
| `FEEDBACK_LOOP_NOW` | 検査で使う固定の時刻。1970年からの秒数です |
