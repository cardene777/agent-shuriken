# Reference beats

The reference beat library keeps visual reasoning that can be used again, never copied layouts, assets, or branded styles.
Before a reference video may influence a production, record it with the fields below.

| Field | Records |
|---|---|
| Source and time range | The address of the public video and the time range watched |
| Viewer question | The question the shot answers |
| Stage mode | `aperture`, `exchange`, `inspection`, `consequence`, or `handoff`, as in `formats/composition-and-staging.md` |
| Primary and support | The actual order of attention |
| Before, operation, after | The visible causal change |
| Text behavior | Whether a condition, a quantity, an owner, or a result is read beside the object |
| Carry | The object or state that motivates the next shot |
| Transferable trait | The abstract property that may be used again |
| Not transferable | The specific composition, characters, art, brand, or voice that must not be copied |

When no recorded entry is approved, use the abstract patterns below.
A generic "style reference" without a question, a proof, and a handoff is not an entry.
In a beat dossier, cite only the abstract staging property of an approved entry close to the subject.

## Abstract patterns

These patterns of composition are seen across explainer and educational videos that keep their viewers.
They depend on no one's artwork.

### 1. Problem aperture

| Part | Pattern |
|---|---|
| Question | What is visibly wrong or constrained? |
| Staging | One object with a state dominates; the context arrives later |
| Operation | The specific missing, blocked, or limited area is revealed |
| Carry | The constrained object stays and motivates the remedy |
| Reject | A row of a building, a person, and a document under a title |

### 2. Object inspection

| Part | Pattern |
|---|---|
| Question | What is the important condition of this object? |
| Staging | Close attention on one object, with one short annotation beside it |
| Operation | The object is made, opened, marked, or changes state |
| Carry | The changed object becomes something that can be handed over or acted on |
| Reject | Text moves in while an unchanged icon stays still |

### 3. Physical exchange

| Part | Pattern |
|---|---|
| Question | Who gives what to whom? |
| Staging | The source and the destination are apart; the object exchanged owns a clear lane between them |
| Operation | The actual object changes owner or position |
| Carry | Its new owner keeps it while what is given in return begins to move |
| Reject | An arrow plus the same movement of the object; a curved line through faces |

### 4. Consequence replacement

| Part | Pattern |
|---|---|
| Question | What changed because of the operation? |
| Staging | Return to the first anchor, now with a PNG of a distinct state |
| Operation | The result replaces the earlier state at the same place |
| Carry | The result state creates the next condition |
| Reject | The object disappears and a caption claims a result |

### 5. Constraint to time

| Part | Pattern |
|---|---|
| Question | What must happen later, and why? |
| Staging | The current carry object becomes a timeline, a calendar, a record, or a condition without resetting the stage |
| Operation | A feature already seen transforms into the view of time or the record |
| Carry | The transformed feature begins the next beat |
| Reject | A new chapter background, a new title, and an unrelated icon |
