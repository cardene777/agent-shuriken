# しくみ

[English](how-it-works.md) · 日本語

このページは、Skill Tuneが読む物、書く物、実行する物、保つ物と、スクリプトが評価の結果に点を付ける方法を説明します。
エージェントはスキルを読み、評価の案件を書き、削る所を削ります。スクリプト`skills/skill-tune/scripts/skill_tune.py`はプラグインを写し、その写しに対して`claude plugin eval`を走らせ、結果を読みます。
スクリプトはPythonの標準ライブラリだけを使います。

## 読む物

| 誰が | 読む物 |
|---|---|
| エージェント | 指定したプラグイン。その`SKILL.md`、`SKILL.md`が名指すスクリプトとファイル、テスト、`evals/`フォルダです。新しい案件の最初の実行の出力は全部読み、落ちた案件については`trace`が出すツール呼び出しも読みます |
| スクリプト | 語数を数えるための`SKILL.md`、写すためのプラグインのフォルダ、`claude plugin eval`が書くJSONの結果、その結果が指す記録のファイル、プラグインの`evals/labels/`にある合否のファイル |

読んだ物はすべてデータとして扱い、指示としては扱いません。

## データのフォルダ

スクリプトは写しと結果を`$SKILL_TUNE_HOME`に置きます。既定は`~/.local/share/skill-tune`です。
データのフォルダ、`runs/`、写しごとのフォルダ、`results/`はあなただけが開けるので、その中の写しと結果をほかの人は読めません。

```text
~/.local/share/skill-tune/
└── runs/
    └── <plugin>-<label>/          one per copy, such as my-plugin-before
        ├── <plugin>/              the copy, without __pycache__, .DS_Store, and evals/results
        └── results/
            ├── <label>.json       what claude plugin eval wrote with --json
            ├── <label>.log        everything it printed
            └── <label>-out/       its report folder
```

スクリプトが`--keep-temp`を渡すので、`claude plugin eval`は実行ごとのフォルダを、`e-`と6文字以上の英数字の名前でシステムの一時フォルダに残します。
結果のJSONはそのフォルダの中にある各実行の記録を指します。`trace`はそれで落ちた実行を読み、`clean`はそれで消す物を見つけます。

## コマンド

すべてのオプションは`python3 skill_tune.py <command> --help`で見られます。

| コマンド | すること | 終了コード |
|---|---|---|
| `size <SKILL.md>` | 本文の語数と説明文の文字数を出します | 0 出した、2 ファイルを読めないかフロントマターが無い |
| `list <folder>` | フォルダの下にあるすべての`skills/<name>/SKILL.md`を、本文の長い順に、プラグインごとの評価の案件の数とともに表で出します | 0 出した、1 スキルが見つからない |
| `copy <plugin> --label L` | プラグインを`runs/<plugin>-<L>/`に写し、写しのパスを出します。`--replace`は同じラベルの写しを、それと評価がそのために残したフォルダを先に消してから置き換えます。プラグインが評価の報告と同じ名前の`report.html`というfileを持つ時は、`claude plugin eval`がエージェントをプラグインのフォルダに入れなくなるので、標準エラーに注意を出します | 0 写した、2 プラグインのフォルダでない、ラベルが正しくない、写しが既にある |
| `run <copy> --label L [--max-cost-usd U]` | 写しに対して`claude plugin eval`を走らせ、結果、記録、終了コードを出します。`--case`、`--runs`、`--ablation`、`-j`、`--eval-dir`はそのまま渡します。`--eval-dir label-evals`は`label-cases`が書いた案件を走らせます | その終了コード、2 入力が正しくないか、その評価のフォルダが無い、3 `claude`が無い |
| `summary <result>...` | 各案件のプラグインありと無しの点、各判定の通った数、スキルが動いた実行の平均の費用と時間と往復の数、全体の費用と時間を出します | 0 出した、1 案件が無い、2 結果を読めない |
| `compare --before <result>... --after <result>...` | 各案件の変える前と後の点を`kept`、`higher`、`lower`、`not measured`として出し、両側の平均も出します | 0 下がった案件が無い、1 下がった案件がある、2 結果を読めない、3 片側でしか測っていない案件がある |
| `estimate <result>` | 案件ごとに1回走らせた結果から、基準と変えた後の実行の費用を出します。`--runs`は案件ごとの実行の数で、既定は3です | 0 出した、1 プラグインありの実行が無い |
| `trace <result> --case NAME` | 各実行の落ちた判定、入力つきのツール呼び出し、ツールの結果、エージェントの文を出します。`--arm without`はプラグイン無しの実行を読みます | 0 出した、1 その案件が無い |
| `clean <name>`または`clean --all` | 写しのフォルダを1つ、またはすべて、その結果のために`claude plugin eval`が残したフォルダとともに消します。この会話か別の会話の`run`が評価している写しは消さずに残し、そう伝える行を出します | 0 消した、`--all`で残した、または消す物が無い、1 そのフォルダが無いか、名前で指した写しを評価している、2 名前も`--all`も無い |
| `label <result> --case C --grader G --arm A --run N` | その実行で`llm`の判定が読んだ文 (結果の`evidence`) を出し、判定の合否は出しません。`--verdict pass`か`--verdict fail`と`--into <plugin>`を付けると、代わりにあなたの合否と文を合否のファイルに記録します。前に記録した実行はその合否を置き換え、合格と不合格の件数を12件ずつの目標と並べて出します | 0 出したか記録した、2 `llm`でない判定、結果に無い実行、文の残っていない実行、または別の版の合否のファイル |
| `label-cases <copy> --labels <file> --set tune`または`--set held` | 最初の呼び出しで分け方を決め、その分の合否1件につき案件を1つ`<copy>/label-evals/`に書きます。前にあった物は置き換えます。`tune`では例の3件を出します。確かめ済みの取り分けの後の`held`では、新しい合格5件と不合格5件を取り分けます | 0 書いた、2 合格か不合格が12件に届かない、写しに判定が無い、または確かめ済みの取り分けに新しい合否が足りない |
| `agree <result> --labels <file>` | 結果にある分ごとに、人の合格のうち判定も合格にした割合と、人の不合格のうち判定も不合格にした割合を出し、測れなかった案件の数も出します。取り分けた分では、確かめた結果を合否のファイルに記録し、判定を信用するかを出します | 0 出した、1 合否の案件が無いか、取り分けた分で判定を信用しない、2 結果か合否のファイルを読めない |

ラベルには英字、数字、`.`、`_`、`-`を使い、英字か数字で始めます。

## runがclaude plugin evalに渡す物

`run`は写しの親フォルダで`claude plugin eval`を始めるので、同じ名前でインストールしたプラグインではなく写しを測ります。

```bash
claude plugin eval <copy> --scaffold --allow-tools Bash Write Edit --trust-plugin --no-publish \
  --threshold 0 -j 3 --keep-temp [--max-cost-usd <U>] \
  --output-dir results/<L>-out --json results/<L>.json
```

| オプション | 理由 |
|---|---|
| `--scaffold` | 各案件の`fixture.sh`を走らせて始まりの状態を作ります |
| `--allow-tools Bash Write Edit` | 評価のサンドボックスの中で、スキルがふつう必要とするツールをエージェントに使わせます |
| `--trust-plugin` | `fixture.sh`はあなたの権限で走るため、`--scaffold`を守る問いを飛ばします。スキルは、あなたが書いたか信頼するプラグインにだけこれを使います |
| `--no-publish` | 結果をあなたのマシンに留めます |
| `--threshold 0` | 合否を`compare`に任せます。`compare`は各案件を基準と比べて判定します |
| `--keep-temp` | `trace`のために各実行の記録を残します |
| `--max-cost-usd` | あなたが上限を言った時だけ渡します。その額を使い切ると、それ以上の実行を始めません。これで止まった時、`claude plugin eval`は2で終わります |

## 点の付け方

- 結果が点に数えない、または`with-only`と印を付けた判定と、`--indicator`で名指した判定を除き、判定は点に数えます
- 1回の実行の点は、数える判定のうち通った割合です。数える判定の無い実行には点がありません
- 片側での案件の点はその実行の点の平均で、どの実行にも点が無い時は`-`です
- `compare`はプラグインありの実行だけを使うので、両方の側で測った基準と`--ablation none`で測った変えた後の結果を比べられます
- 結果のファイルを複数渡すと、各案件はそれを持つ最後のファイルから取ります。そのため、1つの案件だけを走らせ直すと前の分を置き換えます
- 費用は実行とそのLLMの判定の分を数えます。平均は、`--fired`で名指した判定(既定は`skill-fired`)が通った実行だけを数えます

`estimate`は、案件ごとに1回走らせた費用の平均を足し合わせ、案件ごとの実行の数を掛けます。基準はプラグインありと無しで走るので2倍、変えた後はプラグインありだけで走るので1倍です。
プラグイン無しの実行はプラグインありの実行と同じ費用として数え、走らせ直しの分は含めません。

## 判定の作り方と確かめ方

新しい案件では、エージェントはまず各案件に`skill-fired`の判定だけを付けて1回走らせます。
出力を全部読み、出力ごとに悪い所を1行で書き、それをいくつかの失敗の型にまとめます。失敗の型は、出力について「はい」か「いいえ」で答える問いです。
失敗の型1つが判定1つになります。文や動作で決まる型は`regex`か`tool_used`、読む人が判断するしかない型だけを`llm`にします。

`llm`の判定はどちらの向きにも間違えるので、比べる前に、あなたの付けた合否で確かめます。
あなたは基準の実行から合格12件と不合格12件の出力に合否を付けます。見えるのは判定が読んだ文だけです。
合否のファイル`<plugin>/evals/labels/<case>/<grader>.json`は、版1と、各合否のid、合否、文、分け方と、取り分けた分を確かめた記録を持ちます。

```text
合否24件 ─ 例3件 ───────────────► 判定の文に入れる
         ├ 取り分けた合格5件と不合格5件 ─► 最後に1回だけ確かめる
         └ 残り ─────────────────► 判定を直す。何回でもよい
```

合否の案件は、合否の文を判定が読む場所に置きます。返事を読む判定では`label-text.md`に置きます。そして写しの今の判定で採点するので、本番の案件と同じ判定役で確かめられます。
不合格が少ないと、不合格を全部見逃す判定でも全体の一致は高く見えるため、`agree`は人の合格と人の不合格を分けて数えます。
判定を直す間、エージェントは判定が間違えた合否の説明を読み、見つけた問題を軽いとして通す、表面だけを確かめる、の2つの失敗の型を探します。
判定は、取り分けた合格と不合格のどちらでも5件中4件以上一致した時に信用します。届かない判定は`summary`と`compare`に`--indicator`で渡し、信用できない判定として報告します。
取り分けた分を確かめるのは1回だけです。`label-cases`はそれをもう一度書くのを断り、新しく確かめるには新しい合格5件と不合格5件が要ります。

## 実行する物とつなぐ先

- スクリプトが実行するのは`claude plugin eval`だけで、`run`からだけです。スクリプト自身はどこにもつなぎません
- `claude plugin eval`は、案件の`fixture.sh`をサンドボックスの外であなたの権限で走らせた後、ホームフォルダが一時フォルダのサンドボックスで各案件のエージェントを走らせます
- 各案件の依頼文、プラグイン、実行中にエージェントが読む物を、あなた自身のClaude Codeのサインインを通してAnthropicのモデルへ送り、費用をあなたのアカウントに請求します。`--no-publish`により、結果はどこにも送りません
- エージェントは、案件にあなたが同意した後にだけ`run`を実行し、測る前に費用の見込みを見せます

## 保つ物

- データのフォルダにある写し、結果、記録と、`claude plugin eval`が残した実行のフォルダは、`clean`が消すまで残ります。スキルは終わる時に、自分が作った写しを`clean <name>`で消します。別の会話が自分の写しで測っていることがあるので、`clean --all`は実行しません
- `run`が写しを評価している間は、写しの隣に`run`のプロセスIDを書いたファイル`running`を置き、評価が終わると`run`が消します
- プラグインの`evals/`フォルダにある評価の案件と`SKILL.md`で削った所は、あなたが変えるまで残ります
- プラグインの`evals/labels/`にある合否のファイルは、合否を付けた出力の文とともに残り、`clean`の後も次の確かめに使えます。案件と一緒にコミットします
- `label-cases`が書く案件は写しの`label-evals/`にだけ置かれ、`clean`が写しを消すまで残ります
- 何もコミット、プッシュ、公開しません。変更を見直してから、あなた自身でコミットします
