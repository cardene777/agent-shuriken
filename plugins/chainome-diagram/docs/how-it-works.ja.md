# 仕組み

[English](how-it-works.md) · 日本語

プラグインは技`chainome-diagram`を1つだけ持ち、スクリプトを持ちません。
エージェントは`skills/chainome-diagram/SKILL.md`に従い、図のcodeをあなたのプロジェクトに書きます。

## 場面の型

描く前に、エージェントは小さな型付きの場面の型をプロジェクトに書きます。

| 欄 | 中身 |
|---|---|
| `nodes` | 種類と位置と大きさと短い表示の欄を持つ、登場する人と物 |
| `containers` | 契約の実行の範囲のような境と、その中に在る要素 |
| `steps` | 順に並べた段。題、本文、動く道、動く要素、状態の行を持つ |
| `paths` | 動く点と包みがたどるSVGの道か道の値 |
| `stateByStep` | 各段の後の値。変化は隣の段との差から出す |
| `annotations` | 図に属する短い札。説明の文は置かない |

型は図の中だけで使います。作る人が中身を直す製品でない限り、共通のJSONの型は求めません。

## 画面

図の欄には、登場する人と物、状態、道、動くトークン、強調、一時の札を置きます。
説明の欄は図の下か横に置き、段の文と表を持ちます。
目立たせる段は一度に1つで、動く道と見える欄も1つずつです。
状態の変化は、変わった瞬間に要素の隣へ札で出し、カードは今の値だけを出します。

## 見直しの関門

大きな変更のたびに、エージェントはプロジェクトのPlaywrightでPCとスマートフォンの画面の写しを撮り、次の関門で見ます。

| 関門 | 落ちる時 |
|---|---|
| 仕組みの構造 | 保存領域を契約の外に描くなど、起きない所に振る舞いを描いた |
| 因果 | 文を読まずに、何が入り、何が動き、何が状態を読み書きし、何が出るかが分からない |
| 状態 | 今の状態と変化と最後の状態が同じに見えるか、計算式が並んで置かれている |
| 焦点 | 2つ以上の段か道か欄が目を引き合う |
| 配置 | どちらかの画面で、間隔、揃え、強弱、字の大きさが意図した物に見えない |
| スマートフォンでの見え方 | 今の操作が、スマートフォンで最初に見える範囲に無い |
| 負荷 | 余計な箱、飾りの札、重ねた説明が主な流れと張り合う |

落ちた関門には具体的に直し、もう一度見直します。
ERC-20の送金では、署名した取引が契約の外から始まり、`transfer(to, amount)`を呼び、契約の中で`balanceOf`を書き、書いた後に`Transfer`を出すかを別の関門で見ます。

## 動かす物と繋ぐ先

エージェントはプロジェクトの命令を動かします。`pnpm lint`、`pnpm typecheck`、`pnpm build`のような検査と組み立ての命令と、画面の写しを撮るPlaywrightです。
プラグインはどこにも繋ぎません。

## 書く物と残す物

エージェントが書くのは、プロジェクトの中の図のファイルだけです。
プラグインは自分の物を何も残さず、どこにも送りません。
