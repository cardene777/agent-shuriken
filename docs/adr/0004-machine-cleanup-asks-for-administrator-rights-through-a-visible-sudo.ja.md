# 0004. machine-cleanupは、agentが見える形で打つsudoで管理者の権限を求める

## 決めたこと

管理者の権限が要る行 (システムのキャッシュ、システムのログ、rootが入れたアプリ、システムのlaunch daemonとsystemdのunit) を片付ける時に、`machine-cleanup`が本人の承認をどう受けるか。
agentがパスワードを見ず、agentの命令の見張りからも求めが見える形にする。

## 選んだ案

agentが`sudo -A`で始まる命令を1つ打ち、sudoがpluginの持つaskpassの助け手を呼び、助け手がOSのパスワードの窓を開く。
パスワードは窓からsudoへ直に渡り、agentの出力には入らない。1回の承認で、本人が選んだ行を全部片付ける。
多くのクラウドの機械のようにsudoがパスワードを求めない所では、agentは代わりに`sudo -n`を打つ。
どちらも使えない所では、行はページに大きさを出したまま選べず、理由を示す。
定期実行はこの行を片付けない。調べる段はパスワードを求めず、読める分だけ測り、残りは`size unknown`と出す。

## 却下した案

| 案 | 採らなかった理由 |
|---|---|
| scriptが自分で窓を開く (macOSは管理者の権限付きの`osascript`、Linuxは`pkexec`) | 求めがscriptの中で起きるのでagentの命令の見張りから見えず、WSLと多くのサーバーには`pkexec`が無い |
| 本人が自分の端末で打つ1行を出す | 片付けを本人に返す |
| 測って見せるだけにするか、扱わない | 数GBが片付かないか、見えないまま残る |
| 定期実行で片付ける | rootで動く仕事が要り、管理者の権限が常に開いたままになる。窓に答える人もいない |

## 拠り所

- #141のstep 2は、その時に挙がった2つの入り方のどちらにも問題があったので、この行を外した。`machine-cleanup`は管理者のパスワードを求めず使わないと書いていた。
- agentの命令の見張りが読むのは命令の行の`sudo`で、askpassは端末以外のprogramからパスワードを受けるsudo自身の仕組みである。
- 承認はCodexを含むどのagentでも同じに動く必要があるので、1つのagentのhookや秘密の入力の仕組みに頼らない。
