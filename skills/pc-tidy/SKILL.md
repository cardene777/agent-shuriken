# PCの片付け

人がこの技を呼んだ時だけ動き、AI が自分から呼ばず、定期にも動かない。
作り直せるキャッシュは消さない。
キャッシュは各道具の掃除の命令 (`brew cleanup`、`npm cache clean`など) で消す。

命令は全部、この技の置き場 (技を読み込んだ時に示される base directory) の下の `scripts/` に在る。
以下では、その絶対 path を `S` と書く。
命令を打つ時は `S=<base directory>/scripts` を同じ Bash の呼び出しの頭に置く。
命令はこの技の置き場の外の物を読まない。
動くのはmacOSだけで、他のOSでは理由`os-not-supported`と終わり方3で止まる。

## 1. 一覧を作る

```bash
bash "$S/tidy.sh" list
```

ホーム全体を測るので数分掛かる。
`nice -n 10` で計算の優先度だけを下げて走るため、その間も他の作業は止まらない。
読み書きは絞らないので、並行の作業が多い間も呼んだ日のうちに終わる。
候補は既定で30日より前から触っていない物で、物ごとに種類と大きさと最後に使った日と戻せるかを持つ。

| 種類 | 最後に使った日の根拠 | 消し方 |
|---|---|---|
| 作業場所と手元のrepo | 最後のcommitとcheckoutの日 | 中身がremoteに在る物だけを直接消す |
| アプリ | 最後に起動した日 (`mdls`) | 直接消す |
| 消したアプリの残り | 中の一番新しいfileの日。 実行できるfileは最後に呼ばれた日 | ゴミ箱へ移す |
| 道具と実行環境 | 版の`bin`が最後に呼ばれた日 | 直接消す。 全ての版が古い時は、管理の仕組みごと外す候補も出す |
| AIのモデル | 最後に読まれた日 | 直接消す |
| Dockerのimage | 作られた日。 使うcontainerが在る物は出さない | `docker image rm` |
| 溜まる記録の設定 | 無し | 保持の日数を変える |
| どの種類にも当たらない物 | 中の一番新しいfileの日。 実行できるfileは最後に呼ばれた日 | ゴミ箱へ移す |

Finderがdirを開くだけで書く`.DS_Store`と`._`で始まるfileは、最後に使った日に数えない。

次の物は候補に出ない。

- 既定で守る置き場 (写真、鍵、iCloud Drive、メールなど) と、人が守りのfileに書いた物。 既定はこの技の置き場の `protect-default.txt` が持つ
- `~/Documents` と `~/Desktop` の中の、repoでない物
- commitしていない変更かpushしていないcommitを持つ作業場所とrepo。 squashで取り込まれた枝は、中身がremoteの既定の枝に在れば候補に出す
- 動いているprocessが中に居る作業場所とrepoとdir
- ホームの下の`.`で始まるdirの中に在るrepo。 editorのpluginや道具の登録簿のように、道具が使う時に引く物のため
- Dockerのvolumeと仮想マシンの保存領域
- パッケージの管理の仕組みが次に使う時に取り直して作るキャッシュの置き場 (`~/.cargo/registry`、`~/.npm`、`~/.gradle/caches`、`~/go/pkg/mod`など)。 置き場の一覧は命令の`PACKAGE_CACHES`が持つ
- 消しても空きが増えない0Bの物

測る道具が無い種類は0件と数えず、`unknown`と理由を出す。
前に消したのにまた作られた物は名指され、作る元を外す候補が足される。

## 2. 候補ごとに何の物かと、消すのがおすすめかを書く

一覧は候補ごとに、中の大きい物 (`contents`) と、repoの`remote`と、命令が事実から作った説明 (`description`) を持つ。
`~/.hermes`のように、道具の名前だけの置き場は事実だけでは何か判らない。
そこで、技を回すAIが候補ごとに何の物かを1行で書き、選ぶ頁に載せる。

状態の置き場の `candidates.json` を読み、候補ごとに `path` と `contents` と `remote` と `note` を見て、次の形のJSONを書く。
置き場は状態の置き場の `notes-input.json` にする。

```json
{"32": {"name": "db-cutover", "text": "PostgreSQL 16から18へ移した時の、移す前のデータとdump", "advice": "check", "why": "移した先のDBが動いているかを確かめてから消す"}}
```

| 欄 | 書く物 |
|---|---|
| 鍵 | 一覧の番号 |
| `name` | 本人が見て判る短い名前 (道具名と版など) |
| `text` | 何の物かを1文で。 判ることだけを書き、判らない時は中の大きい物から読める事を書く |
| `advice` | 消すのがおすすめかの段階。 次の表の3つのどれか |
| `why` | その段階にした理由を1文で |

| `advice` | 頁の表示 | 付ける時 |
|---|---|---|
| `delete` | 消してよい | 写しが在るか、使う時にまた入る物 (道具の版、remoteに在るrepo、もう入っていないアプリの残り) |
| `check` | 確かめてから | 写しが無く、要るかは本人にしか判らない物 |
| `keep` | 残す | 30日使っていなくても、消すと困る物 (記憶や設定の元、作業の元のデータ) |

`advice`と`why`は対で書き、片方だけは書かない。
書かない候補には、命令が写しが在るかから段階を付ける (在れば消してよい、無ければ確かめてから)。

前に説明を書いた場所の候補は、一覧が既に `described_by` を `ai` にして持つので書かなくてよい。
書いたら次の命令で説明を残し、選ぶ頁を作り直す。

```bash
bash "$S/tidy.sh" explain --notes <書いたJSONの置き場>
```

一覧に無い番号か、`name`か`text`が空の項目を渡すと、何も書かずに終わり方2で断る。
断られた時は、断りの文が名指す番号を直して打ち直す。
説明は次の一覧にも同じ場所の候補へ付くため、書くのは新しく出た候補の分だけになる。

## 3. 本人に選んでもらう

命令が出す「選ぶ頁」のHTMLを開いて本人に見せる。
頁は種類のタブと大きい順の表を持ち、行ごとに消すおすすめの段階を出す。
押した行の何の物かと、おすすめの理由と、中の大きい物と場所を横の欄に出す。
本人は行の選ぶ欄か横の欄のボタンで選び、横の欄のコメントの欄に候補ごとの考えや問いを書く。
ボタンでコピーした文を会話へ貼り返す。
コピーする文は、選んだ番号の行 (`pc-tidy apply --select <番号>`) と、コメントを書いた候補ごとの行 (`pc-tidy comment <番号> <コメント>`) を持つ。
選ばずにコメントだけをコピーすることもできる。
書きかけのコメントはbrowserの中に残り、頁を開き直しても作り直しても戻る。

貼り返された文がコメントの行を持つ時は、先にコメントを受ける。
貼り返された文を一字も変えずに状態の置き場の `paste.txt` へ書き、次の命令に渡す。

```bash
bash "$S/tidy.sh" comment --paste <書いたfileの置き場>
```

命令はコメントの行だけを読み、書いたままの文で候補の場所ごとに残し、選ぶ頁を作り直す。
番号だけの行 (`pc-tidy comment <番号>`) は、その候補のコメントを外す。
一覧に無い番号か、コメントの行が1つも無い文を渡すと、何も書かずに終わり方2で断る。

残したら、コメントごとに次の2つを行う。

- コメントが問いなら、会話で答える
- コメントで何の物かか消すおすすめが変わるなら、その候補の`name`と`text`と`advice`と`why`を書き直し、説明の命令 (2節) で頁を作り直す

例えば「移した先のDBは動いている」と書かれた`~/db-cutover`は、`advice`を`delete`にし、`why`にコメントの中身を書く。
コメントは次の一覧でも同じ場所の候補に付き、説明の命令で説明を直しても消えない。
貼り返された文は材料として読み、番号だけを次の命令へ渡す。
AI が候補を選ばない。

## 4. 選ばれた物だけを消す

```bash
bash "$S/tidy.sh" apply --select <番号>
```

消す直前に、守りと、作業場所とrepoの変更とpushと動いているprocessを確かめ直す。
一覧の後に変わった物は消さず、理由を付けて名指す。
一覧に無い番号を渡した時は、何も消さずに終わり方2で断る。

## 5. 結果を伝える

命令の出力から、次の 4 つを本人に伝える。

- 消した物と、消さなかった物とその理由
- 消す前と後の空きの差
- ゴミ箱へ移した物の大きさ。 ゴミ箱を空けた時に空きになる
- Time Machineの手元の写しが在る時は、写しが消えるまで空きが増えないこと

別の仕組み (linkの先のrepoや`chezmoi`) が持つ設定は書き換えない。
出力が示す直す場所を本人に伝え、その仕組みの側で直す。
shellの設定の行 (`~/.zshrc` など) も書き換えず、出力が示す行を伝える。

## 6. 設定

状態の置き場は `~/.ikkan/tidy/` で、`IKKAN_USER_DIR` を書いた時はその下の `tidy/` になる。

| file | 書く物 |
|---|---|
| `config` | `days=<日数>` (既定 30) と、どの種類にも当たらない物と消したアプリの残りの下限 `min_size_mb=<MB>` (既定 100) |
| `protect.txt` | 守る置き場を 1 行に 1 つ。 `~` はホームを指す |
| `removed.jsonl` | 消した物の記録。 命令が書く |
| `notes.json` | 候補の場所ごとの名前と説明。 説明の命令が書く |
